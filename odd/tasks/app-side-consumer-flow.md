# App-side enforcement of the consumer requests flow (#530)

Consumer apps must carry out the consumer requests flow (#522) on their own: the only way past a DS component's API is a guard allowlist entry, and an entry requires a DS issue. Issue #530 lists eight work units; this document tracks them. Branch per unit.

## Specs

- S1: Owner request, verbatim: "la idea es no tener que hacer revisión desde el design system si no que las apps sean capaces de realizar el flujo correctamente. como lo hacemos?"
- S2: Owner approval, verbatim: "si" (to opening #530 with the three layers as tasks) and "empezamos" (to starting with the first guard unit).
- S3 (T1, agent design choices, open to owner review): new doctor check **DS046** (error), "an app class on a DS component changes its appearance or layout".
  - **Where a class counts:** in non-test `.tsx` files under `sourceDirectory`, a JSX element whose tag is a component imported from `@egdev/ui` (named import, aliased import, or `Namespace.Component` from a namespace import). Collect only static class names from its `className`: string literals, the static parts of template literals, and string-literal arguments of any call expression (`cn(...)`, `clsx(...)`). Dynamic values are ignored.
  - **Which CSS counts:** `.css` files under `sourceDirectory`, outside `themeDirectory` (the theme folder stays the sanctioned override place, as for DS041). A rule matches when one of the collected classes appears in the selector's **last compound** (the element the rule styles). Classes in earlier compounds (structural selectors such as `.x > footer`) belong to T2, not here.
  - **Allowed properties (placement only):** custom properties (`--*`), `margin` and `margin-*`, `align-self`, `justify-self`, `place-self`, `flex`, `flex-grow`, `flex-shrink`, `flex-basis`, `order`, `grid-area`, `grid-column*` and `grid-row*`. Any other declaration in a matching rule is a DS046 finding. This is a list of what is permitted, not of what is forbidden.
  - **Finding:** one per rule, naming the selector, the component, the first offending properties and the fix: `DS046 error src/styles.css:38: .compact-note__title on ListItemTitle sets font-size, font-weight: use the component API or add an allowlist entry with an issue.`
  - **Allowlist:** reuse the existing entry shape: `file` is the CSS file and `pattern` is the rule's selector, as for DS041. Stale-entry, issue-format and DS043 pending rules apply unchanged.
  - Out of scope for T1: Tailwind utility classes in `className`, inline `style`, structural selectors (T2), DS internals in code (T3) and hand-written values (T4).
- S5 (T1, owner choice verbatim): "Permitirlos solo con valor 0 (Recomendado)" ("Son ajuste de ítem flex/grid (dejar encoger), no apariencia. Cualquier otro valor de min-width/min-height, y width/max-width, siguen siendo DS046. Recado y Nexo pierden 2 falsos positivos."). `min-width` and `min-height` are placement when their value is zero (`0`, or `0` with a unit such as `0px`); any other value stays a finding.
- S6 (T2, agent design choices, open to owner review): new doctor check **DS047** (error), "an app selector reaches into a DS component's internal structure".
  - **Trigger:** a CSS rule (same files as DS046: under `sourceDirectory`, outside `themeDirectory`, non-excluded) whose selector has a class collected exactly as DS046 collects it (a static class on a component imported from `@egdev/ui`) in a compound **before** a descendant (` `) or child (`>`) combinator, and whose **last compound targets DS-owned markup**: it holds no app-owned class (any class the app's TSX applies through `className`, on any element), for example a type selector (`footer`, `div`, `button`), an attribute selector (`[data-state]`, `[role]`), `*`, or only pseudo-classes.
  - **Not DS047:** a last compound with an app-owned class (the app styling its own content passed as children, e.g. `.note-detail .note-detail__actions`); sibling combinators (`+`, `~`) right after the DS-component compound, which target elements outside it; a last compound holding `.eg-*`, which DS041 already reports.
  - **Any declaration counts,** placement included: the problem is the dependency on markup the DS does not promise, not the property.
  - **Finding:** one per rule: `DS047 error src/styles.css:66: .note-detail > footer reaches into DialogContent internals: use the component API or add an allowlist entry with an issue.`
  - **Allowlist:** same shape as DS041 and DS046 (`file` = CSS file, `pattern` = selector); on a DS047 rule, only an entry for the full rule selector covers DS046/DS047 (and the rule's DS041 parts); DS041 part entries keep their previous matching and never cover DS046/DS047. (Corrected after verification: on DS041+DS046 comma rules each check still needs its own entry, as before T2.)
- S7 (T3, agent design choices, open to owner review): new doctor check **DS048** (error), "app code depends on DS markup".
  - **Where:** non-test `.ts` and `.tsx` files under `sourceDirectory`, honoring `exclude` (same test-file rule as the guard).
  - **Trigger:** a call whose callee is a property named `querySelector`, `querySelectorAll`, `closest` or `matches` (any receiver) with a static first argument (string literal, no-substitution template, or the static parts of a template literal) containing a DS class token `.eg-<name>`; and `getElementsByClassName(...)` or `classList.contains|add|remove|toggle(...)` with a static argument holding an `eg-<name>` class. Only `.eg-*` counts: it is the DS's public marker, while attribute selectors such as `[data-state]` are too ambiguous to attribute to the DS.
  - **Finding:** one per call: `DS048 error src/components/CompactNote.tsx:52: closest('[data-recado-appearance] > .eg-panel') depends on DS markup (.eg-panel): use a ref or an app-owned wrapper, or add an allowlist entry with an issue.`
  - **Allowlist:** `file` is the `.ts`/`.tsx` file and `pattern` is the static selector or class string exactly as written (whitespace-normalized). Stale-entry, DS042 and DS043 rules apply.
  - Dynamic arguments are ignored. Tests and stories follow the guard's existing test-file pattern.
- S8 (T5, owner choice verbatim): "T5 + release ahora (Recomendado)" ("Bloque de AGENTS.md en init y minor del CLI con DS046–DS048; Recado y Nexo empiezan a abrir sus consumer requests. T4 (valores a mano, warning) queda para después."). Agent design: `egdev-ds init` writes a marked agent block in `AGENTS.md` with exactly the same rules as the S12 `CONTRIBUTING.md` block of #522 (search from `<project>` up to the nearest `.git` ancestor; a marked file anywhere → no action; nearest unmarked file in an ancestor → no write, manual next step; linked or irregular project file → never written, never fails; otherwise create or append in `<project>`, byte-preserving with only the missing blank-line separation; idempotent; in the plan, `--dry-run`, `--json` and rollback; already-vendored backfill; `upgrade` never touches it). Markers `<!-- egdev-ds:agents -->` … `<!-- /egdev-ds:agents -->`. English content, concise, for coding agents: use `@egdev/ui` and `@egdev/tokens` and query the `egdev-design-system` MCP server before writing UI; do not go beyond a DS component's API (no appearance or layout CSS on classes passed to DS components, no selectors into their internals, no `.eg-*` lookups in code, no hand-written colors, spacing or fonts), naming the doctor codes DS041, DS046, DS047 and DS048; when the DS lacks something, stop that part and open a Consumer request describing the need, mitigating only by composing DS parts with `// TODO(egdev-design-system#N)` and an allowlist entry; never edit vendored tarballs, `egdev-ds.json` or `@egdev/*` lockfile entries; link to `docs/distribution/consumer-requests.md`.
- S9 (T9–T11, owner choices verbatim): "si" (to a new #530 unit fixing the two problems Nexo's first run exposed) and "Tag JSDoc con propiedades CSS (Recomendado)" ("En el types.ts del componente, junto a la prosa: `@classNameAllows width max-width grid-template-columns`. Nombres CSS literales, sin vocabulario nuevo; el generador valida que sean propiedades reales y lo publica en design-system.json. La prosa existente se mantiene."). Evidence: `packages/ui/src/molecules/select-tile/types.ts:122` sanctions root className for "margins, width, column count and parent layout", yet DS046 flags `width` and `grid-template-columns` (egdev6/egdev-design-system#536); className contracts exist only as prose in 54 `types.ts` files; Nexo's workers have no `egdev-design-system` MCP server, so the AGENTS block's "query the MCP server" rule blocked them.
  - **T9 contract:** a JSDoc tag `@classNameAllows <css-property> …` on the component's root props type (and on part props types where a part has its own className contract) lists the CSS properties, beyond the guard's base placement list, that the component's `className` may set. Literal, lowercase CSS property names only; the artifact generator fails on an unknown property. The artifact publishes it as `components[].classNameAllows: string[]` (sorted, deduplicated) for each component whose tag exists; absent means "base placement list only". Existing prose stays unchanged. Populate every component whose prose sanctions more than the base list, mapping: "width"/"width constraints" → `width`, `min-width`, `max-width` (and logical `inline-size`, `min-inline-size`, `max-inline-size`); "column count" → `grid-template-columns`; "stacking" → `z-index`; "positioning" → `position`, `inset`, `top`, `right`, `bottom`, `left`; "margins", "alignment", "placement" and "parent layout" are already in the base list. Ambiguous prose is reported for owner review, not guessed.
  - **T10 contract:** DS046 reads `classNameAllows` from the project's vendored `@egdev/system` artifact (`node_modules/@egdev/system/design-system.json`, resolved from `<project>` like the guard's `typescript` and `postcss`) and, for a class on component X, treats X's `classNameAllows` as additional placement. If the artifact is missing, unreadable or has no entry for X, the S3/S5 base list applies unchanged. DS047 and DS048 are unaffected.
  - **T11 contract:** the AGENTS block's MCP rule gains a fallback: use the `egdev-design-system` MCP server when available, otherwise the vendored `@egdev/mcp` over stdio (`node node_modules/@egdev/mcp/dist/index.js`) or the project's `design/system.md`. The block's DS046 line also changes (amendment after implementation): classes passed to DS components may set only placement plus the component's published `classNameAllows`, replacing S8's blanket "no appearance or layout CSS" line.
- S4: Same CLI rules as the rest of `egdev-ds`: Node stdlib plus the project's own `typescript` and `postcss` (as the guard already resolves them), never run git, stable exit codes and `--json`, no `\s*X\s*` regexes on untrusted strings. Doctor codes are never reused.
