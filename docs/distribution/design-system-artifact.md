# Design-system data artifact

`@egdev/system/design-system.json` is generated from repository sources and committed for offline consumers. Run `pnpm artifact --write` to regenerate it and `pnpm artifact --check` to detect drift. The `@egdev/system` build also generates it before packing. It has no timestamps or machine-specific paths.

The `schemaVersion` describes the shape; `packages` gives the actual versions of tokens, UI and effects. `catalog` joins the generated catalog with public value exports. `components` describes public exports, their source, own props and CVA recipes. `types` records naming-registry usages that are not public values. `tokens` copies source values and their CSS block group. `materialRecipes` records curated Material semantics and referenced tokens. `propNaming` comes from the naming registry.

The additive `typographyRoles` array records representative named Heading, Text eyebrow, SectionHeader and Hero ledes, and ProjectCard code recipes. Each role names its source file and resolved family, size, line-height, weight and tracking token; null denotes an unresolved mapping. Extraction reads the named CVA bases and static variant fields, not an inherited or computed CSS cascade. The list is not exhaustive and card headings can use sans. A universal document-body recipe is not established by these extracted sources; WebSection accepts consumer-supplied heading content, so it does not establish a heading font of its own. Source recipe changes produce artifact drift.

Each component has an additive `composedOf` array of `{ name, source }` entries, sorted by public name: public values referenced as JSX tags in its implementation file, resolved through TypeScript symbols. This does not discover components in helpers, dynamic references, or consumer-supplied slots; a shared implementation file can describe more than one export. Empty arrays do not prove absence of composition. Catalog composition descriptions and own props/parts remain separate source facts.

Each component has an additive `parts` array, sorted by name. A part is a public value from the same implementation file whose name begins with the parent's name followed by an uppercase letter. Each entry contains `name`, implementation `source`, source JSDoc `description`, and `children` documentation from its props type and children property. Empty descriptions mean the source does not provide that information; they do not imply unrestricted children. This naming convention cannot discover differently named or separately implemented parts and does not establish a formal nesting contract. Check the parent props and source for restrictions; changes to public source exports or descriptions cause artifact drift.

`@egdev/tokens` still does not itself publish structured JSON; this separate package resolves the deferred structured-token query without changing the token package or its CSS source. Values are not alias-resolved. The artifact is data only; the gentle-design renderer and MCP server consume it separately.

Each component also has additive `anatomy` and `surfaceUsage` arrays. Anatomy contains each statically discovered CVA recipe's `base`, variant axes and values, and compound conditions and classes. Class arrays contain integer indexes into the shared `anatomyUtilities` table: each entry has `className` (including state modifiers), recognized `tokens` and an `unresolved` flag. A mixed known/unknown reference retains the known tokens and is unresolved; unresolved does not mean zero or absence of styling. Numeric spacing without a named step refers to the base `--spacing` token and the multiplier remains in the class. `surfaceUsage` records source expressions that call `surfaceVariants`; consult Surface's anatomy for the referenced recipe. These are source-level observations, not a computed cascade, an exhaustive inventory of JSX/CSS, or a guarantee that every recipe in a shared types file applies to every exported value. Dynamic expressions, literal values, and unrecognized utilities are not guessed. Token values are in `tokens[]`.

`@egdev/tokens` still does not itself publish structured JSON; this separate package resolves the deferred structured-token query without changing the token package or its CSS source. Values are not alias-resolved. The artifact is data only; the gentle-design renderer belongs to #347 and the MCP server to #346.
