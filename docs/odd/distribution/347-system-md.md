## 2. Specification

The renderer is a **pure projection**: one function maps one artifact to one Markdown string. It reads no repository source, no CSS and no Markdown; every fact in the output is already in the artifact (#345 R2, `docs/odd/distribution/345-data-artifact.md:33`). `AC1`–`AC3` are the issue's acceptance criteria.

- **R1 — Pure renderer contract (AC1).** One exported function `renderSystemMd(artifact) → string` in the package chosen by P1. It takes the parsed artifact as its only argument and performs no I/O, network, clock, `process.cwd()`, locale, `TZ` or environment read. The whole document is produced by that function; no template file is read at run time.
- **R2 — CLI contract (AC1, AC2).** One executable with exactly two modes: `--write` writes the rendered bytes and `--check` compares them. Both accept `--file <path>`; without it the target is `<cwd>/design/system.md`. `--write` creates `design/` when missing and exits 0 printing one line with the target path and the version set. `--check` exits 0 when the bytes are equal and exits 1 with exactly one stderr line (`Stale: <path>; run --write.`) otherwise. Unknown arguments, a missing artifact, a target that is not a regular file, or a target whose real path escapes `<cwd>/design/` exit 1 with one stderr line and no write. Nothing else is written or read.
- **R3 — Sections and mapping (AC1).** The document has these `##` sections in this fixed order, each fed only by the named artifact key:

  | Section | Artifact input | Rule |
  | --- | --- | --- |
  | `Header` | `name`, `schemaVersion`, `packages[]` | Title, `Generated … Do not edit` HTML comment, version table, and the exact re-run command |
  | `Colours` | `tokens[]` where the name starts `--color-` | Table of name, verbatim value, `group`, source path |
  | `Typography` | `--font-`, `--text-`, `--leading-`, `--tracking-` tokens | One table, names grouped in that order |
  | `Spacing` | `--spacing-` tokens | Table |
  | `Radius` | `--radius-` tokens | Table |
  | `Shadows and effects` | `--shadow-`, `--gradient-`, `--blur-`, `--ease-`, `--duration-` tokens | Table |
  | `Material rules` | `materialRecipes[]` | One bullet per recipe: id, `semantics`, and its tokens with their verbatim values resolved from `tokens[]` |
  | `Components` | `catalog[]` + `components[]` | One block per catalog row with `available` true, joined to its `components[]` entry; unavailable rows listed once under a "not exported" note |
  | `Usage rules` | `propNaming[]` | One bullet per entry: semantic id, name, status, components (P4) |

  Any token whose name matches no section is listed once under `Other tokens`. A section with no input renders its heading plus one line saying it is empty; no section is omitted, so a missing artifact key is visible as an empty section rather than a silently shorter file.
- **R4 — Provenance, no invented content (AC1).** Every value, id, component name and prop name in the output appears verbatim in the artifact. Every table row and bullet names the artifact key it came from plus the repository path recorded there (`components[].source`, or the documented source of `tokens[]`/`materialRecipes[]`/`propNaming[]`), satisfying the skill's "each entry names its source `path`" (`skills/design/SKILL.md:75`). The renderer adds only section wording and the re-run command; it never adds usage prose, colour names, recommendations or examples. A test asserts every token/component/recipe value in the output exists in the artifact and that the output contains no `--` token absent from `tokens[]`.
- **R5 — Determinism (AC1).** `renderSystemMd` is a pure function of the artifact bytes: identical artifact bytes give byte-identical output, with `\n` endings, a trailing newline, no timestamps, no absolute paths, no hostname and no environment values. All ordering is total and locale-independent (plain `<` comparison, as in `scripts/prop-naming.mjs:9-15`). Verified by rendering twice, and by rendering the same artifact under a different `cwd`, `TZ` and `LANG`, asserting byte equality each time.
- **R6 — Target form (AC2).** The written file is a regular file inside `design/`: never a symlink and never a hard link outside it, because "present" is a realpath containment check (`lib/design-canvas-server.ts:444-454`). The CLI refuses a symlinked target (R2) instead of following it.
- **R7 — Freshness is a write, not a skip (AC2).** `--write` always writes, even when the bytes are unchanged, so the file's mtime advances; gentle-design decides currency by mtime only (`lib/design-sources.ts:112-119`), so skipping an identical write would leave a correct file reported as stale. The rendered header carries the exact re-run command, and a test asserts that a second `--write` over identical bytes advances `mtimeMs` while the bytes stay identical.
- **R8 — Distribution in the versioned package (AC1, AC2).** The renderer, its CLI and the committed golden ship inside the tarball of the package chosen by P1, and that tarball carries the artifact they describe. Because #342 `R1` currently packs "exactly the three packages" (`docs/odd/distribution/342-local-tarballs.md:34`), adding the carrier package is the same amendment #346 needs (its Q5), and this document does not widen it silently. No new dependency: §4 names the only case in which one would be required.
- **R9 — Drift test (AC3).** One committed golden `<carrier package>/system.md`, generated from the committed artifact (P2), plus root script `system:check` running `--check --file <carrier>/system.md`. The test suite asserts: the golden equals `renderSystemMd(artifact)`; removing one token, one component and one recipe from a temp copy of the artifact makes each corresponding test fail; changing one token value in the temp copy makes the golden comparison fail with exit 1 and one stderr line. The golden is never hand-edited and regeneration is one documented command.
- **R10 — MCP delivery of the same bytes (AC2, conditional).** If P5 adopts a tool in `@egdev/mcp`, it calls the same `renderSystemMd` function (imported from the carrier package, not reimplemented) and returns the identical string for the same artifact bytes, with a test asserting byte equality against the golden. `@egdev/mcp` stays a thin reader: #346 R13 already forbids it parsing tokens, catalog or Material (`docs/odd/distribution/346-egdev-mcp.md`, §2 R13). Adding a fifth tool amends #346 Q3 (`:56`), whose recommendation was exactly four.
- **R11 — Sample consumer and one observed sync (AC2).** One script creates a consumer under a fresh `mkdtemp` outside the worktree, installs the tarballs the way `scripts/package-consumption.test.mjs:9230-9241` does, adds at least one file that gentle-design detects as a design source (`lib/design-sources.ts:54-65`), runs `--write`, and asserts the file exists as a regular file inside `design/` and that its mtime is newer than that source. Then, once, an observed `gentle_design list` in the same consumer reports present and up to date, recorded verbatim in the task evidence. The temp directory is kept only long enough for that observation and removed in teardown, including on failure.
- **R12 — No scope creep (all).** The renderer does not modify the artifact, tokens, components, the catalog, `docs/MATERIAL.md`, the naming registry or any `package.json` version, and it creates no `design/` folder in this repository. Output is English (`AGENTS.md:45`); Spanish legacy documents are cited by path only, never translated.

## 5. Risks

- **Consumed contract (highest): the whole document is new external surface.** Its headings, table columns and bullet shapes are what an agent reads; nothing in gentle-design parses or validates them (`lib/design-canvas-server.ts:444-454` stats the file only). A wrong or reordered layout is invisible to `list`, so AC2 can pass with a poor document: the golden drift test (R9) and the R3/R4 tests are the only guard, and P4 is the decision that fixes the shape.
- **AC2's evidence is weaker than the words.** "Present and current" means a regular file inside `design/` whose mtime beats the consumer's own detected sources (`lib/design-sources.ts:112-119`); a one-line file with no tokens satisfies both. Version drift is not observable at all, because installed package files are skipped as sources (`:24,86`). Mitigation: the version table in the header and the golden drift test, not gentle-design's verdict.
- **Freshness semantics are fragile outside our control.** mtime survives neither `git clone` nor checkout order, so a consumer that commits `design/system.md` may see it as stale or current for reasons unrelated to its content; and an editor touching a token file re-stales a correct document. R7 plus P7's documented re-run is the whole mitigation.
- **Data / irreversible:** the rendered values are copied verbatim from the artifact; a mapping bug silently misdescribes colours or Material recipes to a designer. R5 determinism plus R4's "every value exists in the artifact" assertion are guards, not a review of ~292 values.
- **Dependency risk is upstream.** #345 (artifact, O1–O9), #342 (`release:pack`, D1–D7) and #346 (Q1–Q8) are all unapproved drafts. If O1 picks a non-package location, P1 and R8 change; if O6 changes token groups, R3's `group` column changes; if #345 drops `propNaming[]`, P4 loses a section.
- **Third-party drift.** gentle-design lives outside this repository and is not pinned; its detection rules, `list` wording and sync sections can change between releases. The observation in R11 is dated evidence, and the renderer's shape follows the skill as read at drafting time (`skills/design/SKILL.md:72-78`).
- **Concurrency:** two writers reach the carrier package — #345's generator owns the artifact, #347's `--write` owns the golden. The golden must always be regenerated from the committed artifact, never edited; `system:check` catches divergence but not two simultaneous writers.
- **Delivery / environment:** CI is disabled, so freshness depends on local runs of `system:check`; WU4 is unverifiable until #342 lands; WU5's install step needs a warm pnpm store or a first network-enabled run, as #343 documents.
- **Untestable here:** how a client renders the document, whether a designer-facing agent actually follows it, and the observed run itself — that is manual evidence, not a test.
- **Security:** the renderer reads one JSON file and writes one Markdown file into a caller-given directory. It performs no network access, spawns nothing and reads no user-home path; the test scratch lives in `mkdtemp` outside the worktree and is removed in teardown.
