## 1. Purpose and scope

- **Need / non-goals:** A small, independent `@egdev/effects` utility that gives a consumer element a scroll-triggered entrance: **reveal** (fade + rise) or **wipe** (left-to-right clip-path), with an optional per-element delay for stagger. It owns only its own element's entrance. Non-goals: page/zone choreography, band interpolation, layer gating or any director behavior (owned by the future HomeTemplate contract, per the approved web consumer amendment, `docs/CATALOGACION.md` "Web consumer amendment" rule 3–4); coordinating Isotipo3D or AmbientBackground; lazy-loading content; scroll-spy or navigation state; time-based loops; replaying entrances (v0.1 is strictly once-only; any replay proposal would be a separate, explicit owner decision — see OQ-4); replacing CSS `animation`-based effects; any Pulso copy or domain data.
- **Cataloging decision / alternatives:** **New** utility, destination `@egdev/effects`, decided by the owner (L5 approval above; open question 3 of `docs/components/web-catalog/v0.1/cataloging-draft.md:71`). Reuse: no public React export in `@egdev/ui` or `@egdev/effects` covers scroll-triggered visibility (`packages/effects/src/index.ts:1-4`; surveyed `packages/ui/src/index.ts`). Variant: no existing component has an entrance-on-scroll responsibility to extend. Compose: a per-element entrance is not achievable by composing existing components without duplicating the IntersectionObserver logic in every consumer. Extract: the logic lives only in the web app's page script, not inside any system component. It stays out of `@egdev/ui` because effects ownership of scroll-driven web motion was the approved route, and `@egdev/ui` never imports effects.
- **Evidence / level and package:** Responsibility is a single presentation concept (one element, local observer state), atom-equivalent within the effects package, following the established effects pattern (`packages/effects/src/ambient-background/`: `types.ts`, `useAmbientBackground.ts`, `AmbientBackground.tsx`, `index.ts`, tests, stories, one internal non-exported engine module). Source behavior evidence: `packages/effects/reference/pulso-director.js:519-537` (attribute collection, sibling stagger, pre-pass, observer, once-unobserve, wipe end listener, `.js` gate) and `pulso-source.html:467-475` (CSS states) and `:477-483` (reduced-motion override). Usage scale: `data-reveal`/`data-wipe` appear on 55 lines of `pulso-source.html` across 9 of 12 zones (`cataloging-draft.md:71`). **The component name `ScrollReveal` is a proposal only**, one of several viable names (alternatives: `RevealOnScroll`, `Entrance`).

## 2. Anatomy and composition

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| Root | Owns observation state, transition styling and the entrance of its subtree | Proposed default: plain `div` host carrying the stable public root `eg-scroll-reveal`; advanced opt-in: the consumer's single element via Slot composition | Any consumer content |

- **Stable public root (proposed):** the utility's own element carries `eg-scroll-reveal`, per the shared-contract rule that every component has a stable `eg-<name>` public root; composing through Slot does not waive the marker requirement. State markers (`data-state`, wipe terminal marker) live on that same element.
- **Default composition — wrapper element (owner-selected, L52):** the utility renders its own host element around the consumer content. This preserves the child's public markers and states untouched: the child keeps its own `data-state` (Radix primitives and delivered components already own it) and its own transform/transition utilities, which the wrapper does not clobber. A wrapper `div` is layout-neutral in flow contexts but is **not valid inside element-restricted contexts** (for example directly inside `ul`/`ol`/`tbody`), which is the concrete motivation for the advanced mode.
- **Advanced opt-in — Slot composition with an explicit conflict policy (owner-selected, L52):** merging behavior onto the consumer's single child element writes the utility's `data-state` and root marker **onto that child**, so it is offered only under all of these restrictions: the child is a single **native** element (no component); the child does not own a `data-state` or other state marker of its own; the child carries no transform or transition utilities that the entrance would clobber (the source composes post-reveal transforms on revealed elements, `pulso-source.html:473-474`, and utilities on the same element fight for the `transform`/`transition` properties). This fits plain native hosts such as a bare `li` or `figure`; it excludes Radix primitives and delivered system components. The source applies the effect to headings, list items and articles (`pulso-source.html:854-979`), so both modes remain expressible for those hosts.
- **Radix / composition:** No Radix behavior primitive is required: visibility-on-intersection is a platform capability (`IntersectionObserver`), and the shared-contract rule "use Radix for interaction" does not apply because there is no keyboard/focus/ARIA interaction to delegate. For Slot composition the proposal reuses the existing public `Slot`/`Slottable` export of `@egdev/ui` (`packages/ui/src/index.ts:168-169`), which `@egdev/effects` may import through its approved `@egdev/ui` workspace dependency (`packages/effects/package.json`; pinned by `packages/effects/src/package-contract.test.ts:22-29`). This adds **no new dependency**. Adding `@radix-ui/react-slot` directly to `@egdev/effects` instead is a rejected alternative: it duplicates an existing export and mutates the pinned dependency contract without need.
- **Public markers (proposed, unapproved):** `eg-scroll-reveal` root; variant marker `data-reveal` or `data-wipe` on the root (source-compatible naming, OQ-1); `data-state="hidden" | "revealed"`; terminal `data-done` for wipe, mirroring the source `.done` class (`pulso-source.html:472`).

## 3. Public API

- **Prop conventions (registry lookup):** Searched `skills/_shared/prop-naming.json` (154 entries) and `docs/prop-naming.md` by meaning and name. New semantic-ID proposals (unapproved; convention approval stays separate from spec approval; no `once` convention is proposed — OQ-4): `entrance-variant` / `variant`, `entrance-delay` / `delay`. Component usage `source` records (`path`, `symbol`, `revision` whole-file hash) belong to the plan phase once the API is approved, per the shared contract.

| Prop / event | Type | Required | Default or rule | Description |
| --- | --- | --- | --- | --- |
| `variant` | `'reveal' \| 'wipe'` | no | `'reveal'` (proposed) | Entrance style: `reveal` fades in and rises; `wipe` uncovers left→right via clip-path. |
| `asChild` | `boolean` | no | `false` (proposed) | Advanced opt-in: merge behavior and state markers onto the consumer's single child element instead of rendering the wrapper root. | `delay` | `number` (ms) | no | none | Static transition delay for stagger, applied as a numeric millisecond custom property. Proposed validation rule (not yet approved): the value must be a finite number ≥ 0; non-finite or negative values are ignored and the element runs with no delay. See OQ-3 for the rejected auto-sibling stagger alternative. |

- **Native props / refs:** Wrapper mode renders a plain `div` inheriting native attributes (`...rest` to the root). In `asChild` mode props and the forwarded ref land on the child (same rule as the existing Slot primitive). Consumers keep full control of semantics; the utility adds no role, no `tabIndex`, no ARIA attribute.
- **Controlled / uncontrolled:** Not applicable. Observation state is internal; no controlled visibility prop is proposed. No `once` prop exists in v0.1: once-only observation is an invariant, not a configuration (OQ-4). An optional `onReveal` notification was considered and is **not proposed** in v0.1 to keep the API minimal; it can be added later without breaking change.
- **Compatibility:** New public export of `@egdev/effects` (`export { ScrollReveal }` + types from `src/index.ts`); no existing export, marker or consumer changes. The package stylesheet output (`./styles.css`) is unchanged under the recommended "No stylesheet" resolution (OQ-6). React `>=18` peer unchanged; no `three` involvement.

## 4. Behavior

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| SSR / hydration / JavaScript disabled | Content fully visible; the hidden state is applied only on the client, and only when `IntersectionObserver` exists and reduced motion is not requested (source gates the whole system behind a JS-only class, `pulso-director.js:520,536`, and the CSS hides only under that class, `pulso-source.html:468,470`) | none |
| Client mount, observer supported, motion allowed | Element observed; if its top is already above ~92% of the viewport height it is revealed immediately without transition (source pre-pass, `pulso-director.js:527,531-533`) | none |
| Element intersects the observation root (bottom rootMargin −8%, threshold 0; `pulso-director.js:530`) | Transitions to the revealed state using the variant's transition; the element is then unobserved and never re-hides (once-only invariant, source `pulso-director.js:528-529`) | none (no event proposed) |
| Focus moves into the element's subtree while hidden | The element reveals immediately, like the pre-pass, so focus is never received by invisible content | none |
| Wipe transition ends (`transitionend`, property `clip-path`) or is cancelled | Terminal `done` state removes the clip-path entirely; a bounded cleanup (`transitioncancel` handling or an equivalent bounded fallback proposed in OQ-7) guarantees the element never remains clipped indefinitely — a stronger promise than the source's single `transitionend` listener (`pulso-source.html:472`; `pulso-director.js:535`) | none |
| `IntersectionObserver` unavailable, or observer creation/observation fails | Fail-open: the element stays or becomes visible; entrance is skipped, never stuck hidden | none |
| `prefers-reduced-motion` toggles to reduce while hidden | The element is revealed immediately with no transition; reduced motion never leaves content hidden (source CSS override `pulso-source.html:477-483`; the source does not re-evaluate after load, which this draft proposes to improve) | none |
| Utility unmounts | Its observer is disconnected; no global listeners remain | none |

- **States / representation:** Two observable states (`hidden`, `revealed`) plus the wipe terminal state, carried as data attributes on the root (proposed), never as mirrored classes owned by the utility; Tailwind data variants style them per the shared contract. The utility **does not own scroll**: it registers an `IntersectionObserver` per element (proposed; a shared module-level observer is the non-recommended alternative, OQ-5), listens to no scroll events, reads no zone table, exposes no `window.PULSO`-like global, and composes independently with the future HomeTemplate, which owns choreography.
- **Limits / consumer responsibilities:** Elements with their own `transform`-based states (hover lifts, rotations — the source composes `.proj.in:hover` and `.ph-setup` rules, `pulso-source.html:473-474`) must keep those on elements the utility does not merge onto, or use wrapper mode; in wrapper mode the child's transforms are untouched. The utility promises only that its own root ends with `transform: none` and, for wipe, no clip-path. Stagger delays are the consumer's responsibility unless OQ-3 adopts auto-sibling computation. The `delay` validation rule above is a proposal pending approval.

## 5. Accessibility

- **Accessible name / roles / relationships:** Not applicable — the utility is a passive presentation enhancer. It adds no role, name or relationship and never hides content from the accessibility tree: hidden and revealed states use opacity/transform/clip-path only, never `display: none`, `visibility: hidden` or `aria-hidden`.
- **Keyboard / focus:** No interaction of its own, but one binding promise: a hidden element must not hold invisible focus. When focus enters the subtree of a hidden element (tab, in-page anchor, programmatic focus), the element reveals immediately; see the behavior table. Opacity/transform/clip-path leave the element focusable, which the source ignores — this draft closes that gap as a requirement, pending approval with the rest of the payload.
- **Fail-open:** Observer absence or failure and a reduced-motion toggle never leave content hidden (behavior table); this is an accessibility backstop, not only a nicety.
- **Announcements / other conditions:** No announcements: the entrance is decorative and its content is already available. Reduced-motion handling aligns with WCAG 2.3.3. Because the utility cannot know whether surrounding content flashes or moves, page-level motion comfort stays a consumer/HomeTemplate responsibility.

## 6. Appearance

| Variant axis | Allowed values | Default or rule | Combinations / restrictions |
| --- | --- | --- | --- |
| Entrance variant | `'reveal'` \| `'wipe'` | `'reveal'` (proposed) | Mutually exclusive per element, as in the source where an element carries one attribute |
| Stagger delay | Finite ≥ 0 ms, consumer-supplied | none | Independent of variant; composes with both |

- **Tokens / Material (proposed, unapproved):** No colors, shadows or backgrounds are introduced — the utility is geometrically and chromatically transparent. Proposed transition sources: `reveal` → opacity + rise with `var(--duration-reveal)` (560 ms, existing token `packages/tokens/src/theme.css:464-466`, matching the source's `.56s`) and `var(--ease-out)` (`:383-384`, matching the source `var(--ease)`). **Rise distance — source vs proposal, stated explicitly:** the source rises exactly 24px (`pulso-source.html:468`). The owner selected the existing token utility `translate-y-7` = **22.4px** (L52, verbatim: "22.4px existing token (recommended)"), an accepted **1.6px deviation** from the source's 24px; no token utility equals 24px on the 3.2px-based spacing scale (`theme.css:7,414-431`), and no hardcoded 24px is used. This is a design decision within this Proposed draft, not a token change: **no token is edited or added by this spec.** `wipe` → `clip-path: inset(-10% 100% -10% 0)` → `inset(-10% -2% -10% 0)`; the owner selected a **new 800 ms duration token** for it (L52, verbatim: "800ms token + delay exception (recommended)"), proposed as `--duration-wipe: 800ms` — no 800 ms duration token exists today (`theme.css:461-472` is the complete duration set), and the token value is proposed, not written: materializing it in `packages/tokens/src/theme.css` requires the separately approved implementation plan. The wipe bleed values (−10%/−2%) are read from the source and remain part of this draft's proposal, not adopted values.
- **Dynamic geometry:** The `delay` mechanism is an inline numeric millisecond custom property (e.g. `--eg-scroll-reveal-delay`), analogous to the explicitly approved Gauge (`--eg-gauge-size`) and PreviewFrame (`--eg-zone-*`) limited exceptions. The owner selected this scoped exception (L52, "800ms token + delay exception (recommended)"); that precedent does **not** extend to any other inline mechanism. No interpolated class strings and no inline appearance are proposed. Materialization and the exact utility list belong to the separately approved plan.
- **Class composition / consumer layout:** States are attribute-conditioned and are styled with static CVA utilities plus Tailwind data/aria variants (for example `data-[state=hidden]:opacity-0`), exactly as the shared contract requires for Radix/ARIA/`data-state` attributes; transitions compose from static transition/duration/easing utilities referencing the tokens above, with the delay through the owner-selected custom property. Utility emission for the exact variants used (including the arbitrary `delay-[var(--eg-scroll-reveal-delay)]` form) must be proven against the installed compiler at plan time, as in prior layers. In wrapper mode the child's `className` is untouched; in the restricted `asChild` mode the Slot primitive merges classes and consumer classes keep layout precedence. `twMerge` resolves recognized utility conflicts only; no blanket override permission is granted or implied.
- **Files / pending proposals:** If approved for implementation, the six mandatory files in the effects pattern (`types.ts`, `useScrollReveal.ts`, `ScrollReveal.tsx`, `ScrollReveal.test.tsx`, `ScrollReveal.stories.tsx`, `index.ts`) plus no additional internal modules (the IntersectionObserver logic is hook-local; no engine port is needed). **Recommended resolution: "No stylesheet"** — the states, transitions and variant geometry are expressible as static CVA utilities composed through the hook with `cn()`, styled through data variants per the shared contract; the optional `scroll-reveal.css` is created only if the approved plan documents a concrete role utilities cannot express (OQ-6). No token, dependency or catalog changes are authorized by this spec.
