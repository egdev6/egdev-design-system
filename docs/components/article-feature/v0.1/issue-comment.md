## Proposed API summary (details in the snapshot)

- Root `ArticleFeature` (the card **is** the anchor: `a` from `href`, or the consumer's anchor through `asChild`): `title` (required), `level` (2–6, default 3), `href` (required unless `asChild`), `asChild`, `eyebrow?` (category), `detail?` (reading time/date), `actionLabel?` (paint-only action text), `children` = at most one `ArticleFeatureCover`.

- `No stylesheet`: every role is expressible with token-backed utilities over the public recipes. ## 1. Purpose and scope

- **Need:** one reusable featured-article card in `@egdev/ui` so a new web view can present the single highlighted article of a section as one whole-card link. The card carries a 16:8 cover (a generative plate with an oversized decorative word, or a supplied photograph), an optional featured badge, an optional context row (category plus reading time and date), a generated heading and an optional visible action label. No category, duration, date, title, badge word, action label, image or destination is built in: everything arrives through props.
- **Non-goals:** not the blog section (`BlogGrid` is an approved organism that composes this card with the `ListItem` editorial row variant); not the compact article row (`ListItem variant="editorial"`) and not the current-status card (`NowCard`); not a grid, list or carousel; not a second action (the whole card is the single link, so it hosts no nested link or button); no reading-time computation, date formatting, routing, analytics or data fetching; no hover lift, no neon halo, no isotype artwork and no article body copy.
- **Cataloging decision / alternatives:** **new** molecule, per [cataloging-draft.md §4](../../web-catalog/v0.1/cataloging-draft.md) and the `ArticleFeature` row in `docs/CATALOGO.md` (action `mover`, source `ArticleFeature (molécula)`, composes `PhotoFrame, Text`). Rejected alternatives: *reuse* (`ListItem card` is a generic content container with meta and media parts but no 16:8 cover and no generated heading plus visible action label, and its whole-card anchor model belongs to the editorial row variants rather than to a featured cover card; `ProjectCard` is a passive project card whose single action lives in a footer link, so making it navigate would change its approved promise; `ModuleCard` is a module summary with a status badge); *variant* (adding a whole-card anchor, a cover region and an action label to `ListItem` or `ProjectCard` would change their published responsibilities and unions); *compose* (a `PhotoFrame` + text + link composition would re-implement the same cover region, context row and single-link behaviour in every new view, which is exactly what the approved web-consumer amendment removes); *extract* (nothing inside an existing component hides a featured article card).
- **Evidence / level and package:** molecule in `@egdev/ui`, proposed `packages/ui/src/molecules/article-feature/`. The level follows the responsibility: coordinated concepts (cover, context row, heading, one whole-card action) that only work as one unit, with no section or navigation responsibility. Verified public React API inspected in this working tree: `packages/ui/src/index.ts` (whole file, `sha256:f85891be7d1d2ffc6d6788c9a06d87c70466213a227dec2abbd2235d2be6bd24`), `packages/ui/src/primitives/surface/types.ts` (`Surface`, `surfaceVariants`, `sha256:26d0726b5034dceb74e0067c1c0df5108d351e948205bbf22b5e187b92d9c0b6`), `packages/ui/src/atoms/photo-frame/types.ts` (`ratio` numerics incl. `auto` host-height fill, `focalPoint`, required `src`/`alt`, `sha256:aca1d91add7e92b3629233d6bc521b2d07d1e7bf14d86795c3ba23fe6213092e`), `packages/ui/src/primitives/aspect-ratio/types.ts` (`sha256:771b93daa9a3c3548cba5ea6172b0182b32705e6ab7caeaf1b207641669ff1ed`), `packages/ui/src/atoms/badge/types.ts` (`sha256:81d97cd46835e08a2ed5d846d352642ef9230661b4dcfe04d7e4be921c7d6f3e`), `packages/ui/src/atoms/icon/types.ts` (`arrow-right` exists in the closed glyph set, `sha256:673126c6aea8fc04533a323869695bf96abc5ccc732433c446c834d5be577292`), `packages/ui/src/atoms/link/types.ts` (`variant: 'underlined'` paint reference, `sha256:b5e5ba0b47c7e53c9a3759888c1d746a82596537fd3834d1ca3dd2a4b05503f3`), `packages/ui/src/atoms/logo/types.ts` (the only logo instance is a named image that omits `aria-hidden`, `sha256:c94a94db17133bd7b28dcd8763fdf00f40fb788379f2074432599c68c5a1ba31`), `packages/ui/src/molecules/list-item/types.ts` (whole-card anchor model and interactive hover recipe, `sha256:df2e05c470c79ad94bef1b06c87d118216ea601ebebe1d8aea6cff8c366cbe76`) and `packages/ui/src/primitives/text/types.ts` (`sha256:badce40976a01fb4c0079a1481c5ba2fcdf88c10dd2bee6556244991fdfd21c9`).

## 2. Anatomy and composition

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| `ArticleFeature` root | The card's single link plus its Material frame and the generated heading/action label | `a` (or the consumer's anchor through `asChild`) | At most one `ArticleFeatureCover`, then the generated context row, heading and action label |
| `ArticleFeatureCover` | The cover region, its reserved 16:8 proportion and the overlay badge | `div` > `AspectRatio` (`ratio={2}`) | Either the generative plate (`coverWord`) or exactly one `PhotoFrame` with `ratio="auto"` filling the reservation; no other media composition |
| Generative plate (internal) | Recessed plate holding the oversized decorative word | `AspectRatio` (`ratio={2}`) > internal `span`, `aria-hidden="true"` | `coverWord` only; no controls, no links |
| Badge (`badge` prop on the cover) | Featured flag over the cover | Existing `Badge` (`tone="brand"`, `variant="solid"`) | One short text run; omitted when not supplied |
| Context row (root `eyebrow` + `detail`) | Category and the reading/date detail | Internal `p` with `aria-hidden` separators | Plain text only; the row renders only when at least one value is supplied |
| Heading (root `title` + `level`) | Article title and the card's accessible name | `h2`–`h6` selected by `level` | One plain text run; blank titles warn in development and render nothing |
| Action label (root `actionLabel`) | Visible affordance of the card's single action | Internal `span` plus a decorative `Icon` (`arrow-right`) | Text only; **never** an anchor or button |

- **Radix / composition:** no Radix primitive is needed for behaviour. The card's single interaction is native anchor navigation, so no primitive is delegated to and none is invented; `asChild` uses the same Radix `Slot` composition the public `Link`/`Button` already use, which is what lets a router link keep its own semantics. The cover reuses the public `PhotoFrame` atom and the public `AspectRatio` primitive; the badge reuses the public `Badge`; the arrow reuses the public `Icon`. No new dependency.
- **Anchor model:** the card element **is** the anchor — `<a>` from `href`, or the consumer's own anchor element through `asChild` — exactly the `ListItem v0.2` anchor model. No anchor is nested inside the card and no interactive control exists inside it, so there is never a second tab stop or overlapping activation. The visible action label is paint and text only.
- **Public markers:** `eg-article-feature` is the stable public root; the cover keeps `eg-article-feature__cover`, the context row `eg-article-feature__meta`, the action label `eg-article-feature__action`. The word, badge and separator elements are internal and are not a public override surface. No existing ClassBEM/legacy consumer is migrated: the web keeps `.eg-article-feature`/`.feature` until an explicitly approved parity migration.
- **Reading order:** DOM order equals visual order — cover, context row, heading, action label. Nothing is visually reordered against the DOM, and the whole reading order is inside one anchor.

## 3. Public API

| Prop / event | Type | Required | Default or rule | Description |
| --- | --- | --- | --- | --- |
| `title` | `string` | yes | — | Visible article title and the card link's name. Blank or whitespace-only warns in development and renders nothing (never an unnamed link). |
| `level` | `2 \| 3 \| 4 \| 5 \| 6` | no | `3` | Native heading rank only; the title typography never follows the rank. |
| `href` | `string` | yes unless `asChild` | — | Native destination rendered as one `a` around the whole card. |
| `asChild` | `boolean` | no | `false` | Merge the card's frame, recipe and props onto one consumer anchor (router link, analytics link) through Radix Slot. The child owns `href` and must keep anchor semantics. |
| `eyebrow` | `string` | no | none (omitted) | Category line of the context row, rendered in the brand raised ink. Whitespace-only renders nothing. |
| `detail` | `string` | no | none (omitted) | Reading time, date or other short fact of the context row, rendered in the secondary ink. Formatting is the consumer's. |
| `actionLabel` | `string` | no | none (omitted) | Visible text of the card's action affordance. Paint and text only: it never becomes a nested link. Whitespace-only renders nothing. |
| `children` | `ReactNode` | no | none (omitted) | At most one `ArticleFeatureCover`; the card renders it first, before the context row. |
| `className` | `string` | no | — | Outer layout only (grid placement, width, margin), merged last through `cn()`. |
| `ArticleFeatureCover.coverWord` | `string` | no | none (omitted) | Oversized decorative word of the generative plate (for example `/src`). Decorative and `aria-hidden`; ignored when a media child is supplied. |
| `ArticleFeatureCover.badge` | `string` | no | none (omitted) | Featured flag rendered as a solid brand `Badge` over the cover. Whitespace-only renders no badge. |
| `ArticleFeatureCover.children` | `ReactNode` | no | none | Exactly one `PhotoFrame` composed with `ratio="auto"`: the cover region reserves the 16:8 proportion and the auto media fills the reserved height (the v0.4 auto-height behaviour). A child with its own ratio breaks the reservation; that composition error is documented, not detected. |
| `ArticleFeatureCover.className` | `string` | no | — | Local layout only; no appearance overrides. |

- **Prop conventions:** [canonical registry](../../../../skills/_shared/prop-naming.json) and [generated view](../../../prop-naming.md), looked up by meaning, name and alias before drafting. Applied approved entries: `title` → `heading-title`; `level` → `heading-level`; `eyebrow` → `heading-eyebrow`; `asChild` → `slot-composition`. `href` is a native anchor attribute with no own convention. The composed `PhotoFrame` keeps the approved `aspect-ratio` and `image-focal-point` entries on its own API; this card does not re-declare them.
- **Retracted reuse:** an earlier draft of this spec applied the approved `thumbnail-badge` entry to `ArticleFeatureCover.badge`. Re-checked against the registry, that entry is scoped to selectable visual options (“included in the option's accessible description”, sole usage `SelectTileOption`); a featured-article cover is not an option and the badge joins the card's content rather than an accessible description, so the reuse is retracted.
- **Proposed new conventions (pending owner approval, not registered):** (1) semantic ID `card-link-action-label`, name `actionLabel`, meaning “visible text of a whole-card link's action affordance, rendered as paint and text only because the card element is the single link”; component-specific type `string`. (2) semantic ID `content-detail`, name `detail`, meaning “short visible factual detail shown beside a content unit's context label, such as reading time or publication date; never an accessible description and never a control prop”; component-specific type `string`. `detail` is proposed rather than reusing the approved `meta`/`option-metadata` entry, whose meaning (“below its label, available as its accessible description”) belongs to a selectable option and would be widened by this usage. (3) semantic ID `decorative-cover-word`, name `coverWord`, meaning “oversized decorative word rendered as visual identity inside a media cover region and hidden from assistive technology”; component-specific type `string`. (4) semantic ID `cover-badge`, name `badge`, meaning “short non-interactive category or flag annotation rendered as a `Badge` over or beside a media cover or poster, outside selectable-option semantics”; component-specific type `string`. The registry is not edited by this task: `skills/_shared/prop-naming.json` and `docs/prop-naming.md` are outside its edit surface, and a usage needs a `source` revision for a `types.ts` that does not exist yet. No exception is requested and no convention status changes.
- **Native props / refs:** the root forwards native anchor attributes (`data-*`, `aria-*`, `target`/`rel`) for both branches and is merged last through `cn()` for outer layout only. `href` is supplied by the chosen branch (the root `href` on the native branch, the child's own `href` on the `asChild` branch), while `role`, `tabIndex` and `style` stay protected. The accessible name comes from the anchor's content by default; a consumer may override it with native `aria-label`/`aria-labelledby`, and that override then replaces the content name. No ref API is promised in v0.1.
- **Controlled / uncontrolled:** Not applicable. The card holds no state, no timers and no controls.
- **Compatibility:** new export surface (`ArticleFeature`, `ArticleFeatureCover`, `ArticleFeatureProps`, `ArticleFeatureCoverProps`) added to `packages/ui/src/index.ts` under Molecules. Nothing existing changes; no token, dependency or legacy-class migration is proposed. React 18/19 consumption is a plan gate, not a claim of this draft. The catalog row's `composes` column (`PhotoFrame, Text`) drifts from the actual reuse (`PhotoFrame`, `Badge`, `Icon`, `surfaceVariants`, `AspectRatio`); that is an implementation-detail follow-up for the catalog generator in a separately approved future plan, not an approval blocker for this spec.

## 4. Behavior

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| Rendered with `title` and `href` only | One anchor containing the heading and the frame; no empty cover, context row or action label zones | none |
| `asChild` with a router anchor | The same frame, props and recipe on the consumer's anchor; no extra wrapper element and no nested anchor | none |
| `eyebrow` and/or `detail` supplied | One context row: category in brand raised ink, an `aria-hidden` separator, then the detail in secondary ink; a single supplied value renders without a dangling separator | none |
| `badge` supplied on the cover | Solid brand badge over the top-left cover corner | none |
| Generative cover (`coverWord`, no media child) | Recessed 2:1 plate with the oversized decorative word; the word is absent from the accessible name | none |
| Media cover (`PhotoFrame` with `ratio="auto"`) | The supplied photograph fills the 2:1 reserved cover region; `coverWord` is ignored and a development warning explains the precedence | none |
| Media cover with a child that sets its own `ratio` | Documented consumer composition error: the child reserves its own proportion inside the region; the card warns in development that the cover contract requires `ratio="auto"` | none |
| `actionLabel` supplied | Visible label plus the decorative right arrow inside the card's single link; activating it navigates like any other point of the card | native anchor navigation |
| `title` blank or whitespace-only | Development warning; the card renders nothing at all | none |
| Pointer over the card | Brand hairline and the raised tone step change, with no lift, scale or glow (see OQ-4); the cursor is a pointer because the card is a link | none |
| Keyboard focus on the card | One tab stop with the token focus ring (`--shadow-focus`); Enter navigates | native anchor activation |
| `prefers-reduced-motion: reduce` | Colour and border transitions are removed; nothing moves in any case | none |

- **States / representation:** no own `data-state` and no mirrored state class. The native `:focus-visible` and `:hover` pseudo-classes drive the frame recipe; the cover exposes `data-cover` (`generative` | `media`) so parts can read the branch, and the root exposes `data-level` for debugging only.
- **Limits / consumer responsibilities:** the consumer supplies every string, the destination (or the anchor itself), the cover photograph and its alternative, and the formatted date/reading time; on the media branch it must compose `PhotoFrame ratio="auto"` so the cover region keeps its reserved 16:8 proportion. It decides grid or list placement, must keep exactly one cover and no nested interactive content, and owns the `<ul>`/`<li>` or grid semantics around the card. The card never fetches, formats dates, measures reading time, routes, animates or clones children.

## 5. Accessibility

- **Accessible name / roles / relationships:** the card is one native anchor, so its name is computed from its content: context row, heading and action label, in DOM order. Consequences documented for consumers: a cover whose meaning already lives in the title should use `alt=""` (an informative `alt` inflates the card name), and a long `detail` string is part of that name too. A consumer that wants a shorter name must supply `aria-label`/`aria-labelledby`, which then replaces the content name. The decorative word, the separator dots and the arrow glyph are `aria-hidden`. The badge is plain text, never colour-only, and the heading keeps the surrounding outline valid through `level`.
- **Keyboard / focus:** exactly one tab stop for the whole card; native anchor activation (Enter) and native context-menu/copy affordances are inherited, and no key handler is added. There is no inner focusable element, so no focus trap, no roving tabindex and no double activation. Focus is styled with the token focus ring on the frame, not only on an inner element.
- **Announcements / other conditions:** no live region and no synthesized announcement. The visible action label is part of the link name by construction; that redundancy is documented rather than hidden, because hiding it would remove visible text from the name while the card's activation target stays the full card. Touch: the whole card is the target, comfortably above the 44 px minimum; the badge and the arrow are decorative and never targets.
- **Consumer obligations:** one card per featured slot (Material rule 7 keeps a single signature element per view); the `<h*>` rank must fit the surrounding outline; no nested controls may be passed into `children`.

## 6. Appearance

| Variant axis | Allowed values | Default or rule | Combinations / restrictions |
| --- | --- | --- | --- |
| `level` | `2`–`6` | `3` | Rank never changes the title typography |
| cover branch | generative (`coverWord`) / media (`PhotoFrame ratio="auto"`) | none (both optional) | Presentation only, never two covers; media wins when both are supplied |
| `badge` | supplied / absent | absent | The badge is the cover's only ink accent |
| presentation | one presentation | — | No `variant`, `size` or `orientation` axis in v0.1; card width is consumer layout |

- **Tokens / Material:** the root composes the public `surfaceVariants({ tone: 'surface-1', elevation: 1, padding: 'md', radius: 'xl' })` recipe — the same raised Grafito frame as `ProjectCard`/`ModuleCard` — plus own layout classes (`flex flex-col gap-4 no-underline text-fg-default`) and the interactive card hover recipe already approved for `ListItem v0.2` anchors: `hover:border-border-brand` with `hover:[background:var(--gradient-sheen),var(--color-surface-2)]`, focus-visible `shadow-focus`, `transition-[color,background-color,border-color] duration-(--duration-fast) ease-(--ease-out)` from existing tokens, and `motion-reduce:transition-none`. There is **no** brand glow, no lift and no glow shadow (OQ-4). The cover region reserves its 16:8 proportion through the public `AspectRatio` primitive (`ratio={2}`) owned by the cover part: the generative plate is `surfaceVariants({ tone: 'well', padding: 'none', radius: 'none' })` with the word in `text-title-display` uppercase at `text-alpha-white-07`; the media branch is the supplied `PhotoFrame ratio="auto"` filling the reserved height (its approved auto-height behaviour). The badge sits over the cover corner with token spacing (`top-4 left-4`). The context row uses `font-display text-meta uppercase` with `text-fg-brand-raised` for the category and `text-fg-secondary` for the detail; the heading uses `text-heading-small text-fg-default`; the action label uses `text-label-default text-fg-brand-raised` with `border-b border-border-brand` (the paint-only echo of `Link variant="underlined"`) plus `Icon name="arrow-right" size="sm"`, pinned with `mt-auto` so cards of unequal content keep their labels aligned. The web's glass paint, its radial brand halo and its deep cover shadow are replaced by the solid tonal frame, a recessed generative plate and no halo — allowed differences, not new recipes.
- **Dynamic geometry:** Not applicable. The cover region reserves its proportion through the public `AspectRatio` primitive (`ratio={2}`) and the media cover through `PhotoFrame`. No custom property, no interpolated class string and no inline geometry is introduced.
- **Motion:** only the frame's colour/border transition on hover and focus, removed under `prefers-reduced-motion`. The web's isotype rise on hover and its card glow are not ported (OQ-1, OQ-4).
- **Class composition / consumer layout:** the root merges `className` last through `cn()` for outer placement, width and margin; the cover part merges its own `className` last for local layout. `twMerge` resolves recognised utility conflicts only: there is no universal last-class-wins promise, no appearance-override permission and no per-instance recipe. `surfaceVariants` remains the frame appearance API, `PhotoFrame` the cover appearance API.
- **Files / pending proposals:** the six mandatory files are planned at `packages/ui/src/molecules/article-feature/` — `types.ts` (CVA recipes, `ArticleFeatureProps`, `ArticleFeatureCoverProps`, English JSDoc with `@control` on every own declaration and on both union branches), `useArticleFeature.ts` (title/eyebrow/detail/action-label normalization, protected props, cover precedence, derived heading id, per-part `cn()`), `ArticleFeature.tsx` (JSX only), `ArticleFeature.test.tsx`, `ArticleFeature.stories.tsx` (`Molecules/ArticleFeature`, English) and `index.ts`. **No stylesheet** and no extra internal module. No token or dependency change is proposed. Pending token/recipe proposals reported, not added: a mid-size sans card-title recipe (v0.1 uses `--text-heading-small`; OQ-3), a public paint-only link-label recipe (v0.1 keeps a local token utility; OQ-2), a brand halo recipe for generative covers (OQ-1) and an approved decorative brand-mark slot that can be hidden from assistive technology inside a whole-card link (Logo omits `aria-hidden`; OQ-1).

## Blocking decisions for the owner

| ID | Question | Recommendation |
| --- | --- | --- |
| OQ-1 | Is the generative cover a recessed well with the oversized decorative word (as proposed), or must it keep the web's radial neon halo and the seven-polygon isotype mark? | Keep the well plus word in v0.1. The halo is a brand radial gradient with no token and hand-writing gradients is forbidden; the `Logo` atom is the only brand-mark instance and it omits `aria-hidden`, so inserting it inside a whole-card link would inject the name “egdev” into the link's accessible name. Both are prerequisite gaps: they need a separate Logo-family/recipe proposal before they can be built, and can arrive later as an amendment. |
| OQ-2 | Is the paint-only action label a public `actionLabel` string (new convention `card-link-action-label`, pending approval), painted with a local token utility? Alternatively it becomes a part with free children, or waits for a shared paint-only link-label recipe. | Keep `actionLabel`. The card's single action cannot be a nested `Link`, `Link` exports no paint-only recipe, and a part with free children would let consumers put an anchor inside the card. Owner approval of the convention stays separate from spec approval; the shared recipe, if wanted, is a `Link` amendment, not part of this card. |
| OQ-3 | Does the card accept the token title step (`--text-heading-small`, 19.2 px) instead of the web's 26–34 px sans title? | Accept it now. It is the only sans card-title recipe; a `--text-heading-feature` token is a separate token proposal with its own approval, and the card must not hardcode a size. |
| OQ-4 | Is the interactive hover the approved `ListItem v0.2` anchor treatment (brand hairline plus `surface-2` tonal step, no movement) or the web's neon glow? | Use the `ListItem` treatment. It is already approved, Material-compliant and free of a new shadow or gradient; the glow would need a new recipe. Under reduced motion nothing moves either way. |
| OQ-5 | Is the root element the anchor itself (`a`, or the consumer's anchor through `asChild`), or an `article` with a stretched inner link? | Keep the anchor root. It is the `ListItem v0.2` model, it matches the web, it avoids a pseudo-element overlay and it cannot produce a second tab stop; the implicit loss of `article` semantics is documented and the surrounding grid/list provides the structure. |
| OQ-6 | Are “reading time · date” covered by a new `detail` convention, or should the card reuse the approved `meta`/`option-metadata` entry or take separate `readingTime`/`date` props? | Add `detail`. `meta` is already an approved entry whose meaning (below an option's label, as its accessible description) would be silently widened, and two separate props would add domain-ish fields the card does not need. One neutral short fact keeps the API small; the consumer formats it. |
