## 4. Findings

- **F1: the narrowed `aria-current` has no Docs, Controls or artifact row (plan G5, second acceptable outcome).** The real extraction, with the Storybook options and no `propFilter`, gives one merged `aria-current` row for the union: `parent` is React's `AriaAttributes`, the type is the full native union (`boolean | "time" | "true" | "false" | "page" | "step" | "location" | "date"`), the description is React's sentence followed by this change's JSDoc, and the tags are `control: false` with the planned reason. Storybook's `propFilter` keeps a row only when its first declaration is outside `node_modules` or the row is on a component's `documentedNativeProps` allow-list, and the artifact's own-prop filter applies the same first-declaration rule, so the row reaches neither. Plan section 5.2 lists exactly this case as acceptable, and none of its conditions for a stop holds: no diagnostic, no injected argument, no `select` row and no `.storybook/main.ts` change. Consequences: the narrowing is visible only in the TypeScript types, the JSDoc and the stories' text (nothing in the Docs table or the artifact names the allowed values), and the artifact and Controls pins state the absence instead of a row. A test pins the unfiltered row so a change in React's types or in the filter shows up. **Choices for the owner, only if a visible row is wanted:** adding `aria-current` to `documentedNativeProps.chip` in `.storybook/main.ts` would show the row, but with the merged native union as its type (the narrowing would still not appear in the table), and the artifact would still omit it unless its filter changed too. The lane did not do either.
- **F2: the artifact diff renumbers other components' `anatomy` indices, with no semantic change.** `anatomyUtilities` is an index table and two new entries (`aria-[current=true]:shadow-[var(--shadow-edge-strong)]` and `aria-[current=true]:focus-visible:shadow-focus`, the only utilities the artifact resolves to tokens that were new) shifted the indices that 67 `anatomy` and `layout` lists of 65 other components point at. Resolving every index back to its utility, 191 of 193 components are identical to the base; only `Chip` and `chipVariants` differ, `props`, `parts`, `composedOf`, `source` and `package` are unchanged for all 193, and no other top-level section changed. Plan section 5.3 says any other entry changing is a stop; this reading treats the renumbering as the generator's format, not as an entry changing, and the resolved comparison is the evidence. The review diff of `design-system.json` is a single minified line either way.
- **F3: plan size.** The change is 947 changed lines in the tracked files (891 insertions and 56 deletions), plus the 34-line approval record and this file, against the plan's roughly 410, mostly tests: `Chip.test.tsx` grew by 462 lines (the plan estimated 162) because Biome wraps `it.each` calls and string arrays one item per line and because the failing-focus proof runs for both values; the packed harness extensions are 111 and 94 lines (the plan said 34 and 21) for the same reason plus the strictness and order checks for both values. No scope was added to cover it.
- **F4: guards that cannot be RED.** Plan Risk 7 held: the `page` rules and the forced-colours rules are emitted by Pagination and Carousel with the same class names, so the E1 and E2 cases for them passed before any change, and the RED rests on the `true` rules and on the pinned recipe. The plan's AC-03, AC-10 and AC-12 guards are green before and after, as it said.
- **F5: harness notes.** The first browser run sequenced Tab from the previous story's focus point and landed on the Storybook docs skeleton instead of the current chip in the forced-colours block; the block was rewritten to reload the story first, and every value above comes from the rerun. The focus and hover blocks were not affected.
- **F6: `test:package-release` fails only on the two known headings** (`@egdev/tokens: CHANGELOG.md top section is 0.7.0, expected 0.6.1` and `@egdev/cli: CHANGELOG.md top section is 0.5.0, expected 0.4.0`): 13 of 18 pass and the five failures are the same `release:pack` abort, which clears when the parent folds the versions.
