## 4. Findings

- **F1 — plan slice boundary.** `Footer.test.tsx` (the plan's slice 2) imports the four new stories (slice 3), so slice 2 alone would fail the pre-commit `pnpm typecheck`. `Footer.stories.tsx` has to be committed with `Footer.test.tsx`.
- **F2 — a plan-listed test edit was not needed, and two others were.** The plan expected the `historicalRegistry` map to gain the two SectionShell IDs; no test required it, so it is untouched. Two whole-registry count tests (the organism and template receipts) double-counted the two IDs that the new receipt only amends, so they now skip a later receipt's own semantic amendments; the SectionShell test now reads its pre-image through `registryBeforeSemanticAmendments` and filters its usages by component. No receipt and no hash literal was edited.
- **F3 — the root-export pin lists type names.** `package-exports.test.mjs` pins the whole public name list, so the new `FooterRegister` export needed one entry there (the plan lists the file but not this pin).
- **F4 — the spec's contrast parenthesis.** Spec section 5 pairs `fg-secondary` 13.1:1 with the solid `surface-0` fallback. The token comment's 13.1:1 is on canvas; on `surface-0` the measured ratio is 11.37:1. All three roles still clear 4.5:1, so no promise fails; the spec is not changed.
- **F5 — the artifact's `anatomy` is sparse for Footer.** `footerVariants.register` lists `none` and `grafito` with empty utility-index arrays and `footerWrapVariants` indexes only `px-[var(--gutter)]`, while the `variants` lists carry the complete class strings (the wrapper's six and the three wash utilities, and an empty string for `none`, as SectionShell's `wrap` axis does). SectionShell's anatomy indexes more utilities from the same literals; the cause in the builder was not investigated. The new artifact assertion therefore reads the class lists and only the axis names from `anatomy`.
- **F6 — the generated registry view changes five rows.** `docs/prop-naming.md` changes the two widened rows (the new text and the two new Footer usages) and the three rows (`collection-items`, `accessible-name`, `heading-level`) whose Footer usage revision was refreshed; the plan estimated about 12 changed lines, the diff is five lines.
- **F7 — `(#562)` is cited twice.** The already committed Link entry cites `(#562)` and, as instructed, the new Footer `### Changed` entry cites it too; the plan's D3 recommended once. The parent decides when the versions are folded.
- **F8 — two files the plan owns were outside the delegated surfaces.** `packages/ui/src/index.ts` and `.storybook/preview.css` are plan section 2 rows owned by the parent; they were added to the allowed surfaces after a request and touched by one line each.
- **F9 — environment notes.** Stock headless Chrome reports no hover capability (the Link evidence's F1), so the run used a desktop-mouse flag; the Vite instance used by the differential logged one `Port 24678 is already in use` warning for its unused HMR socket, which is harmless. `pnpm build` regenerates the tracked artifact (idempotent: `artifact --check` and `system:check` pass after it) and shifts index arrays across many components' anatomy in one minified line.
- **F10 — consumer-run warnings are not Footer's.** The React 18.3.1 consumer run logs three warnings: two list-key warnings from `NowCardSamples` and `ProjectCardSamples` and one `<div>` inside `<p>` from a Progress sample. None mentions Footer, and this change touches none of those samples; the only Footer sample added is the wrapped Grafito one.
