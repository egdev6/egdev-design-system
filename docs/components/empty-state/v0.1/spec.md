## 1. Purpose and scope

- **Need / non-goals:** A passive empty state for a listing, or a filter combination, that returns nothing: it tells the reader that nothing matches and offers one way back, such as clearing the filters (#573, S4). Parts: a native heading (`title`), a short plain-text explanation (`description`), an optional decorative pictogram (`icon`) and one recovery action (`actions`: a supplied Button or Link). First consumer: egdev-website reading pages (consumer issue egdev6/egdev-website#49; reused across four listings plus filters per the cataloging draft, not re-verified here). The pages are not built, so no reference markup exists. Non-goals: no live region and no announcement (the host announces if it wants to; answered by L3); no focus management; not a loading, error or permission state; not the inline empties of Table (`messages.empty`) or CommandPalette (`messages.empty`), which keep their own contracts; not ListItem's "add an item" affordance; no children, illustration slot, second action, action group, `size`/`variant`/`tone` axis, built-in copy or default icon in v0.1; no filtering logic, data or router.
- **Cataloging decision / alternatives:** **new** molecule, owner-approved (L3). The reuse → variant → compose → extract order was walked on inspected public code; each earlier step fails:

It means "add an item here", not "nothing matched", and has no heading or explanation. |

## 2. Anatomy and composition

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| Root `eg-empty-state` | The single container; no role | `div`; no Radix | The parts below, nothing else |
| Icon (optional) | Decorative pictogram before the title | `span` with `aria-hidden="true"` around the system `Icon` at `lg` | One `IconName` glyph; no text |
| Title | The heading and the only required content | Native `h2` to `h6` chosen by `level` | Plain text |
| Description (optional) | Short explanation | `p` | Plain text |
| Actions (optional) | One recovery action | `div` around the supplied element | One Button or Link, rendered unchanged |

- **Radix / composition:** none. The component composes `Icon` itself; the action is supplied by the consumer and never cloned or wrapped in another control. No `asChild`, no ref, no Surface. DOM order is icon, title, description, actions, and the visual order is identical, so reading and tab order match.
- **Public markers:** `eg-empty-state` is the stable public root marker. No part markers are proposed: there is no legacy EmptyState to preserve and tests use roles and accessible names. No `data-state` or other own `data-*` (the component is stateless).

## 3. Public API

**Prop conventions:** looked up in the [canonical registry](../../../../skills/_shared/prop-naming.json) and [generated view](../../../prop-naming.md) by meaning, name and aliases (none of the entries below has aliases). All five own props reuse **approved** entries; no new semantic ID is proposed and no exception is requested:

| Concept | Result |
| --- | --- |
| Heading text → `title` | Reuse `heading-title` ("visible primary heading text identifying a page, section or content unit"; usages PageHeader, TipCard, ModuleCard). Its `avoid` sends status-message lead sentences to `summary`; EmptyState is a content unit with native heading semantics and no live behavior, so `title` stands and `message-summary` is rejected. The native `title` tooltip attribute is omitted from the public type. |
| Heading rank → `level` | Reuse `heading-level`. The type `2..6` is component-specific (TipCard, NowCard, ProjectCard, CommunityCard and ArticleFeature use the same type; OQ-2). |
| Explanation → `description` | Reuse `content-description` ("short explanatory text alongside the title of a content unit"; usages AlertDialogContent, DialogContent, ArticleFeature). Rejected: `lede` (`section-lede`, an editorial header introduction), `hint` (field help), `statusText` (header status). |
| Recovery action → `actions` | Reuse `trailing-actions` ("consumer-supplied action content"; usages Notice, ModuleCard, PageHeader). The one-element rule is component-specific, with PageHeader's single Button as precedent. A singular `action` would be a new concept for no gain, so none is proposed (OQ-3). |
| Pictogram → `icon` | Reuse `leading-icon` ("decorative icon ... hidden from assistive technology" that "repeats or decorates meaning already present in its text"; usages Notice, ModuleCard, TabBarItem, FieldMessage). Component type `IconName` (OQ-4). The meaning says "beside ... before it"; EmptyState puts the icon before the title in a stacked column, as TabBarItem lays out its icon and label as a column (`organisms/tab-bar/types.ts:57`). Exceptions concern an alternative prop name, so none is requested. |
| Size, variant, tone | Not used: no such axis in v0.1 (§6); `preset-dimensions`, `visual-treatment` and `surface-material-tone` are deliberately not applied. `className` and inherited native attributes need no own convention. |

## 4. Behavior

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| `title` only | `div.eg-empty-state` with one heading named by `title`; no other node | none |
| `title`, `description`, `icon` and a Button | In DOM and visual order: hidden icon wrapper, heading, `p`, actions wrapper holding the Button | none |
| `level` 2 to 6 | `h2` to `h6` | none |
| `level` omitted or invalid (1, 7, 2.5, NaN, non-number) | `h3`, silently | none |
| `description` absent, empty, whitespace-only or not a string | No `p` and no empty node | none |
| `icon` absent | No icon wrapper | none |
| `actions` `undefined`, `null`, `false` or `true` | No actions wrapper | none |
| `actions` is a Button, a Button `asChild` anchor or a Link | The element renders unchanged; pointer, Enter and Space activation and navigation belong to it | The consumer's own handler, once per activation |
| `title` empty, whitespace-only or not a string | Development warning `EmptyState requires a non-empty title. Nothing was rendered.` and no output (never an unnamed state); a later valid rerender renders normally | none |
| Props change on rerender | Content updates immediately: no transition, animation or announcement | none |
| Mount, update or unmount | Focus never moves and nothing receives `autoFocus` | none |
| `role`, `aria-live` or another omitted attribute reaches the component at untyped runtime | Dropped; the root never becomes a live region | none |

- **States / representation:** Stateless: no `data-state`, no variants, no mirrored classes. The warning sits behind the development-only guard TipCard uses (`molecules/tip-card/useTipCard.ts:37-41`, where the rank fallback also lives), and carries the final component name `EmptyState`.
- **Limits / consumer responsibilities:** The host decides when to render the state and when to unmount it. The host announces "no results" if it wants speech (a visually hidden status mounted before results change, updated with the count); a status inserted together with its content is not guaranteed to be spoken, as the Notice contract says (`molecules/notice/types.ts:11-13`). A consumer live region wrapped around EmptyState is unsupported composition with no single-speech guarantee. The action unmounts with the state when it succeeds (for example "Clear filters"), so the host must place focus on a stable target such as the filter control or the results heading. Copy and localization are the consumer's: there is no default text. A bare Link's hit area is its text line, below the 44px touch minimum; see §5 and OQ-3.

## 5. Accessibility

- **Accessible name / roles / relationships:** The root is a `div` with no role; the native heading carries the content's name and gives the outline an entry. Required consumer input: `title`. Semantics were weighed and the first row is adopted:

| Option | Verdict and reason |
| --- | --- |
| `div` with no role, native heading and `p` | **Adopted.** Static content with an outline entry; the component announces nothing; a screen-reader user reaches the heading by heading navigation and the action by Tab. |
| `section` with `aria-labelledby` (a `region` landmark) | Rejected: every instance becomes a landmark and one page can host several (listings plus filters); an empty state is not a navigation destination. |
| `role="status"`, `output` or any `aria-live` | Rejected: excluded by the approved cataloging (L3) and it would add a second announcement owner next to the host's. Notice already owns that responsibility. |
| `role="alert"` | Rejected: interruptive, and an empty result is not an error. |
| `article` | Rejected: not self-contained content (TipCard, ModuleCard and ArticleFeature are articles). |

- **Keyboard / focus:** The component is not interactive: no tab stop, `tabIndex` protected, no key handling. The supplied action is the only focus target and brings native behavior and its own `focus-visible` ring. DOM order equals visual order. Entry, exit and restoration of focus belong to the host (§4).
- **Announcements / other conditions:**
  - **Announcements:** none by design: no live region, no focus move. Host guidance is in §4; screen-reader output is Not evaluated.
  - **Touch target:** owned by the supplied action: Button `md` is 38.4px and `lg` 44.8px ("Use lg when the action must meet a 44px touch target", `atoms/button/types.ts:29`). A bare Link's hit area is its `text-label-default` line (11.2px), so stories and JSDoc prefer Button where touch matters.
  - **Text contrast** (hand-computed with the WCAG relative-luminance formula from the token hex values, `packages/tokens/src/theme.css:25,27,73-77,151-163`; not browser-measured):

| Text token (use) | surface-0 | surface-1 | surface-2 | surface-3 |
| --- | --- | --- | --- | --- |
| `fg-default` #FFFFFF (title) | 18.26 | 17.02 | 15.50 | 13.55 |
| `fg-secondary` #CCCCCC (description) | 11.37 | 10.60 | 9.65 | 8.44 |
| `fg-muted` #A1A2A8 (icon) | 7.17 | 6.69 | 6.09 | 5.32 |

  The icon is decorative, so WCAG 1.4.11 is not claimed for it, although it clears 3:1 on all four surfaces. Reading sections are `SectionShell register="grafito"` (`bg-surface-0/50` over the ambient layer, `templates/section-shell/types.ts:45`; DECISIONS "Pulso en Grafito"): that backdrop is translucent, so contrast over it is Not evaluated and needs a browser check (ES-11).
  - **Color independence:** the meaning is in the title text; the icon is decorative and hidden; no state is color-coded.
  - **Forced colors:** no custom paint and no `forced-color-adjust` rule: text and the icon (`currentColor`) follow the user agent, and nothing depends on shadow, border or background because none exists.
  - **Reduced motion / transparency:** no motion, transform or transition on any part, and no translucent surface, so no solid fallback is owed (the grafito host supplies its own). The supplied Button or Link keep their own `motion-reduce` rules.
  - **Reflow / RTL:** `min-w-0` and `wrap-anywhere` let long words wrap; the layout is centered and uses no physical left or right utility, so it needs no RTL variant.
  - **Not evaluated:** screen-reader output, real-browser zoom and reflow, grafito backdrop contrast, use on real touch devices.
