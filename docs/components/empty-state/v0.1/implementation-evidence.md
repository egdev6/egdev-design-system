## 4. Findings

- **F1: the plan's emission inventory names `calc(var(--spacing) * n)`; the shipped CSS emits `var(--space-n)`.** `.gap-3` is `gap: var(--space-3)`, `.px-4` `padding-inline: var(--space-4)`, `.py-8` `padding-block: var(--space-8)`, `.gap-2` `gap: var(--space-2)`, `.m-0` `margin: var(--space-0)`. It is the same token family and the computed pixels equal the spec's arithmetic, so no promise changed; the new tests pin the emitted form.
- **F2: two existing pinned inventories had to include `EmptyState`, in files the plan names as edit surfaces.** `scripts/prop-naming.test.mjs` pins the exact usage list of `content-description` (`AlertDialogContent`, `DialogContent`, `ArticleFeature`) inside "content description binds the owner decision and preserves dialog usage history"; the list now ends with `EmptyState`. `scripts/design-system-artifact.test.mjs` pins the inventory of components carrying `classNameAllows` ("classNameAllows preserves the reviewed component and part inventory"); it now lists `EmptyState`, as commit `cbde33b` extended it for `HomeTemplateAnchor`. Both edits extend a reviewed list by one name and weaken nothing. The plan's stop line reads "an existing suite must change to pass" and §5.1 reads "re-run to find any other pinned count": I treated these as the second, and flag them for the parent to confirm.
- **F3: the artifact's utility table grew by one entry, so other components' anatomy indices renumber.** `anatomyUtilities` gained `py-8` (400 to 401 entries), and the anatomy arrays that point into the table shifted by position in 139 places across 30 components. Resolving every index before comparing shows **zero semantic differences in all 188 pre-existing components**; the real changes are the new component, one catalog entry (113) and the five convention lists. The `system.md` diff holds only the `EmptyState` section and those lists. `design-system.json` is one minified line, so its git diff is the whole line.
- **F4: `ref` is dropped in the hook.** React 19 hands `ref` to a function component as an ordinary prop, so the hook strips it (plan Risk 6) and a test with a `createRef` proves the root never receives it. React 18.3.1 never passes `ref` to a function component, so there the strip is a no-op; the packed matrix does not exercise a ref.
- **F5: an `icon` outside `IconName` throws at an untyped boundary** (plan Risk 5): `Icon` reads `iconPaths[name]`. No guard was added because the spec promises none; `null` and `undefined` are both treated as absent.
- **F6: the changelog scope.** The brief named the unpacked sections of ui (`0.11.0`), system (`0.13.0`), effects (`0.2.12`) and mcp (`0.4.12`), while plan section 7 says "no `mcp`, `effects`, `cli` or `tokens` entry" and the two other changelogs are outside the allowed surfaces. Only ui and system received a bullet, both citing `(#573)`. The mcp README digest was regenerated, as for Prose.
- **F7: the commit slicing of plan section 10 cannot be reproduced file by file.** `useEmptyState.ts` and `EmptyState.test.tsx` span the plan's slices 1 and 2, so they are one component commit here, as in the Prose lane.
- **F8: `pnpm test:package-release` fails only on the two known changelog headings** (`@egdev/tokens: CHANGELOG.md top section is 0.7.0, expected 0.6.1` and `@egdev/cli: CHANGELOG.md top section is 0.5.0, expected 0.4.0`); 13 of 18 pass and the five failures are the same `release:pack` abort. Both clear when the parent folds the versions.
- **F9: scratch left outside the repository.** `/tmp/es573/` holds the CDP scripts, an unneeded copy of the artifact and Chrome's profile (about 7 MB), and `/tmp/pc-backup-68287.mjs` is a backup of the consumption test used for the mutation check. The static `storybook-static` output is gitignored.
