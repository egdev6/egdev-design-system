## 1. Gates and unchanged boundaries

1. Approve this plan and the exact future edit surfaces and commands before implementation. This document proposes parallel work; it does not delegate, commit, publish or release. No new token, dependency, inline appearance, runtime measurement, dynamic utility interpolation, stylesheet or internal module is approved. The six meaningful Dialog roles remain; **No stylesheet**.
2. Extend only the existing Dialog molecule. Sheet `size='full'` fills the overlay boundary; omitted sheet size remains capped. Centered `sm`, `md`, `lg`, `full` and default `md` remain supported: “sheet-only” describes the **extension**, not removal of centered `full`. The title clamp and action placement are independent sheet-only choices; all three may be combined or used separately.
3. Preserve Radix ownership, document-wide modality, host lifecycle, `Surface` paint, RTL, motion/transparency fallbacks, public markers, className boundary, native exclusions and actual ref contracts. The custom mount and overlay scope are separate. Content `className` remains outer-layout composition only; width, padding, radius, paint, positioning and focus overrides are unsupported even if the cascade permits them. No DS046 allowance or DS047 exception is added.
4. For a clamped title, the consumer must provide an always-discoverable visual route to the complete string usable by keyboard, pointer and touch; a body copy is one valid example. Neither `title` nor Tooltip alone qualifies. No title slicing, generated tooltip, new focus stop or hidden/replaced Radix Title.
5. Normal supported hosts fit the complete chrome and a body **content box** at least `--space-14` high after padding; consumers supply a manageable action set and host. For a sheet opting into clamp or header actions, an insufficient host uses the approved exceptional overlay scroll; top actions can then scroll out of view. This is not an unconditional only-body-scroll guarantee. A full-width-only sheet does not opt into this exception. No nested confirmation or pending-dismissal lock from #544 is included.
6. Stop if the approved constraints cannot coexist in actual CSS/Radix, or if a new token, dependency, style role, contract change or unapproved surface is needed. Do not weaken the body, title, focus or hit-target guarantees to make a check pass.

## 3. Layout, fallback and target strategy

### Width, title and actions

- Resolve sheet `full` independently from the centered size CVA so `max-w-none` wins over the legacy sheet cap only when selected; retain logical inline-end placement, `h-full`, Surface overlay and RTL-aware motion. Container scope fills the overlay's content box, itself inset to the host **padding box**, not its border box. Viewport scope fills the viewport overlay even if the portal is mounted in a custom host; existing fixed-containing-block/clipping restrictions remain.
- Use a static two-line clamp on the Radix Title only, with wrapping for unbroken words and visual ellipsis. Keep the entire string in the DOM and accessible name, no synthetic duplicate or `aria-hidden`. Verify fitting text remains fully visible, and that v0.3's first-title-line/close-centre and last-visible-title-line/status and inline-description baseline rules hold in both header layouts. If an ordinary clamp changes those alignments, find a compliant static composition or stop; do not assert alignment from class names.
- Header actions use the same ReactNode and handlers, once. Only `null`/`undefined` omit the part: `false`, `0`, empty strings and other ReactNode inputs retain existing nullish behavior. Keep `eg-dialog__foot` on the new `div`, with no toolbar/landmark role. The default `footer` and its DOM order remain unchanged. Reuse the existing sheet footer's `surface-1` and hairline semantics, overriding conflicting legacy foot styling through static utilities/CVA, not copied Surface classes or handwritten paint. Check wrapping and cascade with the real stylesheet.

### Insufficient host

Prototype a **static intrinsic-sizing** solution within the existing overlay/panel/body rather than a resize observer or inline geometry. For clamp or header-action sheets only, allow the sheet's intrinsic minimum to include non-shrinking header/actions and a body minimum whose **content** is `--space-14`, accounting for the actual default/compact body padding and box sizing. Permit the existing overlay grid to grow/scroll when that minimum exceeds the available height; in a sufficient host it must remain stationary while the body scrolls. Verify grid track sizing, `h-full`/`max-h-full`, Surface overflow, scroll origin and `twMerge` in built CSS: a plausible `min-height` class alone is not evidence. Avoid adding a separate action scroll area. Default sheets, including `size='full'` alone, must not acquire the new sizing behavior. If static intrinsic sizing cannot meet both conditions or Radix blocks the overlay's scroll, stop for owner review rather than adding measurement or clipping controls.

### Close and header action targets

The built-in ghost `lg` IconButton is visibly 38.4px with an automatic centred 44.8px `--space-14` target under default tokens: 3.2px outset per side. Reserve the full square **and** visible-root focus ring from panel/host clipping and other hit regions. Do not apply the ButtonGroup/Tabs compact-target exceptions. For adjacent IconButtons whose cross-axis target ranges overlap, S12 requires visible separation of **at least one spacing token above the sum of target outsets**: `sm/lg` → `gap-5`, `md/lg` → `gap-4`, `lg/lg` → `gap-3` with default tokens. Apply the same outset-plus-margin principle to adjacent non-IconButton interactive targets, between wrapped rows and in RTL. A flex `gap` does not by itself clear the absolutely positioned close: reserve and measure its real rectangle against each action, including vertical overlap, stacking and focus paint. Consumer-supplied nested action groups must themselves provide compliant spacing; arbitrary ReactNode internals cannot be repaired or guaranteed by the Dialog.

### Marker invariant and legacy cascade

Stable `eg-dialog*`/`eg-dialog__foot` markers remain public markers, **not styling selectors** for this change. Do not introduce `.eg-*` selectors, including Tailwind arbitrary/descendant variants that emit them; use marker-free static recipes and, if necessary, scoped non-marker state/data attributes without inventing a public API. Keep legacy CSS unchanged: it already contains `.eg-dialog__head` and `.eg-dialog__foot` rules, so a blanket assertion that the whole shipped stylesheet contains no `.eg-*` selector would be false. Compare newly emitted selectors against the baseline and assert the new rules use no marker selectors; verify the retained legacy rules are overridden where needed. Tests may inspect public markers as markers, not turn them into appearance selectors.
