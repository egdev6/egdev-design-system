## 1. Purpose and scope

- **Need / non-goals:** Detail pages of the web's four collections (editorial, events, projects and notes, in es and en) show long-form content that the site converts from Payload Lexical rich text to semantic HTML. Prose is the reading column for it: one passive wrapper that gives bare semantic children a readable, token-backed presentation on the grafito register, with a bounded line length (#569; the pages are not built and the issue records no mitigation). Today no export styles semantic children, the only measure token is `--container-quote-pull` (40ch) and `text-body-default` is 12.8px at the ×0.8 scale (#218), which the issue calls small for long reading. Supported children in v0.1: `h2`–`h4`, `p`, `ul`/`ol`/`li`, `a`, `strong`, `blockquote`, `pre`, inline `code`, `img`, `figure`/`figcaption`, a simple `table` (`th`, `td`) and `hr`.

  **Non-goals:** no Lexical, HTML or Markdown parsing or conversion (app-side, as the issue states); no sanitization (Prose takes React children and never an HTML string, block 3); no content, heading anchors, table of contents, copy-code button or syntax highlighting; no embeds (#574) or enlarged image view (#575); no complex data tables (use `Table`); no styling for `h1`, `h5`, `h6`, `dl`, `details`, `kbd`, `mark`, `sub`/`sup`, `iframe` or `video`; no design-system component nested inside (block 4); no `measure`, `asChild`, ref, variant or light-theme API; no change to any existing component.
- **Cataloging decision / alternatives:** **New** primitive, owner-approved at cataloging (L3). Re-check of the approved draft against the inspected code: **not contradicted**; four refinements are listed last. The reuse → variant → compose → extract order, on public code:
  - **Reuse:** no export styles a subtree. `Text` and `Heading` style one element each (`packages/ui/src/primitives/text/types.ts:289,320`). `PullQuote`, `Table`, `PhotoFrame` and `Link` are prop-driven components that render their own markup. `Divider` is a span-based separator (`primitives/divider/types.ts`), not an `hr`, and `Kbd` is one inline key. The system has no list, code-block or thematic-break piece.
  - **Variant:** a `Text` variant would change what Text is, one element versus a whole subtree; the same holds for each other component.
  - **Compose in the app:** possible only by mapping every Lexical node to React (a converter the app would own, with no system piece for lists, code or `hr`) or by restyling the HTML on each page. Four collections share the need and no domain data is involved, so the web consumer amendment applies (`docs/CATALOGACION.md:33`): a reusable piece enters `@egdev/ui`.
  - **Extract:** nothing hides a reusable subtree style. PullQuote's filet and Table's header and cell recipes are internal parts of those components; block 6 echoes their token roles and does not extract them.
  - **New, level primitive:** `docs/CATALOGACION.md:25` allows reusable structure or semantics on tokens and utilities and forbids composing product concepts, imposing copy or coordinating controls. Prose does none of these; its siblings are Text, Heading, Surface and Stack.
  - **Implementation alternatives inside "new":** a hand-authored `prose.css` with tag selectors is rejected, because hand-authored recipes may not use tag selectors or nested blocks while generated Tailwind variants are not hand-authored recipes (`skills/_shared/component-contract.md:105`). Descendant utilities (arbitrary variants) in CVA are chosen; the compile evidence below shows they work on this toolchain. That is the justification for "No stylesheet".
  - **Refinements to the approved draft (none changes the decision):** (1) the draft's `size` values `default \| large` would leave the component default at 12.8px, the size the issue calls too small, so block 3 sets `sm \| md` with default `md` (OQ-2, resolved as recommended); (2) the draft maps anchors to "the `Link` recipe", but Link is `inline-flex` with an arrow and the label step (`atoms/link/types.ts:81-82`), so Prose echoes only its colour, underline and focus roles; (3) the draft's "well recipe for `pre`" cannot be a `Surface`, because the code arrives as a bare element, so block 6 states it as a spec-approved recipe (OQ-3, approved); (4) the token name collides with Tailwind's deprecated `max-w-prose` default (block 6).
- **Evidence / level and package:** Primitive in `@egdev/ui`, proposed `packages/ui/src/primitives/prose/`. Radix base: none; the component is static, with no interaction, so no individual Radix package applies or is added. Verified by inspection: `packages/ui/src/index.ts:201-238` (Primitives section; no `Prose`); a search of `packages/*/src`, `docs/`, `skills/` and `scripts/` finds the word only as the Textarea `prose` variant, the legacy `Field --prose` CSS and a Tailwind `max-w-prose` class in a Text test; the Text, Link, PullQuote, Table, Divider, Surface and SectionShell sources, `lib/cn.ts`, `styles/compiled.css`, `packages/tokens/src/theme.css`, `docs/MATERIAL.md`, `docs/DECISIONES.md` and the registry; read-only `gh issue view` on #569 (open; labels `enhancement`, `status:needs-review`) and on egdev6/egdev-website#49 (it lists #569 as a checkbox only).

  **Compile evidence** (scratch only, no file written): Tailwind 4.3.3 from this repo's `node_modules`, fed the real `packages/tokens/src/theme.css`. A candidate utility set equivalent to the block 6 recipe (123 class strings at `md` and `canvas`, plus the `sm` and `raised` alternates) compiled to the intended selectors (`a:hover`, `a:focus-visible`, `:not(pre) > code`, `> :first-child`, `pre:focus-visible`, `li::marker`), and all 123 survived `cn()` with the project's merge configuration (`lib/cn.ts:6-39`). Property order in the emitted CSS puts `m-0` before `mt-12` and `text-body-large` before `[font-weight:…]` on the same selector. This shows feasibility, not visual quality or built-package behavior (PRS-04 to PRS-06, PRS-13).

## 2. Anatomy and composition

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| Root `eg-prose` | The one part: reading column (measure, body step), outer-margin trimming and the descendant presentation | `div` | React children: bare semantic flow content, converted and sanitized by the host |
| Styled descendants (not parts, no markers) | Presentation selected by tag through descendant utilities on the root | `h2`–`h4`, `p`, `ul`/`ol`/`li`, `a`, `strong`, `blockquote`, `pre`, `code`, `img`, `figure`/`figcaption`, `table`/`th`/`td`, `hr` | Supplied by the consumer; never created, wrapped or reordered by Prose |

- **Radix / composition:** none. No existing component is imported or composed: the recipes echo token roles from Text/Heading, Link, PullQuote, Table and the Surface well without importing them (block 6). Surface is not composed because the children are bare elements; the code well is therefore a spec-approved recipe (OQ-3).
- **Public markers:** `eg-prose` only, as the stable root. No `eg-prose__*` part markers: the descendants are bare elements the consumer owns, and no part-selector API is granted. No ids, no `data-*` and no `data-state` (nothing is stateful).

| Prop / event | Type | Required | Default or rule | Description |
| --- | --- | --- | --- | --- |
| `children` | `ReactNode` | yes | none | The content: bare semantic elements, as React nodes. `@control false` with a reason (non-serializable). |

| `tone` | `'canvas' \| 'raised'` (`ProseTone`) | no | `canvas` | Brand text role of inline code: `canvas` for `surface-0` and the grafito register, `raised` for `surface-1…3` hosts. Never paints a background. |

No events. No `measure` prop: the measure is built in.

- **Prop conventions:** [registry](../../../../skills/_shared/prop-naming.json), [generated view](../../../prop-naming.md) and [workflow](../../../../skills/_shared/component-contract.md#prop-naming-registry). Applied, both existing approved conventions:
  - `size` → `preset-dimensions` (`prop-naming.json:747`): component-specific presets. New usage to record: `Prose: ProseSize ('sm' | 'md')`. Its avoid note (assuming identical dimensions across components) is respected.
  - `tone` → `surface-material-tone` (`:1361`): a material surface tone with component-specific values. The existing `canvas | raised` usages (Text, Heading, PullQuote, SectionHeader) have the same meaning. New usage to record: `Prose: ProseTone ('canvas' | 'raised')`. The scoped `foreground` exceptions of Text and Heading do not apply: Prose has no foreground prop.
  - **Lookup** (terms: measure, width, reading, prose, typography, semantic, html, rich text, content, tone, size, variant, slot): no entry covers a measure or width prop, and none is proposed because the measure is built in. Rejected: `visual-treatment` / `variant` (`:1024`; there is no variant axis), `slot-composition` / `asChild` (`:2882`; not proposed), `field-message-content` / `children` (`:7801`, proposed; scoped to plain-text form annotations), `section-content-wrap` / `wrap` and `top-bar-content-width` / `contentWidth` (no wrapper and no gutters here). `children`, `className`, `lang` and `id` are native, not own conventions.
  - **New proposals, new exceptions:** none. Registry usages for `size` and `tone` can only be appended once `ProseProps` exists and is reviewed (`source: {path, symbol, revision}`); the plan adds them, then runs `pnpm props:docs`, `pnpm props:check` and `pnpm test:props`. This spec edits no registry file. Convention approval stays separate.
- **Native props / refs:** `Omit<ComponentPropsWithoutRef<'div'>, 'children' | 'role' | 'aria-label' | 'aria-labelledby' | 'dangerouslySetInnerHTML'>`, forwarded to the root. `role` and the two naming attributes are omitted because the root is a generic `div`: a host that needs a landmark wraps Prose in its own `article` or `section`. `dangerouslySetInnerHTML` is omitted from the type and an untyped value is discarded at runtime, as Text does (`useText.ts:60`), so Prose never takes an HTML string; the consumer converts and sanitizes. No public ref and no `asChild` (passive, like Text); `style` is forwarded but unsupported for appearance.
- **Controlled / uncontrolled:** Not applicable; there is no state or event.
- **Compatibility:** New, additive export; no existing API or marker changes. The plan adds `ProseProps`, `ProseSize`, `ProseTone` and `Prose` to the Primitives section of `packages/ui/src/index.ts` (lines 201–238). `proseVariants` is not exported: the descendant recipe is not for composition. The React peer range is `^18.3.1 || ^19.3.0` (the tested matrix); there is no ref API, so no React-19-only construct, and packed-consumer evidence is still required (PRS-13). The `@egdev/system` artifact and `docs/CATALOGO.md` (via `scripts/catalog_data.py` and `scripts/build_catalog.py`) change only when separately authorized.

## 4. Behavior

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| Rendered with children only | One `div.eg-prose` holding the children unchanged and in order, with `size` `md` and `tone` `canvas`; no role, id, `tabindex`, `data-state` or extra node. | None |
| `size` or `tone` omitted, or an untyped unsupported value | Falls back to `md` and `canvas`, as Text's hook does (`useText.ts:64-66`). | None |
| A supported element at any depth | Presented per block 6; the first direct child loses its top margin and the last its bottom margin. | None |
| An unsupported element (`h1`, `h5`, `h6`, `dl`, `details`, `kbd`, `iframe`, `video`…) | Not styled by Prose: it renders with the browser (or Preflight) defaults, relative to the root's body step. No warning. | None |
| A system component that owns a recipe (`PullQuote`, `Table`, `PhotoFrame`) rendered inside | Unsupported. Prose's descendant rules also match its elements at specificity (0,1,1) or higher and would override its single-class utilities (for example PhotoFrame's image fill). Nothing guards it. | None |
| Empty or whitespace children | The root renders empty; no placeholder. | None |
| Hover on a link; keyboard focus on a link or on a focusable `pre` | Hover removes the underline and keeps the colour; focus shows `--shadow-focus`. | None |
| `className` supplied | Merged after the variants; margins and placement apply; the root marker survives. | None |

- **States / representation:** none of its own. Link hover and focus use native pseudo-classes in the generated variants; no state is mirrored into a class and no `data-state` exists.
- **Limits / consumer responsibilities:** conversion and sanitization; heading levels (the page title is the `h1`; Prose styles `h2`–`h4`, so the converter caps or remaps the rest); `alt` text; table header cells and captions; the `lang` attribute (the uppercase of `h2` and `th` is CSS and follows it); link `target` and `rel`; a scroll region for tables wider than the measure; font loading, including an italic face (the tokens declare families only, and Storybook loads Barlow weights 400–700 without italics, `.storybook/preview.css:1`, so `em` is synthesized there); code highlighting. Outer-margin trimming reaches direct children only: a wrapper `div` between the root and the content defeats it, while every other rule is descendant-based and still applies. A consumer that holds an HTML string renders it through its own element inside Prose (for example a `div` with `dangerouslySetInnerHTML`, after its own sanitization); the descendant rules apply to that markup and only the outer-margin trimming is lost, because the wrapper becomes the only direct child.

## 5. Accessibility

- **Accessible name / roles / relationships:** the root is a generic `div` with no role and no name. Prose adds no ARIA attribute, id or wrapper and never changes the semantics, order or text of its children; headings, lists, links, images, tables and separators keep the roles of the supplied HTML. Landmark, heading outline, `alt` text and table headers are the consumer's.
- **Keyboard / focus:** native only; Prose owns no key handling and adds no `tabindex`. Links are reachable by Tab in DOM order. `a:focus-visible` and `pre:focus-visible` paint `--shadow-focus`, which replaces the well shadow on focus (`docs/MATERIAL.md:98`). A horizontally scrollable `pre` is keyboard-reachable only where the browser makes scrollers focusable (not verified here) or where the converter adds `tabindex="0"` and a name.
- **Announcements / other conditions:** no live region. Non-colour cues: links keep an underline at rest (the hover state removes it, as Link `plain` does, and keeps the colour); the quote has a logical-start rule; table headers are `th` elements on a band. Contrast, computed from token hex values and not measured in a renderer: `fg-default` is 18.26:1 on `surface-0` and 17.02:1 on `surface-1`; `fg-secondary` is 11.37, 10.60, 9.65 and 8.44:1 on `surface-0…3`; `fg-muted` is 7.17:1 on `surface-0` and at least 5.32:1 on `surface-3`; the neon link text (`--color-link-default`, `theme.css:184-186`) is 4.61:1 on `surface-0` but 4.30, 3.92 and 3.42:1 on `surface-1…3`. That last gap is the owner-retained Link trade-off (the `theme.css` comment: "The owner retained neon Link text and red-200 hover, including the contrast trade-off"), not a new decision; the underline is the non-colour cue. Neon inline code at 11.2px has the same ratios, so below 4.5:1 on `surface-1…3`; Table's code cells already take that trade-off with `text-fg-brand-raised` (`molecules/table/types.ts:189`), so it is not new; OQ-4 is resolved as recommended: the brand colour by tone stays, to be judged in VIS-01. Real contrast on the grafito register, where `surface-0` is only 50% over the particle layer (`templates/section-shell/types.ts:45`), depends on the host and is Not evaluated. The measure uses `max-width`, so content reflows at zoom; `wrap-break-word` keeps long URLs inside it; `pre` scrolls inside the root; a wider table overflows (OQ-7). Prose has no motion and paints no translucent surface, so reduced motion and reduced transparency change nothing. Inline links fall under the usual inline exception of the WCAG 2.2 target-size criterion (external knowledge, not re-verified). Screen-reader output and forced-colors rendering are Not evaluated.

  **Token — owner-confirmed (S6, OQ-1), not yet added:**
  - **Decision (OQ-1, owner-confirmed):** `--container-prose` in `packages/tokens/src/theme.css`, `@theme static`, beside `--container-quote-pull` (`:346-347`); value `65ch`; comment "Reading measure of long-form prose (#569), relative to the prose root's own font metrics."   - **Evidence:** (1) No reading measure exists. The only `ch` token is `--container-quote-pull: 40ch`, a quotation measure pinned by `packages/tokens/tests/typography-spacing.test.mjs:252` and `scale-reduction.test.mjs:55`; the page wrap `--content-max` is 1024px (`theme.css:499`) and SectionHeader caps its lede at `--bp-sm`, 520px (`molecules/section-header/types.ts:103`). (2) At `md`, 1024px is 64em (1024 ÷ 16). A sans face's digit advance is typically 0.5–0.65em (an assumption: no font files are in the repo and Storybook fetches Barlow from Google Fonts, `.storybook/preview.css:1`), so the unconstrained wrap holds about 98–128ch, while 65ch is about 520–676px. (3) External references, not re-verified in this session (no network use): WCAG 2.2 SC 1.4.8 (Level AAA) asks for lines of at most 80 characters, and the typographic tradition cited for single-column text is 45–75 characters, about 66 ideal (Bringhurst). Tailwind's own `max-w-prose` is 65ch, verified locally in `node_modules/tailwindcss/theme.css:509` (the deprecated `--max-width-prose: 65ch`).
  - **Name collision (verified by compiling with Tailwind 4.3.3, scratch only, with `--container-prose: 70ch` in the test theme):** with only the tokens theme referenced, as `packages/ui/src/styles/compiled.css:5` does, `.max-w-prose` is `max-width: var(--container-prose)`. In an app that also loads Tailwind's default theme, the same class compiles to `max-width: 65ch`, because the deprecated `--max-width-prose` wins (`max-w-*` looks up `--max-width` before `--container`). At exactly 65ch every case agrees. At another value the token would be ignored wherever a consumer's own Tailwind build generates `max-w-prose`; a different value should therefore use a non-colliding name (`--container-reading`, utility `max-w-reading`). With the confirmed `65ch` no case diverges and the name stays `--container-prose`.
  - **Release effect (not decided here):** a new token changes `@egdev/tokens` (0.6.1; the precedent 0.6.0 is "Add `--mask-scroll-fade-inline`"), which was not bumped in 0.11.0, so S2 moves its coupled versions and T7 chooses the numbers. Plan items: the declaration, `pnpm tokens` to regenerate the compiled `tokens.css` (never edited by hand), a pin test beside `typography-spacing.test.mjs:252`, and artifact regeneration. The built `packages/ui/dist/styles.css` (a local build output) shows the pattern `.max-w-quote-pull { max-width: var(--container-quote-pull, 40ch) }`; whether Prose receives the same literal fallback for apps on an older tokens version is checked by PRS-03.
- **Dynamic geometry:** None. No inline style, no interpolated class and no limited exception.
- **Class composition / consumer layout:** only the root accepts `className`: `cn(proseVariants({ size, tone }), className)`. Supported: margins (such as `mx-auto` to centre the column), self-alignment and flex or grid placement, which is DS046's base list (`packages/cli/src/appearance-guard.mjs:53-81`); no `@classNameAllows` tag is needed or declared. Width constraints are unsupported: DS046 rejects them for consumers, but at runtime `cn()` lets a `max-w-*` class replace `max-w-prose` (verified with the project's merge configuration), so the measure is guarded by consumer lint, not by the component. Descendants take no `className`.
- **Files / pending proposals:** `packages/ui/src/primitives/prose/` with the six mandatory files. `types.ts`: `ProseSize`, `ProseTone`, `ProseProps` with English JSDoc (`@control select` on both axes, `@control false` with a reason on `children`, bare `@default md` and `@default canvas`) and `proseVariants`, the descendant recipe. `useProse.ts`: defaults and fallbacks, the discarded `dangerouslySetInnerHTML`, `cn()`. `Prose.tsx`: JSX only. `Prose.test.tsx`, `Prose.stories.tsx` (`Primitives/Prose`) and `index.ts`. **No stylesheet** (block 1); no additional module.
