## 1. Purpose and scope

- **Need / non-goals:** egdev-website renders long-form detail pages through `Prose`, which styles a bare `a` with the link colour, underline and focus ring and inherits the 16px reading size (v0.1 §6, `a` row). `egdev-ds doctor` DS040 forbids a raw `<a>` in app code, so the site renders DS `Link` instead, whose label step is 11.2px inside 16px copy (S1 of `odd/tasks/prose-links-580.md`). The need is that the anchors Prose is designed to style pass DS040 when they are Prose descendants, so a consumer can write the bare `a` the Prose contract already lists as a supported child. **Non-goals:** no Link variant, size or axis; no new component; no Prose prop, default, type, export, marker, recipe or token; no change to any DS046, DS047 or DS048 behavior; no config key, flag, exit code, JSON or plan format; no module resolution, `tsconfig` reading or cross-file analysis in the guard; no enforcement of the Prose nesting rule; no validation of an anchor's `href`, `rel`, `target` or accessible name; no `@egdev/cli` change other than the DS040 exemption of block 3.
- **Exact v0.2 delta:**
  1. `@egdev/cli`: DS040 does not report a raw `a` in a file that renders `Prose` (block 3, CLI contract). `button`, `input` and `label` stay reported, and every other file and check is unchanged.
  2. The v0.1 supported-child list gains its usage rule, in documentation only: links are written as bare `a` elements and `Link` does not belong inside Prose (OQ-2). The `children` description of `ProseProps` gains that sentence and the story guidelines repeat it (OQ-3); no type, tag, default or code changes.
  3. Nothing else changes: the v0.1 recipe, props, anatomy, markers, token, accessibility and acceptance criteria PRS-01 to PRS-15 stay as approved, and the nesting rule of v0.1 OQ-8 is not enforced by anything.
- **Cataloging decision / alternatives:** **Reuse, with a guard exemption** ([cataloging.md](cataloging.md), Approved with this spec). Reuse → variant → compose → extract → new was walked on inspected code; Prose already styles the anchor and only the guard blocks the pattern.

**CLI contract (`egdev-ds doctor` DS040).** The observable behavior after the change; how the code achieves it belongs to the implementation plan.

1. **What DS040 reports (unchanged).** A JSX opening or self-closing element whose tag is the identifier `button`, `input`, `a` or `label`, in a non-test `.tsx` file under `sourceDirectory`, honoring `exclude`, unless it is the sole child of a PascalCase element whose `asChild` is true, or an allowlist entry covers it. The message is `Raw <snippet>: use a DS component or add an allowlist entry with an issue.` with file and line, as today.
2. **Prose binding.** A name that TypeScript's in-memory symbol resolution (the program DS046 already builds; no disk, `tsconfig` or `node_modules` read) ties to an import of the export `Prose`: `import { Prose } from '<module>'`, `import { Prose as Reading } from '<module>'` (matched by the real export name, so `<Reading>` counts), or `import * as DS from '<module>'` rendered as `<DS.Prose>`. `<module>` is any specifier, so `@egdev/ui`, an app barrel such as `@/components/egdev-ui` and a relative path all qualify (OQ-1). These do not count: a type-only import or specifier; a parameter, local, function, class or other declaration that shadows or re-declares the name (it resolves to another symbol, as in `ds046.test.mjs:126`); a default import or `require`; `export { Prose } from …`; a barrel alias that renames the export (`export { Prose as Article }`); a lowercase `<prose>`.
3. **Prose file.** A file in DS040's scope that contains at least one JSX opening or self-closing element whose tag is a Prose binding. Importing or re-exporting `Prose` without rendering it does not make a Prose file.
4. **The exemption.** In a Prose file, DS040 does not report a JSX element whose tag is the lowercase identifier `a`, wherever it sits in that file: inside the `Prose` element or outside it, at any depth, in any function or component of the file, with any attributes (none is inspected). In a Prose file `button`, `input` and `label` are still reported with the existing message; in a file that is not a Prose file nothing is exempt.
5. **Everything else is unchanged.** The sole `asChild` child rule in every file; the DS040 message, line and snippet; the exclusion of test and spec files and `__tests__`; `sourceDirectory` and `exclude`; DS041, DS043, DS044, DS045, DS046, DS047 and DS048 give byte-identical results for any project. DS046 and DS047 never judged raw anchors: they collect classes only on owners imported from the exact specifiers `@egdev/ui` and `@egdev/effects`, so a class on an exempt `a` is an app-owned class, as on any raw element, and never a DS owner, and nothing changes; a class on the `Prose` element itself keeps DS046's base list (placement only), and DS047 still reports an app selector that reaches through that class to its descendants (`.post > a`). No flag, exit code, JSON or plan format, `init` or `upgrade` file effect, doctor code, config key or dependency changes, and the scaffolded agent rules are not rewritten. The check reuses the one parsed program, so nothing is parsed twice.
6. **Allowlist.** An entry whose `file` and `pattern` match only an anchor that is now exempt is no longer used, so the existing rule reports it: `DS042 error <file>: Stale allowlist entry <pattern>; remove it.` An entry for an anchor that is still reported is consumed once, as today.
7. **Compatibility.** A relaxation: no project that passes today fails afterwards, except through a stale allowlist entry as in item 6, which `upgrade` and `doctor --from` also surface as a resolved mitigation for an entry whose issue is #580 once a release changelog cites `(#580)` (`docs/distribution/consumer-requests.md:110-121`). The fix for it is to delete the entry and its comment.
8. **Version.** No version moves in this change. T3 chooses the release number (OQ-4); the cli changelog entry goes under a new `## Unreleased` section.

- **Native props / refs:** Unchanged: `Omit<ComponentPropsWithoutRef<'div'>, 'children' | 'role' | 'aria-label' | 'aria-labelledby' | 'dangerouslySetInnerHTML'>` forwarded to the root; no public ref and no `asChild`.
- **Controlled / uncontrolled:** Not applicable.

## 5. Accessibility

- **Accessible name / roles / relationships:** Unchanged. A bare `a` takes its name from its content and its role from the element; the guard checks neither, and the consumer owns the link text and the address (v0.1 §4, "link `target` and `rel`").
- **Keyboard / focus:** Unchanged. Links are reached by Tab in DOM order and `a:focus-visible` paints `--shadow-focus` (v0.1 PRS-11). The exemption adds no handler, `tabindex` or focus behavior.
- **Announcements / other conditions:** Moving from `Link` to a bare `a` removes what `Link` does for an external link: `target="_blank"`, a merged `rel` with `noopener noreferrer`, and a visually hidden, localizable notice (`packages/ui/src/atoms/link/types.ts` `external` and `newTabText`; `useLink.ts`). The website passes both today (`detail-prose.tsx:120-121`). A converter that adopts the bare anchor must set `target` and `rel` itself and keep an equivalent notice; Prose does none of it. Contrast is unchanged and keeps the Link trade-off recorded in v0.1 §5 (neon link text 4.61:1 on `surface-0`, 4.30 to 3.42:1 on `surface-1…3`, with the underline as the non-colour cue). Screen-reader output and forced-colors rendering are Not evaluated.
