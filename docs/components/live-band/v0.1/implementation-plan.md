## 1. Independent owner gates

Plan approval, future edit authorization and the following gates are separate decisions; record each answer before affected work.

1. **Local responsive boundaries:** recommend LiveBand-only inclusive viewport `[@media(width<=860px)]:` for Field and `[@media(width<=1080px)]:` for Streams, with exact wide tracks in §3. No 560px breakpoint, theme breakpoint or other component's local authorization is imported. Prove emitted CSS and computed behavior at and around both boundaries, including fractional widths.
2. **VOD Material and composition:** recommend the existing-token recipe and explicit feasibility check in §3: a raised single-anchor Surface treatment, a 16:9 recessed cover, static decorative play and duration chip. This is a LiveBand-specific proposal, not approval to copy ArticleFeature or invent a Surface recipe. Cover, visible title, badge and duration are consumer-supplied children, not new own props or public parts. Prove they can achieve the recipe through the existing children-only API without inspecting or cloning descendants, overriding protected child styles, or creating a hidden component API. If not, stop for a separate contract decision; do not invent slots or weaken the 16:9/one-anchor promise. Confirm focus and actual contrast; no handwritten gradient/shadow, token or dependency changes.
3. **Registry naming:** recommend no new LiveBand convention or exception. `children`, `className`, native `href` and compatible native attributes are not new own concepts; do not add usages to `collection-items` or `slot-composition`. Existing child IDs are `deadline-instant` (`deadline`), `absolute-deadline-text` (`deadlineText`), `accessible-name` (`label`), `surface-material-tone` (`tone`) and `slot-composition` (`asChild` on Button/ListItem); they do not become LiveBand usages. `auto-dismiss-duration` is not media duration; `card-link-action-label` is not VOD metadata. Recheck meanings, aliases and status before implementation. Any newly discovered convention remains `proposed` with `approval: null`, pending separate semantic approval; never fabricate usage hashes or promote a convention.
4. **Legacy neutralization:** recommend the bounded inventory in §4, static local utilities and distinct internal markers, without changing legacy CSS or consumers. Approval is conditional on actual shipped cascade, emitted CSS and an unchanged legacy control. If a utility cannot win, stop for separately approved scope and a meaningful stylesheet role, never use blanket `!important`.
5. **Host sections and flood:** recommend the host place Field inside a named `<SectionShell register="flood">` using its normal content wrap once, and Streams in a separate appropriately named host SectionShell/register or equivalent section after it. LiveBand adds no section, flood paint, ambient wash, effects import or landmark. Host owns heading IDs, SectionShell padding/wrap, register, contrast and the `live` ambient profile. Verify actual SectionShell geometry and no double wrap; SectionShell DI1 is not presumed delivered. If its real API/layout cannot satisfy this composition, stop rather than paint flood in LiveBand.
6. **Visual adoption:** recommend adopting VIS-01/02 for the surviving intent only, with approved differences above and no parity claim; separately decide adoption and document limitations.

## 2. Contract, parts and future surfaces

One organism provides independently exported `LiveBandField`, `LiveBandStreams`, `LiveBandVod`, `LiveBandList` and `LiveBandRow`; no common React parent is required. Field is `div.eg-live-band`, contains consumer text/countdown/CTA then framed photo; Streams is a passive grid containing VOD then list, and can be omitted independently. No fetching, date parsing, scheduling, routing, playback, event/state machine, animation choreography or default copy. The host supplies the delivered Countdown with epoch-millisecond `deadline`, localized `deadlineText` with timezone, visible `label` and localized units. Countdown retains its initialization, running, expired and unavailable behavior and quiet named timer semantics. Use `<Button variant="dark" asChild><a href="…">…</a></Button>` and `<PhotoFrame variant="framed" ratio="landscape" …>`: token tilt stays static, without hover straightening; reduced motion removes transforms. Omit decorative pixels.

Vod is one native anchor with required non-empty consumer `href`, noninteractive consumer cover and metadata; visible title, badge, date and duration participate in its normal name, and play artwork is `aria-hidden`. It is not a player and exposes no root `asChild` or router adapter. Consumer supplies meaningful link name, valid href, alt and noninteractive descendants; do not claim React types enforce these. List accepts consumer heading, optional independent archive link, and zero or more rows; zero rows omit the `ul` without inventing a message, leaving heading/link. Each Row renders `li` around one consumer-supplied element composed exactly as `<li><ListItem variant="editorial-divided" asChild><a href="…">…<time dateTime="…">…</time>…</a></ListItem></li>`; no ListItemActions or nested links/buttons. Consumer owns keys, dates, readable duration, names and heading ranks.

Field/Streams require `children: ReactNode` and inherit compatible `ComponentPropsWithoutRef<'div'>`; Vod requires `children: ReactNode`, `href: string` and compatible anchor attributes. Omit conflicting children, unsafe HTML, `role`, `style` and interaction overrides that change passive/anchor semantics, enforcing protections at untyped boundaries too. List takes only required `children: ReactNode`; Row only required `children: ReactElement`. `className` is allowed only on Field/Streams, for outer margin, width and placement, not paint or arbitrary descendant overrides. No ref, part className on other parts, automatic link validation, descendant inspection or cloning. Empty detection handles normal null/false and empty arrays without inspecting element types; opaque components that render nothing cannot be detected reliably. `cn()` merges recognized layout utility conflicts, not universal cascade or appearance precedence.

After gates and separately authorized scope, six meaningful writer-owned files under `packages/ui/src/organisms/live-band/`: `types.ts` (public types, English JSDoc and static per-part CVA), `useLiveBand.ts` (meaningful class/empty handling and per-part `cn()`), `LiveBand.tsx` (JSX only), `LiveBand.test.tsx`, `LiveBand.stories.tsx`, and `index.ts` (named parts/types). No extra module. **No stylesheet**, conditional on emitted utility and cascade proof; any failure needs a separately approved meaningful role, not a dummy file. Parent owns shared exports/scans, metadata and package fixtures, registry and catalog integration. Inspect `packages/ui/src/styles/compiled.css` and `.storybook/preview.css` for required source scanning before future integration.

## 3. Proposed geometry, VOD recipe and exact utility inventory

Field wide tracks are `minmax(0,1.1fr) minmax(0,1fr)`, centered items and token `gap-10`; Streams wide tracks are `minmax(0,1.15fr) minmax(0,1fr)`, start-aligned with `gap-7`. At their respective inclusive boundaries each becomes one column, preserving supplied DOM order. Both grids use `min-w-0`; Field explicitly resets legacy root to `static`. Layout, gutters and section spacing remain host-owned, not a duplicate Field wrap. Long contents may grow; test narrow embedding even when the viewport is above the breakpoint.

For owner review, recommend composing the existing public `surfaceVariants` raised treatment onto Vod's native anchor, with zero unexpected inner padding only if the actual Surface API permits the approved card composition; preserve its token-backed elevated background, hairline/light edge and two-layer shadow. Use a 16:9 `aspect-video` cover reservation with `overflow-hidden`, `rounded-lg`, `bg-surface-0` and `shadow-well`; cover content fills its well. Cover contains a consumer-supplied decorative SVG play glyph in a noninteractive circular token-colored element (`bg-action-primary-solid-bg`, `text-action-primary-solid-fg`, `rounded-full`, `size-16`), and a consumer-supplied duration chip (`bg-surface-1`, `text-fg-default`, `rounded-sm`, `px-2`, `py-1`, `font-display`, `text-meta`); both sit within the cover, duration text remains exposed. The cover's title and badge are visible consumer content. Position with `relative`, `absolute`, `top-4`, `right-4`, `bottom-4`, `left-4` as appropriate; reserve room so title, duration and play never overlap or clip. Cover and metadata are children, so this is a documented consumer composition example, not a guaranteed internal layout generated by Vod. Existing-token `focus-visible:outline-none focus-visible:shadow-focus` provides visible focus; no scaling or transition is needed. No new gradients, halo or 560px rule. Confirm the proposed Surface/well nesting, sizing, contrast and child API before treating this as implementable; absence of a supported recipe or an overly long title that cannot remain readable stops for owner resolution, not hidden truncation. Do not apply Gauge's transparent-frame exception.

**Complete LiveBand-owned arbitrary/variant candidates requiring parent emission proof:**

- `grid-cols-[minmax(0,1.1fr)_minmax(0,1fr)]`
- `grid-cols-[minmax(0,1.15fr)_minmax(0,1fr)]`
- `[@media(width<=860px)]:grid-cols-1`
- `[@media(width<=1080px)]:grid-cols-1`
- `focus-visible:outline-none`
- `focus-visible:shadow-focus`

All are literal static strings; no interpolated classes. The consumer-example utilities above are ordinary static utilities, not extra variants. Audit final CVA, Surface composition and stories for every additional arbitrary or variant utility and add exact strings to this inventory for parent proof **before** approval; prove inherited child recipes independently in the production output. Check ordinary `aspect-video`, size, spacing, color, typography, shadow and placement utilities against existing tokens and no-preflight packaged CSS, including Surface's actual output. No `md:`, `max-[X]:`, arbitrary selector or new motion variant is proposed for LiveBand itself.

Parent's installed-compiler evidence in task L31–L32 and [approvals](../../web-catalog/v0.1/layer-d-plan-approvals.md): `md:` emits nothing; `max-[X]:` is exclusive, so inclusive boundaries require `[@media(width<=X)]:`; inclusive 860/1080 media variants, minmax grid templates and `[&>a]:` selectors emit. This does **not** prove the exact LiveBand decimal tracks, focus variants, production source scanning, declarations or cascade. Parent must prove every exact candidate above before approval, and repeat for any replacement. `[&>a]:` is not needed by this proposal.
