## 4. Findings

- **F1: TV-09 against the reported figures (the one reading that touches the plan's stop line).** The plan's stop line returns to the owner when the re-measure disagrees with the report by more than 0.5px or crosses its threshold at another viewport. At 1280px the spare is 51.28px against the reported 51.55px (0.27px) and at 1440px 6.78px short against 6.5px (0.28px); the threshold is the reported one. At 1920px the shortfall is 68.39px against "70px short", which is 1.61px away read literally. The report and the spec already round that figure (the spec's arithmetic cross-check gives about 584px, "about 68px over, which the report rounds to 70px"), and the plan itself writes "about 70px short at 1920px", so this run treated it as agreement with the spec's own cross-check, not as a stop. If the parent reads the 0.5px tolerance as binding at 1920px, these are the numbers to return to the owner. The verdicts (fits at 1280px, breaks at 1440px and 1920px, threshold about 1,421px) do not change either way.
- **F2: Hero overflows its column and overlaps the media instead of breaking the word (pre-existing v0.1 layout; the spec's block 4 last row says otherwise for Hero).** Block 4 states: "A word wider than the copy column at either recipe: Heading's `wrap-break-word` breaks inside the word, with no horizontal overflow". Measured, that holds for Closing, ChapterBreak and LabStage (the heading box equals the column and the word splits), and not for Hero: with `heroCopyVariants` (`min-w-0 flex flex-col items-start`) the heading wrapper is a flex item sized to fit its content, so its width becomes the widest word's natural width (`wrap-break-word` does not lower the minimum content size) and the heading overflows the 528.14px column. Rows: the reported word at `hero`/1440px, heading 573.31px against 528.14px, 45.17px beyond the column and overlapping the media track; `hero`/1920px, 619.38px; `show`/1920px, 583.94px (55.80px); the story's "extraordinary" at 1440px, 625.14px (`hero`) and 569.56px (`show`); at 320px in the padded canvas 289.44px and 270.12px against 262.41px. `show` at 1440px fits (+5.81px). The document never overflows horizontally (the word stays inside the viewport), so the symptom is overlap, not a scrollbar. **#560 neither causes nor fixes this**: it exists with the prop omitted, in the base. A fix (for example a `min-w-0 max-w-full` heading wrapper in Hero) is a v0.1 geometry change that needs its own approval; none was made and no spec was edited. It matters for TV-10 and for the owner's "the website shortens its copy" decision at Hero.
- **F3: the Controls options are listed `show`, `hero`, not in union order.** The plan (sections 6 and 9.4) expected "union order (`hero`, `show`)". The extraction returns `['show', 'hero']` in the docgen test, in the Controls pipeline and in the browser select: TypeScript orders a union's members by type identity, not by declaration, so declaring `'hero' | 'show'` as the spec fixes it does not decide it. The set is exactly `hero` and `show` (the plan's stop line asks for that), the Default column is `hero`, and nothing is injected, so no stop line holds. The pins compare sorted values, like the Collapsible precedent in the same file, instead of pinning an accident of the compiler. The only effect is that the default is listed second in the select.
- **F4: "the same line height".** The plan's computed-style row says the line height is the same at both recipes. The computed values are 81.239px and 89.1648px because the title token's line height is the unitless 0.86 (`--text-title-*--line-height`), so the ratio is equal (0.86 in all eight headings) and the pixel value follows the size. Read as the token, the row holds.

'show' : 'hero'` returned in an object property position widens to `string`, which `tsc` rejected at the Heading call (four TS2322 errors). The plan says its excerpt is indicative; the fix is the declared type `NonNullable<Props['titleVariant']>`, so the hook cannot drift from `types.ts`. One correction attempt.
