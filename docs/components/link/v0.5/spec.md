## 1. Purpose and scope

- **Need / non-goals:** egdev-website needs navigation links inside cards (the NowCard footer band, the CommunityCard action) and in the footer navigation that read as *quiet*: neutral text with a brand underline, as in the Pulso reference. Today every Link is link-coloured text (`--color-link-default`, which resolves to the neon `--color-fg-brand-raised`) with a text underline in that same colour (v0.4), set at the label-default step (11.2px/600). The reference's real NowCard footer link, as recorded in the v0.3 capture metadata (`../v0.3/capture.json`, VIS-05 `observedComputedStyle`), is white (`rgb(255, 255, 255)`), 15px/600, with a 1px `rgba(255, 0, 54, 0.45)` bottom border drawn as the underline. Two consequences shape this version. (1) The need is a second *look*, so the variant axis must carry it: `className` cannot, because it is outer margin/alignment only (`LinkProps` JSDoc). (2) Link v0.5 is sufficient for consumer-supplied links (cards) but **not** for the footer half of #562: `FooterNavigation` renders its own Link and has no way to choose a variant, so its adoption is a Footer change owned by the Footer amendment of this round (OQ-5). Non-goals: a new prop or axis (`size`, `tone`, `mode`); any change to the `plain` or `underlined` class sets, the arrow glyph or motion, the focus ring, the reduced-motion fallback, the hover rule, external-link safety or ref semantics; inline prose links and primary actions (Button), as before; a non-interactive link look (v0.3 Q3 stays declined); a visible current-page cue (Footer's own decision, Footer v0.3 OQ-1); a new token, dependency, Radix primitive or stylesheet; any edit to Footer, NowCard, CommunityCard, ProjectCard, Breadcrumb (#570, same round, may adopt `quiet` under its own spec) or their stories; any edit to the legacy `.eg-link` CSS; removing the deprecated `underlined` alias, which stays scheduled for a later major (v0.4 §8).
- **Cataloging decision / alternatives:** **Variant** of the existing atom (step 2 of [CATALOGACION.md](../../../CATALOGACION.md)), owner-approved on 2026-11-26 (L3): "#562: a Link `quiet` variant". Options that precede it and why each fails: *reuse* — v0.4 states `plain` "is the only treatment", and the issue is exactly the missing second look; *compose in the app* — a consumer would re-create ink and underline in private CSS and put appearance outside the contract, since `className` is not an appearance surface; *extract* — nothing is hidden inside another component; *new component* — the responsibility (navigate to a destination), semantics (a native anchor) and interaction pattern are identical, so a second component would split one concept (CATALOGACION: a variant stops being one only when it introduces another responsibility or interaction pattern, and `quiet` changes paint only). This also answers the question v0.4 §8 step 3 deferred to the next major: the `variant` axis **stays**, because it now carries a real second treatment. v0.3 Q4 had already anticipated this exact appearance promise ("switching that variant to `text-fg-default` with the brand underline would restore AA and match the web exactly"), as a separate decision; this version is that decision.
- **Evidence / level and package:** Atom in `@egdev/ui`, existing folder `packages/ui/src/atoms/link/`; no new level, package, Radix primitive or dependency. Availability comes from the React source and the barrel, not from CSS or stories; `linkVariants` and `useLink` stay internal. ## 2. Anatomy and composition

Unchanged: one root anchor with the same three supporting parts. `quiet` adds no part; ink and underline are root paint.

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| Root | Navigation target, public marker, label ink and underline paint | native `<a>`; `SlotPrimitive.Root` when `asChild` | Label, arrow and notice |
| Label | Accessible name and visible text | `children` inside `SlotPrimitive.Slottable` | Descriptive text; exactly one anchor element with `asChild` |
| Arrow | Decorative direction cue; follows the root ink because the Icon is `stroke-current` | `Icon` atom, `size='sm'`, `aria-hidden` | `arrow-right` only; omitted when `arrow` is false |
| New-tab notice | Screen-reader hint | `VisuallyHiddenPrimitive.Root` | `newTabText`, rendered only when `external` |

- **Radix / composition:** unchanged: `@radix-ui/react-slot` (`Slot`, `Slottable`) and `@radix-ui/react-visually-hidden`, both existing direct dependencies, plus the `Icon` atom. No new primitive, no `asChild` change, no plural anchors.
- **Public markers:** `eg-link` stays on the root in every variant. The variant is a static class set, not a marker or a data attribute; no part marker and no `data-testid` is added. The legacy `.eg-link` rule stays untouched and coexists (v0.4 §6).

## 3. Public API

- **Prop conventions:** [registry source](../../../../skills/_shared/prop-naming.json) (185 entries) and [generated view](../../../prop-naming.md), searched at drafting by meaning, name and aliases (variant, treatment, quiet, muted, subtle, neutral, ghost, plain, ink, colour/color, tone, emphasis, appearance, look, size, register). One own prop changes type (`variant`, a wider closed union); no prop is added, removed or renamed.

| Prop / event | Type | Required | Default or rule | Description |
| --- | --- | --- | --- | --- |
| `variant` | `LinkVariant` (`'plain' \| 'underlined' \| 'quiet'`) | No | `plain` | **Changed:** gains `quiet`, neutral-ink text with a brand underline for links inside cards and footer navigation. `plain` is the default look; `underlined` stays a deprecated alias of `plain`. A runtime value outside the union resolves to `plain`. Reuses `visual-treatment`. |
| `children` | `ReactNode` | Yes | None | Unchanged: descriptive label; exactly one anchor-compatible element with `asChild`. |
| `asChild` | `boolean` (discriminated union) | No | `false` | Unchanged: renders the single child through Radix Slot; the child owns `href`. Reuses `slot-composition`. |
| `href` | `string` | Yes unless `asChild`; `never` with it | None | Unchanged. |
| `external` | `boolean` | No | `false` | Unchanged: `target="_blank"`, merged `rel` with `noopener noreferrer`, hidden notice. Reuses `new-tab-navigation`. |
| `newTabText` | `string` | No | `(opens in a new tab)` | Unchanged: localized hidden notice. Reuses `new-tab-notice`. |
| `arrow` | `boolean` | No | `true` | Unchanged: shows or hides the trailing decorative arrow, independent of `variant`. Reuses `trailing-arrow`. |
| `className` | `string` | No | Absent | Unchanged: outer margin/alignment only, merged last by `cn()`. |
| Native attributes / ref | `a` props; `forwardRef<HTMLAnchorElement>` | No | Forwarded to the root | Unchanged; the actual ref target is the anchor in native and Slot modes. |

```ts
export type LinkVariant = 'plain' | 'underlined' | 'quiet';
```

Proposed JSDoc for the `variant` prop (English, replacing the sentence "plain is the only treatment"; `@control select` options keep the extracted order `plain`, `underlined`, `quiet`):

```ts
/**
 * Appearance axis. plain is the default treatment: link-coloured text with a text underline at rest that
 * is removed on hover, where the arrow still moves and the colour stays. quiet is for links inside cards
 * and footer navigation: neutral text with a brand-coloured underline at rest, removed on hover the same
 * way; not for inline prose. underlined is deprecated: it is an alias that renders exactly like plain, kept
 * so existing consumers do not break, and it will be removed in a later major. Omit the prop instead of
 * requesting underlined.
 * @control select
 * @default plain
 */
variant?: LinkVariant;
```

- **Prop conventions applied (exact IDs):** `visual-treatment` (`variant`; `approved`, scope `convention:visual-treatment`, approval reference `docs/decisions/prop-naming-atom-specs-approval.json`, content hash `sha256:bccb8984aaea33dc2e70aefee09daf2fb1c398da4c4f5536a6699afaf81e1565`), extended on its existing Link usage. Unchanged and still applied: `slot-composition` (`asChild`), `new-tab-navigation` (`external`), `new-tab-notice` (`newTabText`), `trailing-arrow` (`arrow`). **New conventions proposed: none. Exceptions: none.** Convention approval stays separate from this spec; this version asks for none.
- **Registry evidence to update at implementation (parent-owned; `--write` never refreshes evidence):** the Link usage of `visual-treatment` records `type: "LinkVariant ('plain' | 'underlined')"` (`prop-naming.json:1310`) and becomes `LinkVariant ('plain' | 'underlined' | 'quiet')`; the `revision` of all five Link usages (`packages/ui/src/atoms/link/types.ts`, `LinkProps`) goes stale when `types.ts` changes and needs an explicit re-review hash. Usage observations never change a convention hash.
- **Rejected registry alternatives:** `surface-material-tone` (`tone`) means a semantic status family or a Surface material tone, and `visual-treatment` itself lists "Surface material tone" under *avoid*; `quiet` is neither. `render-mode` (`mode`) routes visual presentation to `variant` in its own *avoid* field. `preset-dimensions` (`size`) would add a second axis that neither the approved shape nor OQ-1's resolution needs. `paused-presentation` (`paused`) is entity de-emphasis, unrelated. No entry names `quiet`, `muted`, `subtle` or `ghost` as a prop: those are values, and values and types are component-specific. **Value naming:** `quiet` follows the issue title and the approved cataloging. `muted` is rejected because it already means a lower-contrast ink in this system (`MeterRow` and `ProgressBar` use `muted: 'bg-fg-muted'`), while `quiet` keeps full-contrast ink; `ghost` names a no-chrome button treatment (IconButton, SocialLinks); `neutral` is a Button treatment.
- **Native props / refs:** unchanged inherited anchor props and `forwardRef<HTMLAnchorElement>`; the arrow and notice never receive consumer props.
- **Controlled / uncontrolled:** Not applicable: Link has no own state.
- **Compatibility (additive):** every existing call (omitted `variant`, `plain`, `underlined`) keeps its emitted class set, DOM and accessible name, and `underlined` remains a deprecated alias. Widening a union can break a consumer that switches exhaustively over `LinkVariant` or builds a `Record<LinkVariant, …>`; no such use exists in `packages/` (the exact type name appears there only inside the Link folder; elsewhere only `scripts/package-consumption.test.mjs`, `scripts/package-exports.test.mjs` and the registry with its generated view mention it), and the website's code is not visible here. No export, marker, token, dependency or legacy-CSS change. React 18/19 evidence comes from the packed consumers planned in AC-01 and AC-13, not from type-only claims.

## 4. Behavior

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| Default render, no `variant` | Unchanged v0.4 look: link-coloured label, text underline, label-default typography, right arrow | None |
| `variant="plain"` or `"underlined"` | Identical to the default (the same class set as v0.4) | None |
| `variant="quiet"`, rest | Neutral ink (`--color-fg-default`) and a text underline in the brand neon (`--color-fg-brand-default`), offset by `--space-1`; label-default typography unchanged; the arrow follows the ink | None |
| `quiet`, hover | The underline is removed; ink does not change; the arrow moves right by `--space-1` unless motion is reduced. The removal is an instant state change, not motion | None |
| `quiet`, focus-visible | The `--shadow-focus` ring and `rounded-sm` of the other variants; tab order unchanged | None |
| `quiet` with `arrow={false}` | No arrow; the underline removal is the only hover feedback (the footer-navigation case) | None |
| `quiet` with `external` | Same new-tab semantics, safe merged `rel` and hidden notice as every variant | `onClick` if supplied |
| `quiet` with `asChild` and a router anchor | Marker, ink, underline, arrow and notice land on the single child; the child owns `href` | Child and parent handlers |
| Runtime value outside the union (cast) | Resolves to `plain`: never a partial class set, so the retained legacy border cannot paint | None |
| Reduced motion | Unchanged: no translate, no transition | None |

- **States / representation:** no own `data-state`; `:hover`, `:focus-visible`, `aria-*` and `data-*` stay native. The variant is a static class set, never mirrored into a state attribute, and the underline stays `text-decoration`, never a border (v0.4).
- **Limits / consumer responsibilities:** `quiet` is for navigation clusters (a card's action, a list of footer links), not for inline prose, where an ink equal to the surrounding text leaves the underline as the only cue. The consumer chooses the variant; `FooterNavigation`'s own choice is the Footer contract (OQ-5). Target size stays consumer-owned, except Footer's approved local exception (`min-h-14 min-w-14`), which this version does not touch. Contrast over a translucent or particle backdrop is the host's responsibility and is not measured here (§5).

## 5. Accessibility

- **Accessible name / roles / relationships:** unchanged: role `link`, name from the label (plus the hidden `newTabText` when `external`); the arrow stays `aria-hidden` and unfocusable; `quiet` adds no text, landmark or relationship.
- **Keyboard / focus:** unchanged native Tab/Enter and `focus-visible:[box-shadow:var(--shadow-focus)]`; neutral ink does not alter the ring, tab order or hit area; no key handling is added.
- **Announcements / other conditions:** the new-tab notice remains the only announcement. **Non-colour cue (WCAG 2.2 SC 1.4.1):** with neutral ink, colour no longer distinguishes a quiet link at all, so the underline at rest is its only identifying cue; it therefore cannot be hover-only. The hover removal is a trade-off the owner accepted in OQ-3: while hovered, the pointer cursor, the arrow when shown and the keyboard focus ring remain as cues. **Contrast:** computed at drafting with the WCAG 2.x relative-luminance formula from the hex primitives in `theme.css` (the neon figures equal those documented in the `--color-fg-brand-default` comment; the `--color-fg-default` comment's 21:1 predates Grafito's grey canvas):

| Surface (token) | Quiet ink `--color-fg-default` `#FFFFFF` (text, SC 1.4.3) | Quiet underline `--color-fg-brand-default` `#FF0036` (SC 1.4.11) | `plain` neon text, for comparison |
| --- | --- | --- | --- |
| `--color-surface-0` `#141518` (canvas, NowCard footer band) | 18.26:1 | 4.61:1 | 4.61:1 |
| `--color-surface-1` `#1B1C20` (card body) | 17.02:1 | 4.30:1 | 4.30:1 |
| `--color-surface-2` `#232428` (card hover) | 15.50:1 | 3.92:1 | 3.92:1 |
| `--color-surface-3` `#2D2E33` (selected) | 13.55:1 | 3.42:1 | 3.42:1 |

  Reading: `quiet` meets 4.5:1 for its ink and 3:1 for its underline on every tonal surface, which removes for cards the small-text AA limitation that the owner accepted for neon `plain` text on surfaces 1-3 (`theme.css`, `--color-fg-brand-raised`). **Not established:** the footer sits on `--color-surface-0` at 50% over the particle layer (`docs/DECISIONES.md:92-93`), so ink and underline contrast there depends on what the particles paint; it needs a real-browser measurement, which stays pending and separately authorized (AC-10). Touch target size is unchanged and consumer-owned.

## 6. Appearance

| Variant axis | Allowed values | Default or rule | Combinations / restrictions |
| --- | --- | --- | --- |
| `variant` | `plain`, `underlined`, `quiet` | `plain` | Every value accepts every other prop. `underlined` renders exactly as `plain`. `quiet` changes ink and underline colour only: same size, weight, line height, offset, arrow and motion as `plain` (OQ-1) |
| Size / tone / mode | none | — | No new axis; one size and one label step for every variant |

- **Tokens / Material:** existing token-backed Tailwind utilities, declared with CVA in `types.ts` and composed through the hook's `cn()`; no hardcoded colour, spacing or font. **No Material recipe:** Link paints text and a text decoration only (no Surface, background, border, shadow or gradient). Proposed recipe, in the source's own terms:

  ```text
  base       eg-link group/link inline-flex items-center gap-2 font-sans text-label-default underline
             underline-offset-(--space-1) cursor-pointer transition-colors duration-(--duration-fast)
             ease-(--ease-out) hover:no-underline focus-visible:outline-none
             focus-visible:[box-shadow:var(--shadow-focus)] focus-visible:rounded-sm motion-reduce:transition-none
             (the v0.4 base minus text-link-default)
  plain / underlined   text-link-default pb-0 border-0         (the v0.4 set, unchanged as a set)
  quiet                text-fg-default decoration-fg-brand-default pb-0 border-0
  linkArrowVariants    unchanged, byte-identical
  ```

  The ink utility moves out of the shared base into the per-variant recipes so that **no branch emits two utilities of the same group**; this is by construction, not by trusting the `tailwind-merge` configuration (v0.3 recorded the same trap for `border-0` against `border-b`). The two recipes then differ in exactly `text-link-default` against `text-fg-default decoration-fg-brand-default`. `pb-0 border-0` is required for `quiet` as for `plain`: the retained legacy `.eg-link` rule would otherwise paint a second line (`padding-bottom:2px`, 1px `border-bottom`). Legacy `.eg-link` also sets `color:var(--color-fg-default)`, `text-decoration:none` and a hover colour of `--color-primitive-red-200` in `@layer components`; the utilities layer wins by layer order, so the unconditional `text-fg-default` also defeats the legacy hover colour (the same mechanism as v0.4 §6, to be observed in AC-11). `--color-link-hover` remains unreferenced by Link; no token is changed or removed.

  | Utility | Token | Role |
  | --- | --- | --- |
  | `text-fg-default` | `--color-fg-default` (`#FFFFFF`, `theme.css:73`) | Neutral ink; also the observed reference label colour |
  | `decoration-fg-brand-default` | `--color-fg-brand-default` (neon `#FF0036`, `theme.css:79`) | Brand underline; `docs/DECISIONES.md:86` keeps neon for "rellenos, anillos, subrayados y gráficas" on every surface (neon *text* stays limited to surface-0, which `quiet` never uses) |
  | `text-label-default` | `--text-label-default` (11.2px/1.2/600 = 14px ×0.8, `theme.css:254-258`) | Unchanged label step, shared by all variants |
  | `underline underline-offset-(--space-1) hover:no-underline` | `--space-1` | The v0.4 rule, unchanged |

  **Type step (OQ-1).** The reference link is 15px/600 before the global ×0.8 scale (#218), which is 12px after it; the neighbouring steps, `--text-label-default` (11.2px) and `--text-body-default` (12.8px/500/1.6), are both exactly 0.8px away, so no existing step is closer. This version therefore changes no size. The issue's "about 15px" most likely compares a post-scale 11.2px with a pre-scale 15px (an inference: the consumer's measurement method is not visible here).
- **Dynamic geometry:** Not applicable. No inline style, custom property or interpolated class string.
- **Class composition / consumer layout:** `className` still merges last on the root through `cn()` for outer margin and alignment; `eg-link` survives in every variant; no per-part override surface exists.
