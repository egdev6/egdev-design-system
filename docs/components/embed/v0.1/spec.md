## 1. Purpose and scope

- **Need / non-goals:** Event detail pages on egdev.es embed external content (X posts from `xEmbeds`, video). They need a frame that reserves its proportion before the content arrives, shows a loading or fallback state, has an accessible name and sits in the surrounding Material; `AspectRatio` alone paints nothing and names nothing (#574; the pages are not built, so there is no mitigation yet). `Embed` is that frame: a reserved box in a recessed Surface well that holds either a native `iframe` for URL-addressable content, always named by a required `label`, or consumer-supplied `children` for embeds that a third-party script fills, plus a consumer-supplied `fallback`. Three states are exposed through `data-state`: `loading`, `ready` and `fallback`.

  **Non-goals:** the component never loads or injects a script (X `widgets.js` and any provider SDK stay in the app); never reads or writes cookies, storage or consent state; never decides whether content may load (consent and policy stay in the app, and mounting a frame is what makes the browser request its `src`, so the app must not mount it before consent); no oEmbed or URL-to-embed-URL mapping and no provider detection; no failure detection, load timeout or automatic retry; no `postMessage` resizing or auto-height; no caption or credit line; no `srcDoc` or inline HTML; no lightbox or enlarged view (#575 is an app pattern); no variant, size or tone axis; no built-in or localized text; no ref and no `asChild`.
- **Cataloging decision / alternatives:** **new** atom, owner-approved (L3). The reuse → variant → compose → extract → new order was walked on inspected public code:

| Option | Inspected | Why it does not cover the need |
| --- | --- | --- |

No name, no state, no frame: it is the reservation Embed composes. |
| Variant of **PhotoFrame** | `packages/ui/src/atoms/photo-frame/{types.ts,usePhotoFrame.ts}` | A passive `figure` around an `img` (`src` and `alt` required, `fit`, `focalPoint`, caption) on a raised `surface-1`. An iframe changes the media element, the naming source (`title`, not `alt`), the loading model (a `load` event, no reliable `error`), the security attributes and the Material (well, not raised), so it would stop being a variant (`docs/CATALOGACION.md`: a variant must not take on another responsibility). |

- **Evidence / level and package:** Atom in `@egdev/ui`, proposed `packages/ui/src/atoms/embed/`. One concept: a named, reserved, stateful frame for external content. Against the atom disqualifiers (`docs/CATALOGACION.md:60-70`): no independent peer concepts (the Spinner and the fallback are states of the frame); no collection, navigation or shared coordination state (one local load state); no variants that change the interaction pattern. Two points were weighed and are resolved by OQ-1 (a): `children` and `fallback` fill the one content region as alternatives, never together and with no independent contracts (`docs/CATALOGACION.md:65`), as other atoms carry ReactNode slot props without being demoted (Gauge `center`, Badge and Button `icon`, Indicator `children`: `packages/ui/src/atoms/*/types.ts`); and `src` versus `children` are exclusive by type, like Surface's `asChild`, not two interaction patterns (`docs/CATALOGACION.md:52`). **Radix base: none of its own.** It reuses the AspectRatio primitive (`@radix-ui/react-aspect-ratio` 1.2.0, `packages/ui/package.json:30`) and Spinner; no interactive Radix primitive exists for a frame, and nothing is reimplemented. Verified availability: `packages/ui/src/index.ts` exports AspectRatio (`:201-202`), Surface and `surfaceVariants` (`:221-227`), Spinner (`:35`) and PhotoFrame (`:26`), and nothing named `Embed`.

## 2. Anatomy and composition

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| Root `eg-embed` | Material well and clip; carries `data-state`, `aria-busy` while loading and, only in the content branch and in the fallback state, `role="group"` named by `label` | `div` with the Surface `well` recipe through `surfaceVariants`; no Radix | the reserved box and nothing else |
| Reserved box | Reserves `ratio` and is the positioning context of the layers | existing `AspectRatio` (Radix AspectRatio, Radix-owned geometry) | the layers below |
| Loading layer | Decorative Spinner centered in the well; rendered only while `loading`, behind the frame | `span` around the existing `Spinner` without `label` | the Spinner only |
| Frame | The external document, named by `label` (frame branch) | native `iframe`, mounted after the first client render | none |
| Content | Consumer-supplied script-embed content (content branch) | none: `children` rendered directly in the box | consumer `ReactNode` |
| Fallback layer | Consumer-supplied alternative (fallback state) | `div` centered with the muted body recipe | consumer `ReactNode` |

- **Radix / composition:** no new Radix primitive and no new dependency. Composition: the existing `AspectRatio` primitive, the `surfaceVariants` recipe composed in the hook (not the Surface component, the PhotoFrame and AppIcon pattern) and the existing `Spinner` (decorative without `label`, "for hosts that own their busy state", `packages/ui/src/atoms/spinner/types.ts:11-17`). No `asChild`, no ref.
- **Public markers:** `eg-embed` is the stable public root marker. There are no part markers. `data-state` on the root is the documented own state, with the values `loading`, `ready` and `fallback`; it is styled through data variants where a visual difference exists, never mirrored into classes. The markers `eg-surface` and `eg-aspect-ratio` come from the composed pieces and are not Embed API. No `.eg-embed` rule exists in the legacy CSS or the generated catalog (`packages/*/src`, `docs/CATALOGO.md` and `scripts` searched).

## 4. Behavior

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| Frame branch, valid `label` and `src`, server render | Root `data-state="loading"` with `aria-busy="true"` and the decorative Spinner. The markup contains no `iframe` and not the `src`. The first client render is identical. | none |
| The same, after the first client render | One `iframe` is mounted with `title` equal to `label`, `src` as supplied and `loading="lazy"` unless overridden; the state stays `loading` | none |
| The frame's `load` event fires | `data-state="ready"`; `aria-busy` and the Spinner are removed; the frame stays | `onLoad(event)` |
| `src` changes to another valid value | A fresh frame mounts and the root returns to `loading` | `onLoad` again when it loads |
| `src` absent, blank, whitespace-only, or rejected by the scheme policy, with no renderable children | `data-state="fallback"`: no iframe is mounted (no request), `fallback` is rendered in the box and the root is a `group` named by `label`. A rejected value also emits `Embed ignored a src that is not an http(s) URL. The fallback state was rendered.` | none |
| A valid `src` later becomes blank | The iframe unmounts and the fallback state renders | none |
| Content branch, renderable `children` | Children render inside the box with `data-state="ready"`; no iframe, no Spinner, no `aria-busy`; the root is a `group` named by `label`. The component adds no script. | none |
| Content branch whose children become empty | The fallback state | none |
| `src` and `children` both passed (untyped) | Content branch; `src` is ignored. `Embed received both src and children. The src was ignored.` | none |
| Fallback state with no `fallback` | An empty reserved box is rendered. `Embed has no src, children or fallback. An empty reserved frame was rendered.` | none |
| `label` empty, whitespace-only or not a string | `Embed requires a non-empty label. Nothing was rendered.` and no output (never an unnamed frame); a later valid rerender renders normally | none |
| `ratio` invalid (0, negative, NaN, Infinity, not a number) | The default `16 / 9`, silently | none |
| Pointer or keyboard on the component | Nothing happens: no handler of its own reaches the DOM, and no tab stop is added. Input inside the frame belongs to the embedded document. | none |
| Content or fallback taller than the box | Clipped by the well; nothing scrolls | none |

- **States / representation:** only the root carries `data-state` and `aria-busy="true"` (while `loading`). Derivation: renderable `children` means the content branch (`ready`); otherwise the frame branch, where a non-blank accepted `src` is `loading` until its `load` event and anything else is `fallback`. Each development warning uses the same development-only guard as NowCard and StepMeter (`process.env.NODE_ENV !== 'production'`); the strings above are the exact messages. In the frame branch `ready` means only that the native `load` event fired. Iframes dispatch no `error` event for navigation failures, and browsers are expected to fire `load` for their own error documents (blocked, refused or unreachable frames); this is general platform behavior, not verified in this session, which is why `onError` is not exposed and `ready` is never a promise that content rendered. The iframe mounts after the first client render because an iframe rendered on the server starts its request before hydration (a privacy hazard for consent-gated embeds) and may finish loading before the handler is attached, which would leave the state stuck on `loading` (general platform and React behavior, not reproduced in this session).
- **Limits / consumer responsibilities:**
  - Consent, cookies and scripts: the app decides whether a frame or script may load, mounts `Embed` with a `src` or `children` only after that, and loads any provider script itself.
  - URL and frame hardening: the app owns the trust of the URL and chooses `sandbox`, `allow` and `referrerPolicy`; the component sets none.
  - No failure detection or timeout: to show the fallback after a failure the app drops `src` (or the children) itself.
  - Ratio and clipping: the app picks a `ratio` that fits the content. A fixed ratio clips taller output and leaves a blank well below shorter output; variable-height widgets such as X posts are OQ-2, resolved as (a): v0.1 ships the fixed ratio and a growth mode is added only on measured evidence.
  - Fallback copy: short, localized, with a link to the original where useful.
  - Scripts that rewrite the DOM inside `children` act outside React's control; the app isolates that subtree so React does not reconcile nodes the script replaced.
  - Third-party accessibility (captions, contrast, keyboard traps inside the frame) is not guaranteed by this component. The app announces any change it wants announced.

## 5. Accessibility

- **Accessible name / roles / relationships:** `label` is required. In the frame branch the iframe's `title` is the name once it mounts after hydration (the standard way to name a frame; cited from general knowledge as WCAG 4.1.2 and technique H64, not re-fetched); the pre-mount placeholder is a generic busy box. In the content branch and in the fallback state the root is `role="group"` with `aria-label={label}`, so the content or the fallback has a name. The role depends only on the branch and the state, never on mount timing, and an iframe and a group never carry the name at the same time, which avoids announcing it twice. The native `title` and every `aria-*` or `role` override are omitted from the public type and dropped at untyped runtime, so `label` is the only name source. Required consumer input: `label`, describing the content ("Keynote recording"), not "iframe" or "embed". No default label and no built-in text (a default would need a `messages` dictionary and a localization policy). The embedded document's own title ("X Post", a video title) is third-party and independent of `label`.
- **Keyboard / focus:** the component adds no tab stop, handler or focus management (`tabIndex` is protected). The only focusable part is the native iframe, whose content handles its own keys. Entry, navigation and exit follow the platform: Tab enters the frame and Tab or Shift+Tab leaves it. A third-party document that traps focus violates WCAG 2.1.2 and cannot be fixed by this component; the app vets providers.
- **Announcements / other conditions:**
  - Announcements: none. The Spinner is decorative (`aria-hidden`, no live region): a labelled Spinner is a polite status region, and the single announcement owner is the consumer, as for Notice. While loading the root exposes `aria-busy="true"` as a state hint only; assistive-technology behavior for it is Not evaluated.
  - Non-colour cues: loading is a glyph (shape and motion), not colour; the fallback is text.
