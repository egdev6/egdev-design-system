## Amendment 1 — F4: `box-border` on the fallback layer (2026-11-27)

The amended payload hash below is the current one. The SHA256 at the top of this record stays as the hash the original approval bound.

- **Date:** 2026-11-27
- **Reason (finding F4):** the real-browser check of the #574 implementation (ODD S4, task T6: a static Storybook build plus Chrome 148, computed-style and pixel measurements) found that the approved fallback layer recipe `grid size-full place-items-center p-6 …` is `content-box` wherever no preflight sets border-box sizing: this Storybook, a native-CSS consumer and the packed no-compiler path. `size-full` is 100% of the Radix inner box and the 19.2px padding of `p-6` is added on top, so the layer measured 650.77 × 382.84 in a 612.39 × 344.47 box (twice the padding larger), was clipped at the right and bottom edges by the well, and its content sat (19.19, 19.19)px off the box center. With `*, ::before, ::after { box-sizing: border-box }`, which is what a Tailwind preflight consumer such as the website gets, the same layer measured 612.39 × 344.47 and the offset was (0, 0). EM-11 promises a centered fallback, and plan G4 and section 14 say to stop when a computed style disagrees with block 6, so the implementation followed the approved recipe, stopped and offered three options: (A) add `box-border`, (B) drop `p-6`, (C) ship as is and document a preflight dependency. Measurements: [implementation-evidence.md](implementation-evidence.md), finding F4.
