## 1. Purpose and scope

- **Need:** in the tips rail (Carousel + TipCard) the current slide must read as the current one against its neighbours. The consumer reference gives it a brand border and a glow (`egdev-website`, `egdev-foundation/reference-web/pulso-source.html:264`, rule `.tip.on figure`). Carousel already marks the current slide semantically (`aria-current="true"`, `useCarousel.ts:529`) but paints nothing, and TipCard deliberately excludes the active glow ([TipCard v0.1](../../tip-card/v0.1/spec.md) non-goals). #557 asks for one opt-in Carousel treatment keyed off that existing attribute and painted on the slide wrapper. The issue says it replaces #393, which was not read for this draft.
- **Non-goals:** coverflow or 3D depth (rotation, `translateZ`, and the distance-driven opacity, brightness and scale of the reference's `--ad` / `--d`); any change to TipCard (no glow, no active prop, no reaction to its host); a multi-slide-per-view, peek or rail track layout (resolved by OQ-6 A: outside this amendment, a separate request only if needed); autoplay, looping or any change to hook behavior; hover zoom; legacy TipsSlider migration; new tokens, dependencies or exports; any change to the default appearance.
- **Cataloging decision / alternatives:** **variant** (approved, L3). Rejected, in [CATALOGACION](../../../CATALOGACION.md) order: *reuse unchanged* — Carousel has no emphasis, and `className` reaches only the root's width, margins and placement; *compose* — the frame and its glow room live in the internal slide wrappers and scroll track, which consumers cannot style, and an uncontrolled Carousel does not expose its current identity; *TipCard variant* — rejected by L3 and by TipCard v0.1, because a passive card must not react to its host; *extract* and *new* — nothing is hidden inside another component, and the TipsSlider recipe stays a composition because [`docs/CATALOGO.md`](../../../CATALOGO.md) (row TipsSlider, line 168) makes it an organism only if coverflow offsets are required, which stays excluded.
- **Evidence / level and package:** molecule in `@egdev/ui`, folder unchanged (`packages/ui/src/molecules/carousel/`). Availability is verified in the React package, not inferred from CSS, catalog or stories: `packages/ui/src/index.ts:49` re-exports `./molecules/carousel`, whose `index.ts` exports `Carousel` and the types `CarouselItem`, `CarouselMessages` and `CarouselProps`. The v0.1 decisions are cited from the repository's [v0.1 implementation record](../v0.1/implementation.md); the base contract comment on issue #80 was not re-read for this draft.

## 4. Behavior

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| `variant` omitted or `default` | Identical to v0.3 for both layouts. | None |
| `current-emphasis`, default layout, settled | The slide with `aria-current="true"` shows the brand border and glow; every other slide keeps its default paint. Nothing else changes, including no dimming, scaling or transform of neighbours. Server-rendered markup already carries `aria-current`, so the emphasis is present at first paint. | None |
| User moves with the controls, ArrowLeft, ArrowRight, Home or End (LTR or RTL) | The emphasis moves with the accepted identity: in the same commit when uncontrolled, once the owner accepts when controlled. | Existing single `onValueChange` request |
| Swipe, drag or native scroll in progress | The emphasis stays on the previously accepted slide while neighbours pass through the view. It moves when the settled scroll commits (`scrollend`, drag end or the 120 ms settlement). It does not follow the slide nearest the centre frame by frame, unlike the reference. | Existing single request per settled change |
| Controlled owner rejects a request | The emphasis stays on the accepted slide and the track realigns. | No extra request |
| Items reorder, are removed or reintroduced | The emphasis follows the existing identity rules (initial fallback, identity kept across reorder, fallback after removal). | None |
| Empty or invalid collection | No slides and no emphasis; no new warning or error. | None |
| Single item | That slide is current and therefore emphasized. | None |
| `current-emphasis` with `trackLayout='full-width'` | Resolves to `default`: no border, glow, padding or radius change. | None |
| Changing `variant` or `trackLayout` at runtime | Identity and focus are kept and no request is emitted; the existing resize handling realigns the accepted slide. | None |
| `prefers-reduced-motion: reduce` | The emphasis applies and moves with no transition. | None |
| `forced-colors: active` | The current slide keeps a non-shadow, non-colour-only cue (§5, §6). | None |

- **Current slide when several slides are visible:** today exactly one slide per view exists (V-4); two or more are visible only mid-motion. The definition does not depend on visibility: the current slide is the single slide whose identity equals the accepted identity and that carries `aria-current="true"`. It is the slide the counter, the progress bar, the status message and the keyboard act on. The emphasis is keyed only to that attribute, so it can never mark two slides or “all visible” ones, and visible neighbours are never emphasized. If a future track layout ever shows several slides at rest (none exists and none is proposed), the same definition applies; the nearest-to-centre slide is only a request that still needs acceptance.
- **States / representation:** no new own `data-state`, no mirrored class and no inline style. CVA selects static utilities and the emphasis is gated by `aria-[current=true]` variants. `aria-current` keeps its meaning and is not `aria-selected`.
- **Limits / consumer responsibilities:** the frame follows the slide box, not its content. For a frame that hugs a card, slide content must fill the slide: the consumer sets the Carousel root width (for example a poster-wide token-sized host, as the `FullWidthNarrow` story does) and keeps content corners at or below `--radius-xl`; narrower content is framed at slide width. Slides stay read-only, as in v0.1.

## 5. Accessibility

- **Accessible name / roles / relationships:** unchanged — root `group` named by its visible label, slide `group`s with the localized role description and `n of m: label` names, shared instructions description, `aria-current="true"` on the current slide only. No ARIA attribute, role or id is added, removed or changed by the variant.
- **The emphasis is decorative redundancy.** The current slide is also stated in its accessible name, in `aria-current`, in the visible counter (“02 / 05”) and in the progress bar. The DS rule “colour never alone” is met by text, so the emphasis is never the only carrier of the state.
- **Keyboard / focus:** unchanged (one tab stop on the current slide, Arrow, Home and End, Tab exits). The focus indicator must stay fully visible and win over the glow on the current slide (compound rule, §6) and must appear without delay, as it does today.
- **Non-colour and contrast:** `--color-border-brand` is documented as decorative (1.74:1 on the canvas, `theme.css:86`); the border does not by itself delimit a control and is not claimed to meet WCAG 1.4.11. The neon alternative considered in OQ-2 (option C, not selected) is documented (token comment “Como relleno, anillo o gráfica vale en cualquier superficie”, `theme.css:78`) as valid as a fill, ring or graphic on any surface.
- **Forced colours (to verify in a real browser; not verified here):** CSS Color Adjust removes `box-shadow` in forced-colors mode and replaces border colours with system colours, so a transparent border is expected to paint on every slide. The current slide therefore needs a cue that is neither a shadow nor colour alone: a system-colour outline (`Highlight`), following ColorSwatchGroup. No `forced-color-adjust: none` is applied to slides, because their content is consumer-owned.
- **Reduced motion / zoom / touch:** only a colour and shadow transition exists and reduced motion removes it; there is no transform, animation or layout change. Touch targets are unchanged (Not applicable: no new control).
- **Consumer obligations:** read-only slide content, image alternatives and not relying on the frame to convey state, as today.
