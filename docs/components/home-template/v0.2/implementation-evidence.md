## 4. Findings

- **F1 — an inline SVG fallback makes an `aspect-square` anchor taller than its slot (story fixture changed, contract unchanged).** The first run, with the story's existing `Fallback` (an inline `svg`), measured a 307.19 × 310.19 frame with an anchor equal to it: the box was 3 px taller than its width, though the anchor still equalled the frame. The 3 px disappeared once the fallback was block-level, which points at the inline element's line-box (baseline) gap raising the content-based minimum height of the aspect-ratio box; that cause is inferred from this before and after, not isolated further. `aspect-ratio` boxes do not shrink below their content, and the spec already makes the fallback's fit the consumer's duty (§4 limits). The new story therefore uses a local block-level `RatioFallback` for both sections instead of the plan's "existing `Fallback`", and its JSDoc says so; the frame is square at every width in section 3. Choices: (1) accept, recommended; (2) add one sentence to the effects README telling consumers to make the fallback block-level, which needs the plan's wording to be re-approved. No spec was changed.
- **F2 — the version override leaves a parent step and one blocked check.** The owner's L6 answer set `@egdev/cli` to 0.5.0, while the spec's HT2-08 and HT2-11 and the plan say 0.4.1 (left as written; no spec was changed). The writer wrote 0.5.0 in the changelogs, READMEs, catalog row and CLI documents and did not edit `packages/cli/package.json`. To fold: bump the manifest to 0.5.0 and change the two pins `packages/cli/tests/package.test.mjs:12` and `packages/cli/tests/args.test.mjs:133`. Until then `pnpm test:cli:consumer` exits 1 after 2.2 s with `release:pack failed: @egdev/cli: CHANGELOG.md top section is 0.5.0, expected 0.4.0` (`scripts/lib/pack-packages.mjs:123`), before any install, so the networked npm plus Vite and pnpm plus Next.js flow is **not evaluated**; a real `release:pack` fails the same way. Re-run both after the fold.
- **F3 — one test beyond the plan's list.** C1b (a missing, malformed, invalid, unreadable, untagged or other-package artifact keeps the base list for effects components) is required by the last clause of HT2-09 and was not in the plan's C1 to C3. It is in `ds046.test.mjs`, inside the allowed surface. The browser run also added two widths (320 and 280 px).
- **F4 — plan wording adjusted.** The README sentence follows plan section 6 with the owner's 0.5.0 and one clause naming the `@classNameAllows` tag; the catalog row follows plan section 5.4 with 0.5.0. The unchanged `ui`, `mcp` and `tokens` changelogs have no entry: no ui, mcp or token change exists, and `pnpm mcp:readme` reported the README digests already up to date because no README example shows the new field.
- **F5 — statuses left as in earlier lanes.** The plan header still reads "Proposed, never approved" and the spec header still says the plan awaits approval; the plan was approved by L6 and the parent folds statuses. The plan's canonical-issue and snapshot publication (D6) is a separate GitHub authorization and was not attempted.
- **F6 — scratch left in the shared tmpfs (no `rm` is permitted to the writer).** The scripts and outputs under `/tmp/ht2-scripts/` (including a 613 KB copy of the base artifact and one sanity screenshot) and the log files `/tmp/ht2-*.txt`.
