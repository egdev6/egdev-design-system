## 1. Purpose and scope

- **Need / non-goals:** Consumer request #566 (egdev-website, seen while adopting HomeTemplate in egdev6/egdev-website#47; consumer issue egdev6/egdev-website#45): the 3D isotipo anchor must fill the scene media slot it sits in (Hero, ChapterBreak, LabStage, Closing). Today the anchor is a block whose height comes from its fallback content. The consumer reports that the 638:612 fallback leaves it about 4% shorter than the square slot (consumer-reported, not measured here) and that `HomeTemplateAnchor` publishes no `classNameAllows`, so its documented `className` geometry cannot be used under the DS046 contract. The need is to publish, machine-readably, the CSS properties a class on `HomeTemplateAnchor` may set, so a consumer can size the measured box, and to make the consumer's `egdev-ds doctor` honor that published contract for `@egdev/effects` components (OQ-1 (b)). **Non-goals:** no new prop (no `fill`, `size` or `ratio`); no default sizing (the anchor stays a content-sized block, with no built-in `w-full`, `h-full` or aspect ratio); no change to the fallback wrapper, the director, measurement, engines, markers, tokens, dependencies or stylesheets; no change to the root `HomeTemplate` `className` contract; no `@egdev/cli` change other than the DS046 package-scope extension of delta item 3 (OQ-1 (b)); no new visual treatment.
- **Exact v0.2 delta:**
  1. The v0.1 §2 promise "no geometry props — the box is sized entirely by consumer layout utilities and the template only measures it" stays, and gains a machine-readable form: `HomeTemplateAnchorProps` publishes one `@classNameAllows` tag (§3).
  2. The v0.1 §6 class-composition bullet gains the anchor's supported surface: box geometry (§3 table) beside the shared base placement list, with the invariants `relative block` still winning.
  3. `@egdev/cli` 0.4.1: the DS046 guard also reads `classNameAllows` from `@egdev/effects` (OQ-1 (b)). DS047, DS048, DS040 and DS041 keep their `@egdev/ui` scope.
  4. Nothing else changes: A1–A3, the director, the engines, the fail-open rules, the public API, markers, tokens and the six-file layout all stay as approved.

| Axis | Published properties |
| --- | --- |
| Width | `width`, `min-width`, `max-width`, `inline-size`, `min-inline-size`, `max-inline-size` |
| Height | `height`, `min-height`, `max-height`, `block-size`, `min-block-size`, `max-block-size` |

These are literal lowercase CSS names beyond DS046's base list. Already allowed by the base list and therefore not tagged: custom properties, margins, self-alignment, flex item properties, `order`, grid item placement, and `min-width` / `min-height` at zero only (`component-contract.md:109`); tagging `min-width` and `min-height` additionally permits nonzero minimums. Not listed on purpose: `position`, `inset` and `z-index`, and `display` (the invariants own `relative block`); `padding`, `border`, `overflow` and `transform` (appearance, outside this need). No conditional or value-limited permission is flattened: any value of a listed property is allowed, and an unusable result (zero or non-finite area) fails open as in v0.1. All thirteen names exist in the installed `csstype` 3.2.3 typings that the generator validates against, and all match the CLI reader's `^[a-z][a-z0-9-]*$` pattern (`packages/cli/src/doctor.mjs:85`), which discards the whole map on any other name.

**CLI contract (OQ-1 (b); `@egdev/cli` 0.4.1).** The observable behavior of `egdev-ds doctor` DS046 after the change; how the code achieves it belongs to the implementation plan.

1. **Artifact reading.** `readClassNameAllows` keeps `classNameAllows` entries whose `package` is `@egdev/ui` or `@egdev/effects` (today only `@egdev/ui`, `doctor.mjs:90`). Validation stays all-or-nothing: a missing, unreadable or invalid artifact, or any component whose `classNameAllows` is not an array of lowercase CSS property names, leaves the base list for every component, silently.
2. **Import scope.** DS046 collects static `className` classes on named, aliased and namespace imports from `@egdev/ui` and `@egdev/effects` (today only `@egdev/ui`, `appearance-guard.mjs:524`); type-only imports are skipped as today. The collection rules, the rule matching (last compound, media and nested rules, outside `themeDirectory` and excluded paths), the message format, one finding per rule and the allowlist exceptions are unchanged. The `@egdev/effects` components are `AmbientBackground`, `HomeTemplate`, `HomeTemplateAnchor`, `Isotipo3D` and `ScrollReveal`.
3. **Package-matched allowances.** An entry extends the base list only for imports from its own package, resolved by the real exported name (aliases and namespace members resolve to it). An `@egdev/effects` entry never extends a component imported from `@egdev/ui`, and the reverse; the existing "wrong package" case (`ds046.test.mjs:776`) keeps its outcome and now pins that boundary.
4. **Outcome.** A class passed to `HomeTemplateAnchor` may set the base placement list plus the thirteen published properties, and any other property is a DS046 error. An effects component with no published allowance (the `HomeTemplate` root, `AmbientBackground`, `Isotipo3D`, `ScrollReveal`) uses the base list alone. A missing, invalid or untagged artifact keeps the base list for `HomeTemplateAnchor` too.
5. **Unchanged.** DS047, DS048, DS040 and DS041 ignore `@egdev/effects` imports as today; DS046 for `@egdev/ui` imports gives byte-identical results for any project without an `@egdev/effects` import; no flag, exit code, JSON or plan format, `init` or `upgrade` file effect or doctor code changes; the scaffolded agent rules already say "DS components" and are not rewritten. Tailwind utilities, inline styles and structural selectors stay outside DS046.
6. **Version.** `@egdev/cli` moves 0.4.0 → 0.4.1 by the owner's answer, with a `## 0.4.1` changelog section; no other package version moves (S2).

- **Native props / refs:** Unchanged: native `div` attributes are forwarded except `dangerouslySetInnerHTML`, `role` and `style`; no ref and no `asChild` (the hook strips both).
- **Controlled / uncontrolled:** Not applicable.
- **Compatibility:** In the component packages, documentation and published metadata only: no runtime, export, marker, prop, default or component behavior changes, and React 18 and 19 behavior is not touched. The `@egdev/system` artifact gains `components[HomeTemplateAnchor].classNameAllows`, an additive field (`schemaVersion` stays `1.0.0`, `docs/distribution/design-system-artifact.md`). ## 4. Behavior

- **States / representation:** Unchanged. `data-state="painted"` lives on the internal fallback wrapper and drives `data-[state=painted]:opacity-0` through a data variant; no state is mirrored into classes and no new `data-*` attribute is added.
- **Limits / consumer responsibilities:** The template never clamps, validates or caps the consumer's sizing. Percentage heights (`h-full`, `size-full`) need a containing block with a definite height; `aspect-square w-full` does not. The consumer owns the slot, its overflow, and the sizing of its own fallback element: the fallback wrapper is auto-height (`types.ts:65`), so a `h-full` on the consumer's fallback child cannot fill a sized anchor (`aspect-square w-full` on that child can). The fallback matters only before the first eligible 3D paint and without WebGL. The consumer keeps the fallback within the box.

## 5. Accessibility

- **Accessible name / roles / relationships:** Not applicable as a control; unchanged. The anchor is a plain `div` with no role (`role` is stripped) and no name; its fallback is decorative; geometry classes cannot change semantics.
- **Keyboard / focus:** None added. The anchor is not focusable, and sizing introduces no focus hazard because the layers stay `aria-hidden` and `pointer-events: none` (v0.1 §5).
- **Announcements / other conditions:** None. Consumers prefer relative sizing so the box follows zoom and reflow (fixed pixel boxes can clip at high zoom). No touch target or colour-only cue is introduced. The component guarantees passive, hidden effect layers; the consumer guarantees the slot and the fallback.
