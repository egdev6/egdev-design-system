## 1. Purpose and scope

- **Need / non-goals:** A page-level template that stacks the effect layers under web content and owns the scroll choreography between them: an ambient particle layer and one viewport-fixed masked 3D isotipo layer, whose **director targets** (layer presences, profile multipliers, pose and anchor-box targets) are continuous functions of scroll position across consumer-registered zones. The template owns: zone registration and ordering, the band/read-point math, the non-overlapping layer handoff, ambient profile transitions, per-zone isotipo scenes with anchor travel, pause-at-zero, resize/measure discipline and reduced-motion behavior. **Non-goals:** grain (explicitly excluded by prior decision; not reopened); per-zone isotipo instances or discrete profile snapping (rejected by the L65 continuity choice); any `window.PULSO`-like global, `html`/`body` attribute contract or automatic global-DOM state (the director is React-internal); TopBar/MobileMenu/SectionNav/CommandPalette/Footer composition (delivered organisms composed by the consumer); SectionShell responsibilities (per-zone layout/registers); ScrollReveal scanning or imperative reveal clones (ScrollReveal is delivered and remains declarative consumer use); time-based **choreography** (director targets are scroll-derived; if scrolling stops mid-band the targets stay mid-band — this does not freeze the engines' own intrinsic animation, see §4); Pulso domain content, zone ids, copy, links or counts (the zone table is a generic consumer input); blog/product pages without choreography (SectionShell territory).
- **Cataloging decision / alternatives:** **New** template in `@egdev/effects`, decided by the owner (L1/L5; catalog row "effect layers plus zone choreography in @egdev/effects; the zone table becomes an input, not hardcoded Pulso values"). Reuse: no delivered component renders layers or choreography (`packages/effects/src/index.ts:1-6`); `AmbientBackground` and `Isotipo3D` explicitly exclude the director (`docs/CATALOGACION.md` "Web consumer amendment" rule 4 — the exclusion stays valid and each keeps an appended note). Variant: neither effect component has a page-choreography responsibility to extend. Compose: continuous band interpolation and one traveling 3D layer cannot be achieved by composing discrete-profile components — that is exactly the substitution the L65 choice rejects. Extract: the choreography lives in the web app's page scripts (`pulso-director.js`, `pulso-iso3d.mjs`), not inside any system component. Package `@egdev/effects` (not `@egdev/ui`) per the approved catalog row; `@egdev/ui` never imports effects.
- **Evidence / level and package:** Template level (page frame + choreography), matching the Foundation HomeTemplate folder and the catalog row (`scripts/catalog_data.py:121`, `docs/CATALOGO.md:180`). Internal-engine reuse is the core implementation strategy, with the port's actual limits verified rather than assumed: the private particle engine already exposes exactly the numeric surface the director needs (`packages/effects/src/ambient-background/particleStreaks.ts` — `Profile = { lineCount, squareCount, speedMultiplier, backgroundGlowOpacity }`, `set(next: Profile)` at :331, `start()` :350, `stop()`, `renderOnce()` :370), while the 3D scene engine exposes a pose override (`packages/effects/src/atoms/isotipo3d/isotipoScene.ts:2` — `IsotipoPose = { az, el, fov, ex, halo }`; `render(..., animation.pose)` :300-320) but contains **no** viewport anchor projection, lens shift or masking (searched: no mask/scissor/shift/anchor code), so anchor travel requires additive internal adaptation, not "as-is" reuse (§2, §6, OD-2). Neither public effect component exposes any of this, and no public extension is proposed. No new `@egdev/ui` prerequisite is assumed; scenes and organisms consumed inside the template are the consumer's composition of already-delivered public API. **The component name `HomeTemplate` follows the approved catalog row and the Foundation folder name** (not a new proposal).

## 2. Anatomy and composition

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| Root | Renders the stacked fixed layers, the content wrapper, and owns the director | `div` host carrying the stable public root `eg-home-template` | Layer parts + `children` |
| Ambient layer (internal) | Template-owned ambient canvas and controller: instantiates the same private particle engine the delivered `AmbientBackground` uses (`createParticleStreaks`, package-internal, not exported) with the same token-backed color derivation, and drives it with numeric `set(Profile)` interpolation | `canvas`, `aria-hidden`, `pointer-events: none` | — |
| Isotipo layer (internal) | One viewport-fixed 3D canvas for the whole page, driven through the internal scene engine plus the additive travel adaptation (OD-2), visually confined to the active anchor box | `canvas`, `aria-hidden`, `pointer-events: none` | — |
| Vignette layer (internal) | Static token-backed edge-darkening paint above the ambient canvas, below the 3D layer and content (source layer order) | `div`, `aria-hidden`, `pointer-events: none` | — |
| `HomeTemplateAnchor` (public part) | Consumer-rendered measured box inside a 3D scene; registers its DOM node with the director and hosts consumer fallback content | `div`, no Radix primitive (no interaction semantics) | Consumer fallback content (e.g. a decorative SVG), visible until the 3D layer first paints |
| Content | Consumer page content | `div` wrapper (`overflow-x` clipping as the source frame does) | Sections; each zone's section carries `data-zone="<zone.id>"` (native attribute; SectionShell passes it through) |

- **Ambient adapter (why not the public component):** the public `AmbientBackground` API is discrete (`profile: 'base'|'read'|'live'`, one static `opacity` prop) and cannot express continuous band interpolation; driving its discrete props every frame is neither its contract nor performant. The template therefore owns its ambient canvas and controller and reuses the **same-package private engine** (`particleStreaks.ts`) whose `Profile`/`set()` surface is exactly the four interpolated values of the source director (`pulso-director.js` `applyProfile()`), reusing the approved `effect-profile` values and the delivered color treatment. No engine extension is needed; no public `AmbientBackground` prop, marker or default changes, and existing standalone callers keep their exact behavior (the plan adds regression/differential checks on the shared engine, per the shared-contract mutation discipline).
- **Isotipo adapter (honest boundary):** the pose override alone does **not** establish anchor travel: `IsotipoPose` carries no anchor box, and the scene engine has no viewport-anchor fit, lens shift or mask. The proposal is a minimal **additive internal extension** of the scene pipeline (a named, non-exported optional projection input consumed only by the template's travel path) plus a new internal `homeTravel.ts` that computes interpolated poses (source `poseOf`/`mix`) and the anchor-box fit (source lens-shift/projection and mask math, `pulso-iso3d.mjs`). Defaults are unchanged for every existing caller; the plan must include differential/regression evidence for the extended engine. Copying the whole `pulso-iso3d` engine as a parallel implementation is rejected.
- **`HomeTemplateAnchor` contract (OD-1):** props: `zone: string` (required; must equal a configured zone id whose `scene` is set); optional `children` (consumer fallback content); native attributes forwarded except unsafe HTML, `role` and `style`; no ref is promised; no geometry props — the box is sized entirely by consumer layout utilities and the template only measures it. Registration is via React context from the template root: the node registers on mount, unregisters on unmount, and is measured by the director while its zone is active (the source reads anchor rects per frame). There is **no id-based geometry or style contract**; ids stay consumer-owned accessibility anchors. Its fallback content is the consumer's decorative, non-interactive responsibility (§3). Duplicate anchors for one zone: the first registered wins, development warning; an anchor naming a non-3D zone is ignored with a warning; a zero-area or unmeasurable anchor is treated as absent (that zone's isotipo is suppressed and the consumer fallback stays visible).
- **Radix / composition:** No Radix behavior primitive is required: the template adds no keyboard, focus or ARIA interaction of its own; choreography is platform scroll/resize observation. Composition reuses delivered public API: `ScrollReveal` remains available to consumers inside sections, declaratively. The 3D layer intentionally does **not** instantiate per-zone public `Isotipo3D` components (OD-2 boundary): the L65 choice requires one isotipo traveling between anchors, which only a single masked canvas can express.
- **Zone order authority (OD-1):** the `zoneTable` prop order is authoritative for choreography sequencing; document order of `data-zone` sections is used only for measurement and band geometry. Sections whose `data-zone` matches no `zoneTable` entry are foreign and ignored (development warning); a `zoneTable` entry with no matching section contributes nothing to the resolved choreography (development warning). If the resolved entries' document order disagrees with the `zoneTable` order, the template does **not** silently reorder against the authoritative input: choreography stays fail-open inert (layers rendered but static/inert, all content visible) with a development warning until the geometry and configuration resolve consistently. No Pulso zone ids are shipped or defaulted.
- **Public markers (proposed, unapproved):** `eg-home-template` root; proposed part marker `eg-home-template-anchor` on the anchor part (a presence marker for tests/consumers, not a styling-selector API). State is carried as `data-state` on the root (active zone id, plus `data-motion="reduced"` when reduced motion applies); layers are `aria-hidden`.

## 3. Public API

- **Prop conventions (registry lookup):** Searched `skills/_shared/prop-naming.json` (155 entries) and `docs/prop-naming.md` by meaning and name, with exact evidence. **By name:** `zones` is globally taken — approved entry `guide-zones` has canonical name `zones` ("Ordered, labelled, non-interactive guide rectangles drawn over a preview canvas…", PreviewFrame), and canonical names are globally unique, so the zone table proposes the unused canonical name **`zoneTable`**: not present in any registry `id` or `name` (searched; 0 hits in `skills/_shared/prop-naming.json` and `docs/prop-naming.md` for `zoneTable`/`zone-table`). **By meaning:** no existing entry covers an ordered scroll-choreography zone table for a page template (`guide-zones` is explicitly preview rectangles and its `avoid` notes navigation entries; `active-section-id` names a host-designated current-section identity input, not a table input). Proposed semantic ID: **`choreography-zone-table` / `zoneTable`** (unapproved). **Reused conventions:** `effect-profile` / `profile` (approved) for the per-zone ambient profile values, and `effect-scene` / `scene` (approved, name `scene`) for the per-zone isotipo scene values. Considered and not applied: `layer-opacity` / `opacity` (approved) — layer presence is owned by the zone table, and a second opacity knob would duplicate the concept. **New event proposal:** `zone-change` / `onZoneChange` (searched: `zone-change` and `onZoneChange` appear in no registry id or name), following the established `on…Change` event family; it notifies **active-zone changes** (see API table), not per-frame mix state. Field names inside the table type (`id`, `isotipo`, `ambient`, `mobileIsotipo`) are also unused registry names (searched; recorded with the convention proposal). Component usage `source: {path, symbol, revision}` records belong to the plan phase once a real reviewed `HomeTemplateProps` source exists, per the shared contract.

## 4. Behavior

All mechanics below are proposed ports of the source director (`pulso-director.js`), restated as promises; the source's own values are cited as evidence, not as new knobs. **Time semantics:** only director **targets** (layer presences, profile multipliers, pose and anchor-box targets) are scroll-derived, with one rAF-coalesced recalculation per scroll frame and no temporal smoothing of those targets. The engines' own intrinsic animation continues while their layer is active and visible: ambient particles keep drifting at the interpolated counts, the isotipo keeps its idle motion and intro/settling ramps, exactly as the delivered engines already behave. Only reduced motion renders static effect frames.

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| Mount; measure after load, `document.fonts.ready` and body `ResizeObserver`; resize re-measures with a 150 ms debounce (source `measure()`/listeners) | Zone elements resolved from the content wrapper by `data-zone`, ordered by the `zoneTable` (§2 authority rules); band table computed; first state applied without transition | `onZoneChange` once with the computed initial zone |
| Scroll (targets only) | Reading point `R = scrollY + readPoint × viewport` (source read point 0.5); continuous position `u` = zone index + fraction; pure zone values outside bands, interpolation with `t` inside bands | `onZoneChange` when the active zone id changes |
| Band between zones A and B | Band occupies the last 35 % of A plus the first 15 % of B, scaled proportionally to a 0.75-viewport minimum; first band never starts before 0.5 viewport; last band ends before the end of scroll; a band never starts before the previous ends (source band rules; constants fixed per OD-1) | none |
| Layer handoff where the dominant layer changes (3D ↔ ambient) | **Non-overlapping crossing:** the outgoing layer fades 1→0 in the first half of the band (`a × max(0, 1 − 2t)`), the incoming rises 0→1 in the second (`b × max(0, 2t − 1)`); a safety gate zeroes the layer that does not own the half; values below 0.002 count as 0. Same-layer transitions interpolate linearly (source `seg()`) | none |
| Layer target at 0 | That layer's loop stops (ambient `stop()`; 3D render paused); it resumes when the target returns above 0 (source pause-at-zero and `wake()`); both stop while the tab is hidden | none |
| Ambient interpolation inside a band | The four `Profile` values interpolate between the profiles of A and B; counts rounded; the engine is patched via `set()` only when values change (source `applyProfile()`; private-engine reuse, no public change) | none |
| Isotipo inside/between 3D zones | One isotipo: per-zone scene progress drives the zone's pose (source formulas: hero `scrollY/height`; chapter `(scrollY + vh − top)/(height + vh)`; lab sticky `(scrollY − top)/(height − vh)` or non-sticky variant; outro `(scrollY + vh − top)/height`); between zones the pose (angles, fov, explosion, halo) and the anchor box interpolate with the same band `t`, so the logo travels between anchor boxes instead of jumping; the canvas is visually confined to the active anchor box so the 3D never passes behind text (source `poseOf`/`mix`/`setMask`; OD-3 mechanism) | none |
| Viewport ≤ 760 px | Zones with `mobileIsotipo: false` lose the 3D layer and gain full ambient; the traveling canvas skips them (source: chapter keeps its SVG; VIS-09). Below 700 px ambient counts scale to 60 % (source factor; fixed, no prop) | none |
| `prefers-reduced-motion: reduce` | Nearest-zone targets (t snapped to 0/1), no interpolation; ambient painted via `renderOnce()` only on change; 3D rendered as one static frame per change; engines produce no further frames (source RM rules; VIS-10) | none |
| Invalid or incomplete input (all development warnings, never throws, no new error props) | Empty/no-valid `zoneTable`: children render with inert layers, no choreography. `ambient` validation: `NaN` → `0`, `+Infinity` → `1`, `−Infinity` → `0`, finite values outside [0, 1] clamped. Contradictory ownership: an `isotipo: true` zone with an explicit positive `ambient` resolves to `ambient 0` (3D ownership wins) with a warning; `isotipo: true` with a missing or invalid `scene` becomes an ambient-only zone with `ambient 1` and a warning. Both layers at `0` is a valid, stable configuration for a deliberately effectless zone. Duplicate `zoneTable` ids: first entry wins. Foreign `data-zone` sections and zone ids without sections: ignored. Duplicate anchors per zone: first registered wins. Anchor for a non-3D zone: ignored. Zero-area anchor: that zone's isotipo suppressed, consumer fallback stays visible. ZoneTable/document-order mismatch: fail-open inert choreography with a warning (§2) | `onZoneChange` reflects the resolved zones |
| SSR / no JavaScript / `IntersectionObserver`-independent failures / missing `ResizeObserver` | Content fully visible; layers inert or static from the initial measurement; nothing hidden, nothing thrown; the template fails open | none |
| WebGL unavailable or 3D context lost | Isotipo layer never shown (or hidden on loss); anchor fallbacks remain visible (source `gl-off` behavior) | none |
| Unmount | All observers, listeners, rAF loops and the 3D context are disposed; nothing global remains | none |

- **States / representation:** The director state (active zone, mix, layer presences) lives in React-internal refs/state; the root exposes only the active zone id and reduced-motion flag via `data-state`, plus `onZoneChange` — never a global object, `window` key, or `html`/`body` attributes. The internal engines keep their existing contracts; the template adds no public capability to them.
- **Limits / consumer responsibilities:** Consumers own landmarks, headings, `aria-labelledby`, anchor navigation targets and `scroll-padding-top`; the template adds none. Consumers own SectionNav/TopBar composition and wire `onZoneChange` to it. The template never hides content: layers are decorative, `aria-hidden`, `pointer-events: none`, and content stacking order keeps text above effects. Scenes with a 3D anchor must render a `HomeTemplateAnchor` and keep fallback content visible until the 3D layer has painted its first frame (source `gl-on`/fallback behavior), so no-JS and no-WebGL degrade to the fallbacks.

## 5. Accessibility

- **Accessible name / roles / relationships:** Not applicable as a control — the template is a passive page frame. It adds no role and no name. All effect layers are `aria-hidden="true"` and `pointer-events: none` (source behavior). Landmarks (`header`, `nav`, `main`, `footer`) belong to the consumer's content; the content wrapper adds none of its own beyond `div`s.
- **Keyboard / focus:** No keyboard interaction of its own and none added. Content is never visually hidden by the choreography (layers live behind content), so no invisible-focus hazard exists; the template introduces no focus management, traps or restoration.
- **Announcements / other conditions:** Zone changes are not announced (decorative context, not state); consumers may surface active-section information through their own navigation (SectionNav already carries the accessible pattern). Reduced-motion support is a hard guarantee (behavior table). No color-only state is introduced by the template. Touch targets: none added. Component vs consumer guarantees are stated in §4 limits.

## 6. Appearance

| Variant axis | Allowed values | Default or rule | Combinations / restrictions |
| --- | --- | --- | --- |
| Ambient profile (per zone) | `base \| read \| live` | `zoneTable` entry | Reuses `effect-profile` values; interpolated continuously between zones (L65 choice) |
| Layer ownership (per zone) | `isotipo` × `ambient` presence | `zoneTable` entry | Non-overlapping handoff enforced by the director; both layers at `0` is a valid stable state for an effectless zone |
| Motion | normal \| reduced | automatic from `prefers-reduced-motion` | Reduced motion renders static effect frames; no choreography interpolation (VIS-10) |

- **Tokens / Material:** All static appearance is token-backed Tailwind utilities declared with CVA in `types.ts` and composed with `cn()`. Layer stacking uses the source frame's order as a proposal: ambient + vignette (z 0), 3D canvas (z 1), content (z 2), navigation above content — with no handwritten colors, gradients or shadows in component code.
- **Vignette (direction chosen S7/L67, recipe and token unapproved):** the owner retained the source edge-darkening direction (verbatim: "Conservarla: proponer receta compatible (Recomendado)"); omission is no longer an alternative, and this draft authorizes no token/component implementation. Original rule, read from the read-only source (identical bytes in the hash-verified harness copy), `pulso-source.html:38`: `.vignette{position:fixed;inset:0;z-index:0;pointer-events:none;background:radial-gradient(ellipse 120% 90% at 50% 45%,transparent 35%,rgba(0,0,0,.55) 75%,rgba(0,0,0,.92) 100%)}`. **Existing-token lookup conclusion:** no current token supports this effect — the gradient tokens have different shapes, colors or roles (`--gradient-section-show` `theme.css:506` red-tinted scene wash; `--gradient-sheen` :511 and `--gradient-glass-card` :513 white sheens; `--gradient-btn-primary*` :514-517 button fills), `--mask-section-fade-*` (:507-509) are masks, and the alpha blacks (`--color-alpha-black-25`/`-42` :57-59) do not match the `.55`/`.92` stops. **Proposed one new token, exact declaration, awaiting independent token authorization (nothing added to `theme.css`):**

  ```css
  --gradient-vignette: radial-gradient(ellipse 120% 90% at 50% 45%, transparent 35%, rgba(0, 0, 0, 0.55) 75%, rgba(0, 0, 0, 0.92) 100%);
  ```

  Rationale: the exact source stops preserve the original look; literal rgba stops follow the existing token convention (`--gradient-sheen`, `--gradient-hot`), avoiding additional alpha tokens. **Proposed static CVA delivery (types.ts, no component stylesheet, no inline paint):** `vignetteVariants = cva('fixed inset-0 z-0 pointer-events-none bg-[image:var(--gradient-vignette)]')`, rendered after the ambient canvas with `aria-hidden="true"` (the static utility follows Tailwind's typed image-variable syntax; exact candidate emission and own-element delivery must be probed before plan approval and pinned in package checks). **Source-vs-token differences, documented honestly:** the gradient has the same numeric stops and geometry as the source literal, with normalized whitespace and leading zeros rather than byte-identical spelling; delivery sets `background-image` via the utility instead of the `background` shorthand, leaving the element's default transparent `background-color`, so the composite is intended to match — asserted, not a pixel-parity claim. The token would participate in theming like every gradient token (the system currently ships one dark theme; the source defines no alternative), and reduced motion changes nothing (static paint).
- **Grain stays excluded** (prior decision, not reopened).
- **Dynamic geometry (OD-3, explicit owner gate — not analogical Gauge/PreviewFrame authorization):** the traveling 3D layer needs exactly two dynamic visual values: layer opacity and anchor confinement. **Technical proposal (unapproved): renderer-side confinement.** No CSS `mask-image`, no gradient strings, no arbitrary inline styles, and **no stylesheet** for this route. The scene pipeline is reused/extended with an optional internal projection/confinement input: validated anchor geometry (rect, feather, viewport bounds) is passed to the renderer as geometry, not style, and the confinement (including feathered edges and offscreen anchors) is computed inside the render — proposed new internal implementation work, not a proven current engine capability (`isotipoScene.ts` has no such code today). Rules: anchor coordinates may be signed/offscreen — the logo is never moved by clamping rect origins to 0; only the visible output intersecting the viewport is rendered. The only inline style values permitted are **bounded numeric opacity custom properties on the two fixed canvases** (finite, clamped to [0, 1]; non-finite → 0), consumed by static CVA utilities (`opacity-[var(--…)]`), mirroring the established numeric-custom-property pattern; this per-component transparent compositor-frame recipe — two fixed full-viewport transparent canvases, opacity via those bounded custom properties, all other appearance token-backed static utilities, no other inline values — is the exact approval being requested, not an inferred Gauge/PreviewFrame precedent. Existing callers of the extended engine are unchanged; if the owner rejects the required travel adaptation, this spec returns for redesign — anchor travel is not optional (S6).
- **Class composition / consumer layout:** Root `className` merges with `cn()` (outer placement only, not an appearance override); merge precedence per part is documented and tested (AC-15). The content wrapper is a plain block; consumers control inner layout with SectionShell.
- **Files / pending proposals:** The six mandatory files in `packages/effects/src/home-template/`: `types.ts` (CVA + public types incl. `HomeTemplateZone`), `useHomeTemplate.ts` (director wiring, context, refs, observers, `componentVariants` call), `HomeTemplate.tsx` (JSX only), `HomeTemplate.test.tsx`, `HomeTemplate.stories.tsx`, `index.ts` (named exports `HomeTemplate`, `HomeTemplateAnchor` and types).
