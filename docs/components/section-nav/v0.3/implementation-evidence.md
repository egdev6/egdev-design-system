## 4. Findings

- **F1 — resolved before code (the plan's F1).** `fg-brand-raised` is the neon `#FF0036`, not `#FF6680`; Amendment 1 restated block 5's contrast sentences and PAR-07 with 3.92:1 and 3.42:1 and kept the token. The browser confirms 3.92:1 from pixels on the solid fallback.
- **F2 — the browser's accessible name carries the rendered case (owner decision: accepted).** In Chromium's AX tree the name of an index link is `01 SECTION 1`, while the DOM text and the jsdom name are `01 Section 1`. PAR-03 and block 5 say the name is `02 Beta`; that holds at the DOM level, which is the planned method, and PAR-04 holds (the label text is untouched). The visible text is `01 BETA`, so Label in Name (WCAG 2.5.3, case-insensitive) is met exactly. How a screen reader speaks an all-caps name is Not evaluated. Choices: (1) accept and keep this record, recommended, since the promise's method and its "Real assistive-technology output is Not evaluated" already scope it; (2) amend PAR-03 and block 5 to say the letters are the host label and the case follows the browser's rendered text, which needs a new approval and hash, as Amendment 1 did. No spec was changed. **Owner decision (2026-11-27): choice (1), accept and keep this record.** Verbatim "Aceptarlo y dejarlo registrado (Recomendado)" (`odd/tasks/round-5-consumer-requests.md` L8). The owner accepted that Chromium's accessibility name is uppercased by the CSS `text-transform` (`01 SECTION 1`) while the DOM text stays as the host supplied it (`01 Section 1`); this paragraph is the registration. PAR-03 and block 5 keep their wording and method, the spec's `contentSHA256` stays `362df467cb74e034735bbd559b93e67208e67dce5485436a5d7778fe753e15bb`, and no spec, plan, approval record, code or test changed. How a screen reader speaks an all-caps name stays Not evaluated (section 6).
- **F3 — the separator matters outside this browser.** Before the change Chromium already named rows `1 Overview` because flex items are blockified, while jsdom's name was `1Overview`; the `{' '}` text node makes the name independent of layout CSS (tests, unstyled DOM, other consumers). No action.
- **F4 — plan slice boundary.** `SectionNav.test.tsx` imports `ManySections`, so `SectionNav.stories.tsx` (the plan's slice 2) has to be committed with the test (slice 1); otherwise slice 1 alone fails `pnpm typecheck` and its story test. The Footer lane found the same boundary.
- **F5 — two tests beyond T1 to T9.** The `ManySections` pin (twelve items, the tenth current, open index) ties the story to the VIS-01 scenario, and the contrast pin makes the amended PAR-07 testable the way Link's quiet contrast test is. - **F6 — changelog shape.** A `### Changed` subsection already existed under ui `## 0.11.0` (the Footer entry), so the SectionNav entry opens that list instead of a new subsection, and the system entry opens `### Added` under `## 0.13.0`, newest first, as the earlier lanes did.
