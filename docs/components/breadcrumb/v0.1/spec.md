## 1. Purpose and scope

- **Need / non-goals:** egdev.es detail pages (editorial, events, projects and notes, in es and en) show where the reader is, for example "Home / Editorial / <title>": an accessible trail whose earlier steps are links, whose current page is marked, whose navigation landmark has a localized name and whose separators are decorative (#570; the pages are not built and no mitigation exists). Non-goals: not site, page-section or bottom navigation (TopBar, SectionNav, TabBar, Footer); not a menu, disclosure or tabs (no collapsed middle steps, no "…" control, no sibling dropdown); no routing and no router integration beyond `onNavigate`; no trail derived from the URL, router or content tree; no structured-data output (the website derives schema.org BreadcrumbList from the same entries); no `separator` prop, per-step icon, external or new-tab step, built-in text or `messages`; no truncation or collapsing (OQ-7); no right-to-left mirroring; no Pulso copy, links or domain data.
- **Cataloging decision / alternatives:** **new** molecule, owner-approved at cataloging (L3). The reuse → variant → compose → extract order was walked on inspected public code; each earlier step fails:

| Option | Inspected | Why it does not cover the need |
| --- | --- | --- |
| Reuse **NavList** | `packages/ui/src/molecules/nav-list/{types.ts,useNavList.ts,NavList.tsx}`; export `packages/ui/src/index.ts:72` | Named in-flow navigation, but a vertical unordered list of full-width rows (icon, count, tag, warning) with one level of static or collapsible groups; the host marks `aria-current` per link and the current row composes a Surface. It has no ordered semantics, no separator and no "the last entry is the current page" rule. A horizontal ancestry trail is another responsibility, so a NavList variant would stop being a variant (`docs/CATALOGACION.md`: "Una variante deja de serlo cuando introduce otra responsabilidad"). |
| Reuse **TopBar, TabBar, SectionNav, Footer** | `packages/ui/src/organisms/{top-bar,tab-bar,section-nav,footer}/types.ts` | Page-level regions: fixed header with brand and utilities, bottom bar, floating section index, heading-named footer group. None renders a root-to-current trail. `FooterNavigation` is the nearest code (labelled `nav`, `ul`, `Link arrow={false}`) but it is a Footer part with a visible heading. |
| Variant of **Link** | `packages/ui/src/atoms/link/types.ts:32-74` | Link is one link. A collection of links with separators and a current-page marker is a collection and navigation, which rules out an atom (`docs/CATALOGACION.md`). Link is **reused** here, not varied: the trail needs the `quiet` treatment of #562. |
| Others | Menu and Tabs (Radix composites), Divider, Stack | Menu and Tabs own roving focus and open or selected state; a trail is plain links in the tab order. Divider is a hairline content boundary with `decorative` and `orientation`, not a glyph between inline links; Stack and Cluster are layout only. |
| Compose in the app | native `nav > ol > li` with `Link` and `Icon` | Possible today and the consumer's only mitigation, but landmark naming, the current-page mark, separator hiding, wrapping and target size would be rebuilt on each of four collections' detail pages. The web-consumer amendment (approved 2026-11-02, `docs/CATALOGACION.md`) admits a web building block that a new web view could reuse into `@egdev/ui`, provided it carries no domain data; labels and destinations arrive through props. |
| Extract | `packages/ui/src` (searched) | No component contains a trail (ArticleFeature, NavList and Footer have none), so nothing is hidden to extract. |

- **Evidence / level and package:** Molecule in `@egdev/ui`, proposed `packages/ui/src/molecules/breadcrumb/`. It coordinates an ordered collection of links, decorative separators and one current-page marker as one unit, which is a collection and navigation, not an atom (`docs/CATALOGACION.md`); it is secondary in-flow navigation, not a page region, so it is not an organism: NavList is a molecule on the same grounds, unlike TopBar or Footer. **Radix base: none.** The 26 individual `@radix-ui/react-*` packages installed under `packages/ui/node_modules/@radix-ui` include no navigation primitive and none is needed: the semantics are native (`nav`, `ol`, `li`, `a`, `aria-current`) and the keyboard model is the browser's. Availability is checked in code, not in CSS, catalog or stories: `packages/ui/src/index.ts` exports no Breadcrumb, and the name appears nowhere in `packages/*/src`, `docs/CATALOGO.md`, `scripts/catalog_data.py`, `skills/` or the Foundation sources (`egdev-website/egdev-foundation`, searched for "breadcrumb" and "migas"), only in the Round 5 ODD documents (at drafting). **Prerequisites, verified absent today:** a Link `quiet` variant (`LinkVariant` is `'plain' | 'underlined'`, `packages/ui/src/atoms/link/types.ts:74`; `docs/components/link/` ends at v0.4) and a right-pointing chevron in the Icon set (`IconName`, `packages/ui/src/atoms/icon/types.ts:5-53`, has no `chevron-right`: its only chevron is `chevron-down`, and `arrow-right` is Link's own trailing arrow).

## 2. Anatomy and composition

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| Root `eg-breadcrumb` | Named navigation landmark | `nav` with `aria-label` taken from `label`; no Radix | one `ol` and nothing else |
| List | Ordered trail from the root to the current page | `ol` (native ordered list, numbering not shown) | `li` steps only |
| Step | One trail position | `li` | one step element and, except for the last rendered step, one separator |
| Ancestor link | Link to an earlier page | the exported `Link` atom (`a`) with native `href`, `variant='quiet'` and `arrow={false}` | the entry `label` text only |
| Current page | The page being viewed | `span` with `aria-current="page"`; not a link, not focusable | the entry `label` text only |
| Separator | Decorative boundary between steps | the exported `Icon` (`svg`), decorative and `aria-hidden` by Icon's own rule | none |

- **Radix / composition:** none. `Link` and `Icon` are reused unchanged by this component (`quiet` arrives with #562, its own spec). Links use the native `href` form: no `asChild`, no `external`, no `newTabText`. No Surface (nothing is painted behind the trail), no Divider, no Stack. The ARIA roles are the native ones (`navigation`, `list`, `listitem`, `link`); this component adds no role.
- **Public markers:** `eg-breadcrumb` is the stable public root marker. No part marker is promised; `eg-link` and `eg-icon` belong to the reused atoms. No legacy `eg-breadcrumb__*`, no `.is-*` and no `data-state` (the component has no own state): the native `aria-current` attribute is the only current-page representation. No legacy `bundle.css` rule targets these markers (none exists for a breadcrumb: searched).

## 3. Public API

**Prop conventions:** looked up in the [canonical registry](../../../../skills/_shared/prop-naming.json) and [generated view](../../../prop-naming.md) by meaning, name and aliases (no candidate entry has aliases) across all 185 entries. A keyword scan over every entry's id, name, meaning, use and avoid fields (current, crumb, trail, path, separator, divider, ancestor, parent, page, route, href, link, nav) found no entry for a current-page or separator prop and no existing Breadcrumb usage:

| Concept | Result |
| --- | --- |
| Accessible name of the landmark → `label` | Reuse approved `accessible-name` (`label`: "The accessible name of the control or displayed magnitude"). Existing navigation-landmark usages: NavList, TabBar, TopBar, ModuleRail, FooterNavigation and SectionNav (the TabBar and TopBar usages read "required navigation landmark name"). The entry's own `BreadcrumbItem.label` is a second usage of the same entry, as `FooterNavigationItem` and `SocialLinkItem` register theirs. |
| Ordered entries → `items` | Reuse approved `collection-items` ("Ordered data describing the entries a composite component renders, such as tabs, menu entries or navigation links; the entry shape is component-specific"; use: a molecule renders its own standard entry for each element of a consumer-supplied list). Rejected: `options` (`choice-options`, selectable form options), `rows` and `columns` (tables) and free `children` composition (the entry shape is defined). |
| Link activation → `onNavigate` | Reuse approved `navigation-intent` (the entry plus the originating event; preventing default hands navigation to a client router). Same signature as NavList, TopBar, TabBar, SectionNav, Menu and ModuleRail: `(item, event: MouseEvent<HTMLAnchorElement>) => void`. |
| Current page → no own prop | Derived from position: the last supplied entry. Rejected: a per-entry `'aria-current'?: 'page'` as on TopBarItem, NavListLink, TabBarItem, the ModuleRail links and FooterNavigationItem (host-marked, "at most one"; a trail always ends at the current page, so host marking would allow none, several or a middle current step); `activeId` (`active-section-id`, SectionNav's host-designated section id, avoid "generic selection"); `status` (`item-presentation-status`, lifecycle presentation); a separate `current` string (no registry entry, so a new convention, and the approved cataloging keeps one `items` array). |
| Separator → no own prop | A fixed decorative glyph. `decorative` (`decorative-separation`) and `orientation` (`layout-orientation`) belong to Divider and RadioGroup, whose contracts they describe. `arrow` (`trailing-arrow`), `external` (`new-tab-navigation`) and `newTabText` (`new-tab-notice`) are Link's own props: Breadcrumb passes `arrow={false}` to the links it renders and exposes none of them. |
| Built-in text → none | `messages` (`localized-messages`) is not used: there is no built-in text; the landmark name is `label`. |
| Size, variant, tone, status | Not used: v0.1 has no such axis (§6). Inherited native attributes and `className` need no own convention. |

## 4. Behavior

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| `label="Breadcrumb"` and entries `Home` (`/`), `Editorial` (`/editorial`), `Post title` (no `href`) | One `nav.eg-breadcrumb` named "Breadcrumb" with an `ol` of three `li`: links "Home" and "Editorial" with their `href`, then the text "Post title" in a `span` with `aria-current="page"`; two decorative separators, one after each link, none after the last step | none |
| One entry only | One `li` with the current-page text; no link and no separator | none |
| The last entry also supplies an `href` | The `href` is ignored: the current page is never a link and no anchor is rendered for it | none |
| An ancestor has no non-empty string `href`, or any entry has a blank or non-string `label` | The entry is omitted with a development warning (below); the other entries render; separators sit only between rendered steps | none |
| The last supplied entry is invalid | It is omitted with a warning and **no ancestor is promoted**: the trail ends at the last remaining link and no element carries `aria-current` (Footer v0.3 precedent: "no remaining entry becomes current") | none |
| `items` is empty, not an array, or has no valid entry | Nothing is rendered (no empty landmark); an empty array warns nothing | none |
| `label` is blank, whitespace-only or not a string | Development warning `Breadcrumb requires a non-empty label. Nothing was rendered.` and no output (never an unnamed landmark); a later valid rerender renders normally | none |
| Click or Enter on an ancestor link | Native navigation, unless the callback calls `preventDefault` | `onNavigate(item, event)` once, with the original entry object and the React `MouseEvent<HTMLAnchorElement>` |
| Pointer or keyboard on the current page or a separator | Nothing happens: not focusable, no handler | none |
| Re-render with different entries (navigating between pages) | Steps, destinations and the single current-page mark follow the data; appending an entry turns the previous last step into a link; no stale `aria-current`; focus is not moved | none |
| Many steps or long labels in a narrow container | The list wraps onto further rows and a long label wraps inside its step; nothing is truncated, clipped or collapsed (OQ-7) | none |
| Hover, focus, press on an ancestor link | The `Link` atom's own states; Breadcrumb adds none | none |

- **Derivation order (hook):** (1) `label` must be a non-blank string, otherwise warn and render nothing; (2) `items` must be an array; (3) classify by supplied position: the last entry is the current page and needs a non-blank `label`, every other entry is an ancestor and needs a non-blank `label` and a non-empty string `href`; (4) omit each invalid entry with one development warning, `Breadcrumb omitted the entry at index ${index}: it needs a non-blank label.` or `Breadcrumb omitted the entry at index ${index}: an ancestor entry needs a non-empty href.` (0-based index in the supplied array; strings final at plan, same development-only guard as SocialLinks and StepMeter); (5) render nothing if no entry remains; (6) render the rest in order, a separator after every rendered step except the last rendered one. Keys are positional because entries carry no `id`.
- **States / representation:** No own state and no `data-state`. The native `aria-current="page"` on the current-page `span` is the only state representation; link states are Link's; no state is mirrored into classes.
- **Limits / consumer responsibilities:** The host builds the trail (route data and titles), owns locale and wording, keeps the order from the root to the current page, supplies safe destinations (no URL validation, as in NavList, TopBar and Footer) and intercepts routing through `onNavigate`. Breadcrumb does not infer the trail from the URL or router, does not deduplicate or sort, does not announce changes, does not restore focus if a re-render removes the focused link and emits no structured data. Landmark names must be distinct on a page; that is the host's duty.

## 5. Accessibility

- **Accessible name / roles / relationships:** The `nav` landmark is named by `label` through `aria-label` (`aria-labelledby` is protected). Inside, a native ordered list (`ol`, `li`) lets assistive technology expose the position in the trail. Ancestors are links named by their `label` (the arrow is hidden and there is no new-tab notice). The current page is text with `aria-current="page"`: `aria-current` is a global ARIA attribute, so it is valid on a role-less `span` (cited from general knowledge, not re-fetched in this session). The APG breadcrumb example marks the current page's *link*; this component marks plain text instead (OQ-1). Separators are decorative `svg` elements with `aria-hidden="true"` and `focusable="false"` (Icon's rule), so they add no text to any name or reading. Required consumer input: `label` and every entry label, in the page language.
- **Keyboard / focus:** Native only. Tab and Shift+Tab visit the ancestor links in order; Enter activates. The current page and the separators are not tab stops. No roving focus, arrow-key model, Radix or `tabindex`. The focus ring is Link's (`--shadow-focus`, `link/types.ts:82`); Breadcrumb moves no focus on update and promises no focus restoration.
- **Announcements / other conditions:**
  - **Announcements:** none (no live region); a trail change accompanies a page change, and announcing that is the host's.
  - **Non-colour cues (WCAG 1.4.1):** ancestors are underlined by the Link `quiet` recipe and the current page is not; the current page also carries `aria-current`; separators carry no meaning. This holds only if #562 keeps the underline (OQ-3).
  - **Contrast:** the current-page text is `text-fg-default` (documented 21:1 on canvas, `packages/tokens/src/theme.css:72`); other surfaces are measured in BC-12. The separator is decorative, so no contrast claim is made for it.
  - **Target size (OQ-4):** an unmodified `Link arrow={false}` is about 13.4px tall (Footer measured 42 × 13.44px and 29 × 13.44px, `docs/components/footer/v0.1/link-target-amendment.md`). The proposal gives each ancestor link a hit area at least 44.8px tall (the DS 44px touch rule) with the width following the label, and claims nothing until BC-13 is observed; the current page is not a target.
  - **Reflow and zoom (WCAG 1.4.10):** the list wraps and long labels wrap; planned browser proof at 320 and 390px (BC-14), not claimed yet.
  - **Reduced motion, transparency and forced colours:** Breadcrumb adds no transition, animation or movement, so reduced motion needs no fallback (Link's own transitions are suppressed by Link); nothing is translucent; no meaning depends on colour, and the separator strokes `currentColor`. Real forced-colours rendering is Not evaluated.
  - **Not evaluated:** screen-reader output (including whether list semantics survive `list-style: none` and `display: flex` on `li` in WebKit), right-to-left rendering (the separator's rotation is physical, so it would point the wrong way), protan and deutan simulation.
