## 4. Findings

- **F1: the minimum same-row gap is 25.58 px against the 25.6 px design figure.** BC-13 and plan section 9 derive 25.6 px as 6.4 + 12.8 + 6.4. Chromium lays out in 1/64 px units, so each 6.4 px gap computes as 6.390625 px and the 12.8 px icon as 12.796875 px, which sums to 25.578125 px. No component choice changes it (the same snapping applies to every token step, as the glyph "22.4 px (22.39 px after layout snapping)" of the EmptyState lane), and the WCAG 2.5.8 minimum target size is met by size, because every target is 44.8 px tall and at least 28.64 px wide. I treat it as measurement quantization, not as a contradiction, but a strict reading of "at least 25.6" would be 0.02 px short: the parent confirms the reading.
- **F2: `-rotate-90` serializes differently in the two CSS pipelines, and it was already shipped.** The optimized preview CSS emits `rotate: -90deg`, the shipped, unoptimized `styles.css` emits `rotate: calc(90deg * -1)`; the plan expected the serialization to be "recorded by the first run". Plan section 3 and R-3 also expected the bare utility to be new in the shipped CSS, but it is not: Menu's chevron (`menuChevronVariants`) and Tabs already use bare `-rotate-90`, so only its serialization needed pinning (no test pinned it before; only the group-data variant was pinned). `storybook-css.test.ts` pins the first form and `package-exports.test.mjs` and the packed consumer check pin the second. They are the same quarter turn.
- **F3: the focus ring follows the stretched anchor** (28.64 × 44.8 px and 41.61 × 44.8 px with the `--shadow-focus` token), a tall ring around 11.2 px text, as plan R-2 anticipated for Footer-style links. No promise changed; its look is an appearance question for the VIS captures.
- **F4: when the trail wraps, each chevron stays on the row of the step it follows,** because it lives in that step's list item, so a wrapped row can end with a chevron (visible in `Wrapping` at 390 px). The spec's anatomy says exactly this (one separator after each rendered step but the last), so it is not a contradiction; it is recorded for the owner's VIS-02 review.
- **F5: CDP's accessibility tree exposes no `current` property,** so `aria-current="page"` is verified as a DOM attribute and as the unit test's `getByText` assertion. How a screen reader announces it is **Not evaluated** (spec section 5).
- **F6: the only non-visible `overflow` among the parts is the separator `svg`'s user-agent default** (`svg:not(:root) { overflow: hidden }`). It is Icon's element, no Breadcrumb utility sets an overflow, and it clips nothing: the chevron lies inside its viewBox.
- **F7: the shared `anatomyUtilities` table keeps its 401 entries but reorders 23 positions.** `gap-x-2` and its neighbours are now first met earlier, so 14 pre-existing components differ in raw bytes only through renumbered indices.
