## 1. Gates and scope

1. Obtain owner approval of this plan, the exact implementation/integration surfaces, and the compatibility route for the existing compositions in §6. No edits to those surfaces are authorized by this document. Follow test-first, preserve the six meaningful files and use **No stylesheet**. If static utilities cannot meet the contract, stop for a separately approved stylesheet role or revised contract; do not improvise either.
2. All enabled sizes and treatments get one centered, invisible `--space-14` square on every pointer type, with no prop, wrapper, extra accessible object or event synthesis. Under the default scale the square is 44.8px; the visible boxes remain `sm` 25.6px, `md` 32px and `lg` 38.4px. Actual ≥44px operation is conditional on the unobstructed, unscaled host and sufficiently large resolved token described in v0.4.
3. Remove geometric press motion, not the active state: all four treatments retain native activation and v0.5's paint feedback. Keep v0.2's no-hover-lift rule and v0.3's outline hover border. Preserve focus, disabled semantics, all public names, defaults, exports and actual-host refs. No new token, dependency, API, registry convention, legacy migration or inline geometry.
4. `odd/tasks/consumer-request-specs.md` L9 records Chrome 148 **synthetic** feasibility work: the former 44.8px descendant became 42.112px under `scale(.94)`; compensated and counter-scaled alternatives also misdirected stationary clicks during spring overshoot. v0.5 resolves the contract obstacle by removing the root scale, not by approving those alternatives. L9 is not proof of the future component: shipped-CSS, stationary-pointer and consumer tests remain gates.
5. Obtain separate permission for generated outputs, package fixtures, server/browser access and any capture. Stop on a contradictory result, unsupported host, failed geometry/cascade check or needed unapproved edit surface; never weaken the target or silently accept overlap to make a check pass.

## 3. Geometry, press paint and cascade

**Root and hit square.** Add a static positioned-root utility and static `after:` utilities for empty content (for example `after:content-['']`), absolute positioning and `size-14`. Center it relative to the actual root border box, using token-backed static positioning; a non-animated centering expression must continue to track a locally resolved `--space-14`. For example, after verifying Tailwind emission and browser support, use static `after:left-[calc(50%_-_var(--space-14)_/_2)]` and the corresponding `after:top-…` with `after:size-14`. This is CSS utility arithmetic, not a runtime inline custom property or interpolated utility. The pseudo-element has no background, border, shadow, focus paint, independent DOM node or handler. Confirm its computed size and center, including the bordered outline root; if the selected utilities do not emit or center correctly, stop rather than add an unapproved geometry mechanism.

An existing supported positioned host can remain `absolute` rather than `relative`: `cn()` may resolve positioning classes, so the requirement is an effective positioning context, not the literal presence of one root class. Disabled `data-disabled:pointer-events-none` must also suppress the inherited pseudo-element pointer events; never add `after:pointer-events-auto`. A disabled action can allow the event to fall through to an underlying row.

**Slot compatibility proposed for plan approval.** A native button or one empty anchor/router host must spread props and forward its ref. Its effective positioning must anchor the pseudo-element; its own `::after`, clipping, stacking, overlays, non-identity ancestor transforms, insufficient token overrides or target-overriding styles are unsupported unless separately resolved. Document these precise conditions on `asChild` and in usage guidance. Check native anchor and compatible router host separately; do not overwrite a child's own pseudo-element or promise arbitrary Slot CSS precedence. Root `className` remains outer margin/alignment/placement only, not a target or appearance override.

**Transitions and legacy.** Remove `motion-safe:[&:not([data-disabled]):active]:scale-94`, `[&:not([data-disabled]):active]:duration-(--duration-press)`, the redundant `motion-reduce:active:scale-100`, and the `transform`, `translate` and `scale` entries in the root transition. Retain static `transform-none`, `translate-none` and `scale-100` root resets to defeat legacy `.eg-icon-btn:active { transform: scale(.94) }`, plus the existing `motion-reduce:transform-none`, `motion-reduce:translate-none` and `motion-reduce:scale-100` identity resets; do not animate those resets. Keep the existing root paint transitions: color and background-color at `--duration-fast`, border-color and box-shadow at `--duration-base`, all with `--ease-out`. Preserve v0.5's `--duration-press` for applicable **paint** changes without restoring the removed duration utility: for example, a motion-safe enabled-active transition shorthand can set those four paint properties to `--duration-press` with their existing easing. Verify its exact emitted cascade and release timing, not merely class order. Keep the icon's existing `transition-colors`/`--duration-fast` and reduced-motion suppression. `motion-reduce:transition-none` must win; there must be no root geometric animation in either motion mode. Check computed `transform` **and** individual `translate`, `scale` and `rotate` through hover, down and release with the legacy stylesheet present.

| Treatment | Planned enabled active state; focus and other layers |
| --- | --- |
| `ghost` | `bg-surface-3`, including hover+active and focus-visible+active; `shadow-btn-pressed` only when not focus-visible. Keep no image, glyph and rest/hover recipe. |
| `outline` | `bg-surface-3` with its sheen, hairline/brand hover border, round radius and glyph intact; `shadow-btn-pressed` only when not focus-visible. Preserve its rest/hover elevation and glow outside active. |
| `primary` | Retain solid primary background, `bg-none` and `shadow-btn-pressed` except while focus-visible. |

The approved ghost/outline pressed shadow supplies the non-color depth cue. On every treatment `--shadow-focus` wins on the visible root while focus-visible; the tone may remain active. Ensure active backgrounds/shadows beat hover where both match, e.g. exclude `:active` from a competing hover rule if the emitted cascade requires it. Keep disabled paint/opacity and native semantics; do not add `aria-pressed` or change Link motion. Reduced motion removes transitions but retains tone and focus. Test the built layer cascade rather than inferring precedence from CVA string order or `twMerge`.

## 5. Stories and usage guidance

- Add `AdjacentTargets`: show equal `sm`, `md`, `lg` and mixed-size neighbors using token-backed layout with sufficient separation. The default-token visible edge gaps are at least 19.2px for two `sm`, 12.8px for two `md`, 6.4px for two `lg`; mixed sizes use the sum of 9.6/6.4/3.2px outsets. Use a `gap-6` (19.2px) layout where one token must safely cover every pair. Inspect wrapped rows as well as horizontal pairs. Do not present an insufficient gap as compliant.
- Update the existing `Sizes` story from `gap-4` to sufficient spacing: `sm` next to `md` needs 16px, more than `gap-4`'s 12.8px. Correct its historical 32/40/48px/glyph copy to the actual token-resolved values. Preserve `Variants`, `Default`, disabled and Slot examples and their defaults.
- Add `CompactListItem`: a real two-line `ListItem` row with content/title and metadata plus **one independent trailing IconButton**, analogous to Recado's card; use token-backed parent layout and reserve the full target, including space between rows. Do not put an independent control inside a whole-row anchor or fake a row action. Demonstrate the row arrangement the existing ListItem API actually supports, not a local override of its internal appearance.
- Describe overlap, row-to-row center spacing of at least 44.8px or equivalent clear reserved space, clipping/overlays, Slot restrictions and earlier hover/Tooltip entry. A target may extend outside a short row only into reserved, unclipped and non-interactive space. Normal click bubbling remains; the consumer must not turn it into an independent row activation. Keep `Meta<typeof IconButton>`, autodocs and English story JSDoc; no manual `argTypes`, `play`, dummy actions or appearance overrides.

## 10. Risks, open questions and stop

- **R1 — Existing compositions conflict with the precondition.** Attached ButtonGroup and md SocialLinks are not made safe by the atom's invisible rectangle; Nexo and Recado use the latter today. Tabs' deliberate edge overlay and other internal consumers need actual event evidence. No unconditional compatibility or WCAG conformance claim is justified.
- **R2 — CSS cascade and timing.** Legacy active transform remains shipped, and both package harnesses currently require the old scale. A global token search can be falsely green. Reduced-motion paint, focus shadow precedence and stationary hit testing must be checked with emitted styles.
- **R3 — Hosts and theme.** Slot-owned pseudo-elements, absolute positioning, clipping, overlay/stacking, ancestor transforms and insufficient local `--space-14` overrides can invalidate the target. Disabled pointer suppression permits fall-through. Router and hybrid capability support remain unproved.
- **R4 — Integration and evidence.** Source-byte registry pins, system artifacts, story-name assertions and package harnesses require separately authorized coordinated updates. Package-cache availability, real-browser/AT checks and visual references are pending. The app-owned Recado mitigation stays until independent downstream verification.
- **Open decision A — compatibility route:** approve a separately scoped accommodation/migration for ButtonGroup, md SocialLinks and any confirmed Tabs/other conflicts, or return the combined contract to the owner for revision. Do not silently enlarge the authorized atom scope, disable automatic expansion or declare overlaps acceptable.
- **Open decision B — plan and evidence:** approve this exact plan and the future edit/verification surfaces, or revise it. Decide separate browser/AT access, packed-fixture permission and the VIS-03/04 expected-design sources/capture adoption. None changes the already approved v0.4/v0.5 decisions.

**Stop:** no implementation, release, registry edit, product change, server start, capture or publication is authorized by this proposal. Report any unresolved compatibility gate and missing evidence before claiming the amendments are delivered.
