## 1. Purpose and scope

**Proposal.** Remove the root's motion-safe `scale-94` press shrink for all IconButton sizes, treatments and consumers. Keep the v0.4 automatic, all-pointer, centered `--space-14` invisible square unchanged; use Material paint, not movement or an alternative target geometry, for press feedback. This changes the appearance of a momentary press in every app, not the resting size or the public API. The owner selected this direction in `odd/tasks/consumer-request-specs.md:11,36-37` (S6 and L9–L10). The exact added paint below is a proposal, not an approved decision.

**Changed promises and preserved history.** v0.2 explicitly kept `motion-safe` `scale-94` on `:active` (`docs/components/icon-button/v0.2/hover-motion-amendment.md:11-13`); this amendment supersedes that promise. It also supersedes v0.3's press-scale description and the v0.4 requirement to preserve the old visible active/press appearance with no feedback change (`docs/components/icon-button/v0.4/hit-area-amendment.md:18,79,109,116`). The v0.4 target, focus, spacing and input policies otherwise stay intact. Primary and secondary keep their existing active paint; the proposal adds a pressed tone to ghost and outline, which currently have no explicit active tone. These are additional active-paint changes, not claims that all variant appearance remains byte-for-byte unchanged.

v0.2 **already removed** hover lift: ghost formerly used `-translate-y-0.5` and the other variants `-translate-y-px` (`hover-motion-amendment.md:7-9`). Its promise of hover feedback through background, border, shadow and glow without root lift remains; there is no approved hover translation to remove. No hover scale, translate or other geometric root motion is introduced, including while entering the enlarged hit region. A moving hover root would move its `::after` relative to a stationary edge pointer and could cause hover loss or misdirect activation. This is a geometry risk, not an observed failure of the current v0.2 hover. v0.2's obsolete reduced-motion-only hover reset remains unnecessary; static resets that defeat legacy rules can still be required. Focus, disabled behavior, variant and size **identities**, accessible naming, API and Link's separate arrow nudge remain as in v0.2, subject only to the stated pressed-paint delta.

**Cataloging and alternatives.** Reuse and amend the exported `@egdev/ui` IconButton atom (`packages/ui/src/index.ts:13`, `packages/ui/src/atoms/icon-button/index.ts:1-2`). Unchanged reuse retains a shrinking target; a new variant, wrapper or component would duplicate one action and alter the API, layout or Slot/focus boundary. A larger `--space-16` target, compensated size, counter-scale, inner visual wrapper and registered geometry property are not adopted: L9 reports their respective overlap, spring, contract or stylesheet-approval problems. No dynamic geometry, custom event forwarding or synthetic click is proposed.

**Evidence obtained; not validation of this proposal.**

- `packages/ui/src/atoms/icon-button/types.ts:51` contains the active scale, `--duration-press`, identity resets and spring transitions on `transform`, `translate` and `scale`. The four variant recipes at `types.ts:55-62` give ghost and outline hover paint but no explicit active paint; primary uses an active solid background and `--shadow-btn-pressed`, while secondary uses `--color-alpha-red-15` and the same shadow. Both active shadows yield to `focus-visible`.
- `packages/ui/src/styles/legacy/bundle.css:58-78` still contains `.eg-icon-btn:active { transform: scale(.94) }` and a legacy outline hover lift. `packages/ui/src/styles/index.css:10-12` imports it in the components layer. Simply deleting the CVA scale utility is not proof that the resulting built cascade has no motion: retain an effective static reset against legacy CSS and test the shipped stylesheet. Do not edit or retire legacy rules in this amendment.
- At default tokens, `--space-14` is 44.8px (`packages/tokens/src/theme.css:459-460,594-595`); multiplying by .94 gives 42.112px. The L9 **Chrome 148 synthetic-fixture** experiments reported a corner press reaching the row and reported pointerdown on the button followed by pointerup/click on the row for both a compensated resting size and an animated counter-scale during spring overshoot. These are prior feasibility observations, not a browser test of an implemented v0.5 or v0.4 component.
- The existing hover regression tests explicitly expect the old active scale (`packages/ui/src/atoms/icon-button/IconButton.test.tsx:205-210,234-240`). They must be revised in an independently authorized implementation, not mistaken for verification of this draft.

| Invisible extension | The v0.4 empty, centered `::after`, 44.8px square with default `--space-14` | No new node, name, paint or independent action. Its shape, token and all-pointer policy do not change. This is approved direction, not evidence it is already shipped. |
| Icon and hidden name | Existing Radix AccessibleIcon composition | Decorative glyph stays hidden; required `label` supplies the accessible name. |

The native button and compatible empty anchor/router host still use the existing Slot/Slottable and AccessibleIcon composition (`packages/ui/src/atoms/icon-button/IconButton.tsx:1-14`). A slotted host must spread props and forward its ref. Its own `::after`, clipping, positioning or stacking can conflict; v0.4 requires the later plan to resolve such a conflict or obtain approval for a precise restriction. No new Radix primitive or stylesheet role is proposed.

## 4. Behavior

| Condition / action | Proposed observable result |
| --- | --- |
| Rest → hover, all variants | The root and target do not translate, scale, rotate or otherwise change geometry; existing hover paint still applies. Hover may start at the invisible boundary under v0.4. |
| Enabled pointer down → active → release | Root and its `::after` remain stationary and unscaled throughout the sequence and any release transition. Apply the variant's pressed paint in §6; deliver one ordinary native activation to the intended root, without synthetic forwarding or an extra click. |
| Focus-visible plus active or hover | The pressed tone may coexist with focus. The same visible-root `--shadow-focus` ring wins over competing Material shadows, including while pressed. |
| Disabled native or slotted host | Preserve existing opacity, pointer suppression, tab-order and activation/navigation guards; do not introduce pressed paint or a separately active pseudo-element. As in v0.4, disabled events may fall through to underlying content. |
| Keyboard | Keep native button Tab/Enter/Space and native anchor behavior; no new handlers, focus stops, persistent state or `aria-pressed`. Press paint follows the browser's applicable native `:active` state. |
| Reduced motion | No geometric transformation or animation; preserve the existing reduced-motion suppression of transitions while the non-motion pressed tone and focus ring remain available. |

For supported, unobstructed, unscaled hosts with sufficient resolved tokens, v0.4's square must contain a contiguous centered 44 × 44 CSS-pixel target, including its corners, at rest, on hover, while pressed and on release. This is a goal for the later implementation, not a demonstrated effect of this document. Identity resets such as `transform: none`, `translate: none` or an identity scale are compatible with the no-movement promise; adding non-identity transforms is not. Remove transform/translate/scale spring transitions from the root rather than animating an identity reset. Preserve the existing token-backed paint transitions and `--duration-press` timing where applicable; reduced motion suppresses them. Tests must examine computed transform **and individual** translate/scale/rotate properties and actual hit testing, not merely a missing class.

v0.4's consumer obligations continue: reserve the full square without overlap with adjacent controls, rows or links; prevent clipping, overlays, ancestor transforms and undersized local token overrides; and do not nest an independent action in a whole-row anchor. Its illustrative default-token edge gaps are 19.2px for two `sm`, 12.8px for two `md` and 6.4px for two `lg` controls; mixed sizes use the sum of outsets. Normal event propagation remains unchanged: a row may observe a bubbled button event, but must not treat it as a separate row activation. Audit attached ButtonGroup controls, SocialLinks, Recado, Nexo and egdev-website before adoption (`odd/tasks/consumer-request-specs.md:36`).

## 5. Accessibility

Keep the accessible name, native button/link roles, decorative hidden icon, descriptions, keyboard interaction, disabled semantics and actual-host ref. The extension adds neither a separate accessible object nor a focus target. The focus-visible ring stays on the visible button, not the invisible square, and must not be clipped or obscured. Press is momentary action feedback, not a persistent selected state; do not add an `aria-pressed` state or rely on color to convey a persistent state. Screen-reader, keyboard, focused-press visibility and target-size outcomes require separate checks.

The v0.4 objective remains an actual 44 × 44 CSS-pixel target in the stated supported context, stronger than the WCAG 2.2 AA 24px target-size minimum and corresponding to the AAA enhanced criterion with its stated exceptions. Neither a token, this proposal nor an image establishes conformance. Tooltip remains supplementary; it does not replace the label and is not promised to open on touch.

## 6. Appearance

**Proposed active recipe, pending owner approval.** Existing hover and rest treatments remain; active paint takes precedence over hover where both match. No arbitrary color, new token, new shadow recipe, additional stylesheet or dependency is proposed.

| Variant | Current source evidence | Proposed enabled `:active` paint |
| --- | --- | --- |
| `ghost` | Transparent at rest, `--color-action-primary-bg-default` on hover; no explicit active background or shadow (`types.ts:55-56`). | Add `bg-surface-3` (`--color-surface-3`) as a distinct pressed tone, including when hovered or focus-visible. Keep its existing no-image/no-shadow recipe and glyph treatment; no transform. **Resolved (owner, 2026-11-22):** also add `--shadow-btn-pressed` while pressed and not focus-visible, so the press has a depth cue as well as a tone; `--shadow-focus` keeps priority when focus-visible. |
| `outline` | `surface-1` plus sheen at rest, `surface-2` plus sheen on hover; no explicit active background (`types.ts:57-58`). | Add `bg-surface-3`, including when hovered or focus-visible. Retain the sheen, round shape, border, existing rest/hover elevation and glow rules; no transform. **Resolved (owner, 2026-11-22):** also add `--shadow-btn-pressed` while pressed and not focus-visible (depth cue as well as tone); `--shadow-focus` keeps priority when focus-visible. |
| `primary` | Active solid `--color-action-primary-solid-bg`, no background image, and `--shadow-btn-pressed` unless focus-visible (`types.ts:59-60`). | Preserve that existing tone/shadow and the focused ring; remove only geometric press motion. |
| `secondary` | Active `--color-alpha-red-15`, no background image, and `--shadow-btn-pressed` unless focus-visible (`types.ts:61-62`). | Preserve the existing tone/shadow and focused ring for this minimal proposal; resolve the documented token-role conflict below before approving an implementation. |

`docs/MATERIAL.md:25` explicitly identifies `--color-surface-3` with a pressed IconButton; the token exists at `packages/tokens/src/theme.css:172-173`. The added ghost/outline state is a **proposed component-specific Material recipe**, not already approved just because the token exists. It does not turn those variants into a persistent selected control. Primary/secondary shadows and the focused shadow priority remain as before. The proposed ghost/outline pressed cue is color-only; the unchanged icon and focus ring do not themselves indicate a press. The shared contract requires a non-color state cue, so this proposal is not implementation-ready until that requirement is explicitly resolved. Do not treat focus visibility alone as proof of distinct pressed feedback; review both focused and non-focused states without weakening the focus ring.

**Token caveat, not a new approval.** `packages/tokens/src/theme.css:46-47` documents `--color-alpha-red-15` as for shadows only, although the current secondary active recipe uses it as a background. That is a pre-existing source/documentation conflict; no approved scoped exception was recovered in this task. Do not silently characterize it as compliant or change a token here. If the owner wants the identical secondary color with a semantically valid non-shadow role, a separately confirmed token/alias or explicit scoped exception may be needed; otherwise an existing suitable token could be selected with an acknowledged visual change. The exact resolution is open below. No new token is needed for the proposed ghost/outline tone or the 44.8px target.

**Material and focus boundaries.** Keep the approved visible-root border, radius, sheen, focus, disabled treatment and state-shadow priority apart from the stated active-tone additions and removed transform. `docs/MATERIAL.md:42-44,71-72` describes historical pressed-transform CSS as a semantic illustration, not a mandate to copy it; this component-specific no-transform amendment requires explicit approval. `--shadow-focus` continues to win (`docs/MATERIAL.md:98`). No paint is moved to `::after`; no inline appearance, interpolated utility or registered dynamic geometry is proposed.

**Files and class composition.** Preserve the six existing roles: `types.ts` (props/CVA), `useIconButton.ts` (host, guards and composition), `IconButton.tsx` (JSX), `IconButton.test.tsx`, `IconButton.stories.tsx` and `index.ts`. **No stylesheet** and no extra internal module are proposed. Existing root `className` remains outer margin/alignment/placement only, merged with `cn()`; it is not permission to override appearance or hit geometry, and `twMerge` does not guarantee arbitrary CSS cascade precedence. Future implementation must check real static utility emission and a packaged consumer without a Tailwind compiler; a separately approved plan must address all necessary integration surfaces.

### Resolved decisions

1. **Pressed paint and non-color cue, ghost and outline.** Owner choice, verbatim: "surface-3 + shadow-btn-pressed (Recomendado)" ("Tono de MATERIAL.md (pressed IconButton) más la sombra hundida que ya usan primary/secondary: señal de profundidad, no solo color. Sin tokens nuevos; --shadow-focus sigue ganando.").
   - While pressed, ghost and outline set `bg-surface-3` (`--color-surface-3`) plus `--shadow-btn-pressed` when not focus-visible.
   - The inset shadow is the non-color cue that satisfies the shared state-cue requirement. When focus-visible, `--shadow-focus` keeps priority, exactly as for primary and secondary.
   - No new token is needed.
2. **Secondary token role.** Owner choice, verbatim: "Excepción documentada (Recomendado)" ("Mantener el color actual (sin cambio visual) con una excepción acotada y escrita en la ficha para este uso; sin tocar tokens.").
   - **Scoped exception:** IconButton `secondary` may use `--color-alpha-red-15` as its pressed background (`types.ts:61-62`), although `packages/tokens/src/theme.css:46-47` documents that token for shadows. The exception covers only this pressed background of this variant.
   - It does not extend the token's role elsewhere and changes no token. The secondary press color stays visually unchanged.
3. **Visual evidence.** Owner choice, verbatim: "Sí, sin capturas (Recomendado)". The snapshot is approved without new captures; VIS-03/04 remain pending, and visual conformity is Not evaluated until captures are authorized and approved.
