## 1. Purpose and scope

- **Need / non-goals:** A consumer that writes no utility classes (egdev.es runs Tailwind with `source(none)`, #392) cannot lay out columns: today it can only stack with `Stack` (#395). Grid is the passive layout part it is missing: a column count, a token gap, cross-axis alignment and an opt-in collapse to one column at two approved viewport widths. GridItem places one item by column span and row span. First consumers: egdev-website's About, Community, Discord and Build zones and its listing pages. Non-goals: container queries; any threshold other than 860 and 1080; per-breakpoint column counts; `auto-fit`, `auto-fill`, masonry, named areas, subgrid and explicit rows; explicit start or end lines; independent row and column gaps; `justifyItems`, `justifyContent` and reordering (`order`); paint, Material, scroll or overflow behavior; scene organisms and `Split` (declined by the owner); any change to Stack, Cluster, BlogGrid, Hero or SectionShell; tokens and dependencies.
- **Cataloging decision / alternatives:** **new** primitive, owner-approved (L3: "Grid genérico, sin organismos ni Split (Recomendado)", which also resolves the #491 decision). Rejected, in [CATALOGACION](../../../CATALOGACION.md) order: *reuse* — Stack is one flex column and Cluster a wrapping row, with no columns, spans or collapse, and BlogGrid, Hero and SectionHeader own fixed domain shapes; *variant* — a column axis on Stack would turn a one-axis flow into a two-dimensional layout, a change of responsibility; *compose* — composing needs consumer utilities (`grid`, `grid-cols-*`, `min-[48rem]:`), which egdev.es cannot generate; *extract* — BlogGrid's grid is private and shaped for one feature; scene organisms and `Split` — declined by the owner.
- **Evidence / level and package:** primitive in `@egdev/ui` at `packages/ui/src/primitives/grid/` (reusable structure with no semantics, Material, copy or domain data). Radix base: none; `@radix-ui/react-slot` for `asChild`, already a dependency (`packages/ui/package.json:45`). Availability is read from the React package, not from CSS, stories or the catalog: `packages/ui/src/index.ts` exports no `Grid` or `GridItem`, and no file under `packages/ui/src` or `packages/effects/src` declares one.

## 2. Anatomy and composition

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| Grid (`eg-grid`) | Two-dimensional layout of its children in equal-width tracks with a token gap, and the opt-in collapse to one column. Passive: no role, no state | `div`, or the single child element with `asChild` | Any children, in reading order: `GridItem` parts or any element |
| GridItem (`eg-grid-item`) | Places one child of a Grid by column span and row span; `min-width: 0` so long content cannot widen its track | `div`, or the single child element with `asChild` | Any content |

- **Radix / composition:** no Radix primitive. `@radix-ui/react-slot` only, for `asChild`, as Stack does. Reused pieces: the types `LayoutGap` and `LayoutAlignItems` (type-only import from `primitives/stack/types.ts`) and `cn()`. With `asChild`, exactly one element child that spreads props; the host element keeps its own semantics.
- **Public markers:** stable roots `eg-grid` and `eg-grid-item`. They are markers, not styling hooks. No data attribute, id or part marker is added.

### Interactions with Stack, Cluster and the other layout parts

- **Division of labor.** Stack owns one vertical axis, Cluster a wrapping row, Grid equal columns with optional spans. Each owns only its own axis, and all three share the `LayoutGap` keys and `LayoutAlignItems`, so a section can mix them (`Stack gap={10}` holding a header and a Grid) without a second spacing vocabulary.
- **`GridItem asChild` over a Stack.** Slot merges the item placement (`col-span-N`, `row-span-N`, `min-w-0`, the marker) onto the Stack's root, giving one element that is both the grid item and the vertical flow. Stack forwards `className` through `cn()`, so the merge needs no wrapper. This is the About second column.
- **Stack parent with a non-stretch `alignItems`.** A Grid inside a Stack whose `alignItems` is `start`, `center`, `end` or `baseline` is a flex item with a fit-content width, so its tracks follow its content instead of the Stack's width. The Stack default (`stretch`) fills the width. A consumer that needs another alignment places the Grid in a stretching parent. Grid adds no `w-full`, because `width: 100%` plus a margin from `className` would overflow.
- **Reach of the collapse reset.** The reset targets the Grid's direct children only (`> *`). Nested grids, and the contents of a `GridItem`, are untouched; a nested Grid has its own `collapseBelow`.
- **Cascade across packages (#392).** See block 6, "Cascade and the #392 risk".

## 3. Public API

- **Prop conventions:** looked up in the [canonical registry](../../../../skills/_shared/prop-naming.json), the [generated view](../../../prop-naming.md) and the [lookup workflow](../../../../skills/_shared/component-contract.md#prop-naming-registry) by meaning, name and aliases. The registry has 193 entries and none declares an alias for these concepts. Method: every entry's id, name, meaning, `whenToUse` and `avoid` text was swept for column, span, row, gap, grid, align, layout, collapse, breakpoint, viewport, responsive, placement, slot and track. Convention approval is independent of this spec's approval: the owner's L4 approval covers the registry receipts of the four new conventions below (OQ-6), recorded as a scoped receipt at implementation. Nothing in this document edits the registry.

| Concept | Result |
| --- | --- |
| Spacing between items → `gap` | **Reuse approved `layout-gap`** (`gap`: "Token-backed spacing between adjacent children of a layout container, including row and column gaps when it wraps."). Type `LayoutGap`. Its `avoid` (inner padding, outer margins, arbitrary lengths, reordering) is respected. Usage to append: Grid |
| Cross-axis alignment → `alignItems` | **Reuse approved `cross-axis-alignment`** (`whenToUse`: "A flex or grid layout container exposes supported item alignment choices…"). Type `LayoutAlignItems`. Usage to append: Grid |
| Render onto the child → `asChild` | **Reuse approved `slot-composition`** (`asChild`). Usages to append: Grid and GridItem (OQ-2 for GridItem) |
| Column count → `columnCount` | **No approved entry fits.** `table-columns` owns the name `columns` and avoids "CSS grid layout tracks"; `count` is `indicator-count` (a supplementary marker total), `steps` is `step-count`, `pageCount` is `page-count`. **New concept:** semantic ID `grid-columns`, canonical name `columnCount`, type `1 \| 2 \| 3 \| 4 \| 12` (default 1). **Resolved (OQ-1): the owner chose `columnCount`.** The L3 draft's name `columns` cannot be registered because `table-columns` owns it (V-7); the alternatives (a Grid-scoped exception to `columns`, or another name) were not chosen, so no exception is requested |
| Viewport collapse → `collapseBelow` | **New concept:** semantic ID `layout-collapse-below`, name `collapseBelow`, type `860 \| 1080`. Swept: no entry names a breakpoint; `compact-presentation` (`compact`) avoids "automatic responsive detection" and is a boolean for a launcher |
| Item column span → `span` | **New concept:** semantic ID `grid-item-span`, name `span`, type `1 \| … \| 12` |
| Item row span → `rowSpan` | **New concept:** semantic ID `grid-item-row-span`, name `rowSpan`, type `1 \| 2 \| 3 \| 4` |

  **New conventions, exact registry text** (each registered `status: proposed` with `approval: null` and promoted to `approved` by the scoped receipt of plan decision D3, which the owner's L4 approval covers; no alias, no exception; sentence case with a final period, as the Pagination receipt):

  | ID | Name | Meaning | Use | Avoid |
  | --- | --- | --- | --- | --- |
  | `grid-columns` | `columnCount` | Number of equal-width columns of a grid layout container. | A reusable grid layout container exposes a small finite set of equal column counts. | Table column definitions (use `columns`), explicit track sizes or templates, item spans (use `span`) and responsive breakpoints (use `collapseBelow`). |
  | `layout-collapse-below` | `collapseBelow` | Viewport width in CSS pixels at and below which a layout container drops to a single column; above it the container keeps its columns. | A grid layout container offers a small finite set of inclusive viewport thresholds at which its columns stack. | Container-relative thresholds, arbitrary pixel values, automatic responsive detection and changing the order of the children. |
  | `grid-item-span` | `span` | Number of grid columns that one item of a grid layout container occupies. | A grid item part places itself by a finite column span in the container's automatic flow. | Explicit start or end lines, reordering the items, column counts of the container (use `columnCount`) and native table cell attributes. |
  | `grid-item-row-span` | `rowSpan` | Number of implicit grid rows that one item of a grid layout container occupies. | A grid item part stretches over a finite number of rows next to items that span fewer. | Explicit row lines or templates, reordering the items, column spans (use `span`) and native table cell attributes. |

- **Controlled / uncontrolled:** Not applicable. No state, value or notification exists.

## 4. Behavior

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| `<Grid>` with children and no props | One equal-width column, token gap 4, items stretched, children in DOM order | None |
| `columnCount` 1, 2, 3, 4 or 12 | That many equal tracks that can shrink below their content | None |
| `gap` a `LayoutGap` key | That token gap on both axes | None |
| `alignItems` a `LayoutAlignItems` value | Each item aligned on the cross axis inside its area | None |
| `collapseBelow` 860 or 1080 and a viewport at or below it (inclusive: 860 and 1080 collapse; 861 and 1081 do not) | One column; every direct child's span and row span stop applying; gap and alignment unchanged | None |
| The same props at a wider viewport | `columnCount` columns and the item spans apply | None |
| `collapseBelow` omitted | The grid keeps its columns at every width, 320px included | None |
| `GridItem` with `span` and `rowSpan` | The item takes that many columns and rows in the automatic flow; dense packing is never enabled | None |
| `span` larger than `columnCount` | Not clamped and not warned: the browser adds implicit columns. The consumer keeps `span` at or below `columnCount` | None |
| A child that is not a GridItem | Placed in one cell by auto-flow; if it carries its own column or row placement, the collapse resets it to `auto` | None |
| Null, `false` or empty children | Nothing renders and no cell exists | None |
| An unsupported runtime value (untyped JavaScript, for example `columnCount={5}`, `gap={9}`, `alignItems='around'`, `collapseBelow={900}`, `span={13}`, `rowSpan={0}` or `null`) | Ignored: that axis contributes no utility of its own, nothing is interpolated into a class or forwarded to the DOM, and nothing throws or warns (the Stack and Cluster behavior; OQ-7). `undefined`, `NaN` and the empty string count as omitted, as CVA's own fallback does. A `columnCount` with no usable value leaves a single implicit auto column | None |
| `asChild` with exactly one element child | The part merges onto that child through Slot: no wrapper element; the child's own attributes, `className` and ref are kept | None |
| `asChild` with zero, several or non-element children | Radix Slot's own behavior, unchanged and not wrapped: the consumer's responsibility | None |
| A rerender with other prop values | The replaced utility is dropped and the new one applied (`cn()` resolves the conflict); children stay mounted in the same positions | None |
| `dir='rtl'` | Auto-flow follows the inline direction; spans are direction-neutral | None |

- **States / representation:** no own `data-state`, no mirrored class and no inline style. The collapse is pure CSS (a media query): no resize listener, no state, no hydration difference, so server and client markup are identical. Static utilities only.
- **Limits / consumer responsibilities:** the consumer keeps DOM order equal to the intended reading order, keeps `span` at or below `columnCount`, sets `collapseBelow` on multi-column grids that carry text (block 5), wraps long unbreakable content in a `GridItem` (which sets `min-w-0`) or gives it `min-w-0`, and picks the gap key that is closest to a reference value. There are no per-breakpoint column counts and no independent row and column gaps.

## 5. Accessibility

- **Accessible name / roles / relationships:** none. Grid and GridItem are passive layout: no role, no `tabindex`, no ARIA attribute, no id and no live region is added, so a plain grid is a generic container. A consumer who needs a list uses `asChild` with `ul` and `li` and names it; native `aria-label` and `aria-labelledby` pass through to the root.
- **Reading order is DOM order.** At every width and in every state the visual order equals the DOM order. The primitive adds no `order` utility, no explicit start or end line, no `row-start` or `col-start`, and never enables dense auto-flow (`grid-auto-flow: dense`), so no combination can reorder content visually (WCAG 1.3.2 Meaningful Sequence, 2.4.3 Focus Order). The reference moves some media first on narrow screens (`.hero-art{order:-1}`, `.com-grid` areas); that is outside this contract, and a consumer who needs another mobile order renders another DOM order.
- **Keyboard / focus:** Not applicable: Grid adds no tab stop, handler or focus management. Focusable children keep their own behavior, and tab order is DOM order.
- **Reflow and zoom:** a multi-column Grid without `collapseBelow` stays multi-column at every width and can break reflow at 320 CSS px (WCAG 1.4.10). The consumer sets `collapseBelow` on grids that carry text. Tracks use `minmax(0, 1fr)` so a track never forces horizontal scroll by itself; content that cannot shrink still can (block 4). Gap tokens are spacing tokens; no fixed pixel width is applied.
- **Announcements / other conditions:** Not applicable (no changes announced, no motion, no paint, no colour). Assistive-technology output for lists built with `asChild`, including whether a consumer needs `role="list"` once it removes markers, is not evaluated here. Component guarantees: no semantics added and no reordering. Consumer guarantees: names, list semantics and content order.

| `columnCount` | `1`, `2`, `3`, `4`, `12` | `1` | Independent of the other axes |

- **Tokens / Material:** nothing is painted: no Surface, no Material recipe, no colour, shadow, radius or font. Spacing comes from the existing spacing tokens through `gap-*` utilities (`theme.css:439-468`), checked key by key by a test. The two thresholds are literal viewport widths inside media queries, the Hero and BlogGrid precedent, not tokens: theme breakpoints generate min-width variants, `max-*` variants are exclusive (V-4) and a custom property cannot be read inside a media condition. **No token is proposed.** Utilities are static CVA literals in `types.ts`, composed per part with `cn()` in the hook. The planned classes (static literals, no interpolation):
  - Grid: base `eg-grid grid min-w-0`; `columnCount` → `grid-cols-1`, `grid-cols-2`, `grid-cols-3`, `grid-cols-4`, `grid-cols-12`; `gap` → `gap-0` … `gap-24`; `alignItems` → `items-start`, `items-center`, `items-end`, `items-stretch`, `items-baseline`; `collapseBelow` 860 → `[@media(width<=860px)]:grid-cols-1 [@media(width<=860px)]:[&>*]:col-auto [@media(width<=860px)]:[&>*]:row-auto`, and 1080 the same with `1080px`.
  - GridItem: base `eg-grid-item min-w-0`; `span` → `col-span-1` … `col-span-12`; `rowSpan` → `row-span-1` … `row-span-4`.
  - Axis maps are inline object literals inside `cva(…)`, so the artifact extractor lists them (V-9).
- **Dynamic geometry:** Not applicable. No custom property, inline style or interpolated class string.
- **Class composition / consumer layout:** `cn(gridVariants({…}), className)` and `cn(gridItemVariants({…}), className)`; `className` merges last and keeps the marker. It supports outer placement of the part itself (margins, self-alignment, placement in a parent grid or flex), as Stack documents. It is not the way to change columns, gap, alignment or spans, and a colliding utility there resolves by `twMerge` last-wins without being part of the contract. No part override API. The plan tests the supported precedence.
- **Cascade and the #392 risk:**
  - Within `@egdev/ui/styles.css` each Grid utility is one rule in `@layer utilities`. The collapse rules sit in `@media (width<=N px)` blocks emitted after every unconditional utility (V-4), and the child reset (`> *`, one class) has the same specificity as `.col-span-N` and `.row-span-N`, so order alone makes it win. The plan proves that order on the preview build and on the packed build.
  - #392 is the same mechanism across packages: both stylesheets ship utilities in the same layer and, at equal specificity, the one imported later wins (the documented order is ui then effects; egdev.es imports effects first as a workaround). Grid is exposed only if effects ever declares `grid-template-columns`, `grid-column` or `grid-row`. It declares none today (V-8), so there is no present conflict in either import order. This spec does not claim #392 is fixed, and Grid does not depend on its fix. The plan adds a packed guard that fails if effects starts declaring those properties, and runs the packed checks with effects present in both orders.
- **Files / pending proposals:** the six mandatory files in `packages/ui/src/primitives/grid/`: `types.ts` (props types for both parts, `gridVariants` and `gridItemVariants`), `useGrid.ts` (`useGrid` and `useGridItem`), `Grid.tsx` (`Grid` and `GridItem`, JSX only), `Grid.test.tsx`, `Grid.stories.tsx` and `index.ts`. **No stylesheet** (`grid.css` is not created) and no extra internal module. Two parts share one hook file, one JSX file and one `types.ts`, as BlogGrid does, and Stack and Cluster share `types.ts`. Derived changes the implementation PR would make, none authorized here: the `@source` line in `packages/ui/src/styles/compiled.css`, the preview and Storybook allowlist lines, the registry JSON and generated view, docgen, Controls and emitted-CSS tests, package fixtures, the system artifact, the catalog rows and the changelogs. Token and dependency confirmations: none pending.

## Findings and risks

- **F-1 (resolved):** the L3 draft's `columns` cannot be registered (V-7). The owner chose `columnCount` (OQ-1), so the registry step is unblocked and no exception is requested.

Gaps are token keys, so the reference's 20px and 24px have no exact value (`--space-5` is 16px, `--space-6` 19.2px, `--space-7` 22.4px).

- **F-6:** a Grid inside a non-stretching Stack is sized by its content (block 2).
- **F-7:** list semantics for `asChild` markup and assistive-technology output are not evaluated (block 5).

- **R-2:** pinned export, docgen and Controls inventories move with the new names; the first red run lists them.
