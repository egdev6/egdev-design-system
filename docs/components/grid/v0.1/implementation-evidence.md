## 4. Findings

- **F-1 — A stray global utility from prose.** The differential (section 5) found one rule the plan did not predict: `.collapse { visibility: collapse }` in the shipped stylesheet. Tailwind scans `types.ts` as text, and the doc comment of `gridVariants` used the bare word "collapse" ("The collapse uses the inclusive …"). Any consumer element with a `collapse` class would have been hit. Fixed by rewording the comment ("The one-column fold uses …", no code changed), pinned by a test in `package-exports.test.mjs` and `package-consumption.test.mjs`, and `types.ts` was re-hashed everywhere it is bound: eight registry usages, four receipt sources, the generated view (a comment-only change moved no artifact, `system.md` or README byte: `artifact --check`, `system:check` and `mcp:readme --check` stayed clean). After the fix the shipped CSS gains exactly the 20 Grid rules.
- **F-2 — Two serializations of the same inclusive query.** The Storybook preview optimizer lowers `(width<=860px)` to `(max-width: 860px)`, while the shipped `dist/styles.css` keeps `(width<=860px)`. Both are inclusive; the exclusive `width <` would lower to a value below the threshold. E1 and E2 pin the preview form, and the packed and shipped assertions accept either.
- **F-3 — Option order is the extractor's, not the declaration's, and the widgets do not show it uniformly.** The real parser lists each union in the order TypeScript gives it, consistent with TypeScript ordering union members by internal type id, that is by when each literal type was first created in the program: `gap` comes out as 0, 1, 2, 3, 4, 12, 5, 6, 7, 8, 10, 14, 16, 20, 24 and `span` as 1, 2, 3, 4, 12, 5, 6, 7, 8, 10, 9, 11 (the `12` sorts right after the `4`, which fits `columnCount` creating it first), and `alignItems` as center, start, end, stretch, baseline (the shared `LayoutAlignItems`, as Stack's own table). The registered enhancer leaves those values and that order untouched: the installed options equal the native pipeline's, asserted for both parts in `grid-docgen.test.ts`. In the browser the Docs type column keeps the extractor's order, while the `gap` select lists 0 to 24 ascending, because Storybook's `normalizeOptions` (`@storybook/addon-docs` 10.6.1, `blocks/controls/options/Options.tsx`) folds the options into an object keyed by `String(item)` and JavaScript orders integer-like keys ascending; string options such as `alignItems` keep the extractor's order, so `center` is first and the declared start, center, end, stretch, baseline never reaches the widget, as for Stack. So AC-09's "each select in union order" holds as: exactly the declared union members, in the order the extractor gives, unmodified by the enhancer. The test pins the members as sets and the enhancer's pass-through, not a literal order, because the extractor's order depends on the program. It is cosmetic and breaks no promise; the declaration order would need a change in the extraction or in the central enhancer, which is outside this plan. (My first-pass wording said the selects follow the type column; the `gap` select shows that they do not.)
- **F-4 — The first packed-consumer GREEN failed twice, once by my own mistake.** My CSS helper located the media block with `lastIndexOf('@media')`, which matched the `\@media` inside the previous escaped class name; replaced with brace-matched block ranges and shown able to fail (section 2, row 9 and the mutation note). The same run also failed two `tsc` steps by `ETIMEDOUT`: see F-5.
- **F-5 — The harness's fixed 30 s `tsc` limit is load-sensitive.** The typed-consumer and `types` steps of `package-consumption.test.mjs` have a 30,000 ms limit. During the RED run they completed in 29.0 and 24.7 s, and in the first GREEN run both hit the limit while the machine ran at a load average of 30 to 45 on 16 cores from unrelated jobs. The rerun passed 14/14 in 94 s and the final-tree run in 115 s. No timeout was changed. A harness that fails on a slow machine is an environment risk to keep in mind, not a Grid defect. In the second pass the load average was 63 when `pnpm test` started, and all 163 files still passed.
- **F-6 — The artifact derives `GridItem` as a part of `Grid`.** Both components live in `Grid.tsx`, so the generator lists `GridItem` under `Grid.parts` and also as its own entry; `GridItem.parts` is empty. The artifact test pins that.
- **F-7 — `beforeIndicatorConventions` moved from 190 to 194.** The plan expected it not to move; it is the registry size minus the three indicator entries (197 − 3), so it follows the count. The pin is 197 and 194.
- **F-8 — Literal G8 item: a generator demanded an edit outside plan section 2.** The artifact change made `pnpm test:mcp` fail until `packages/mcp/README.md` was regenerated (a one-line digest diff). The parent's task pre-authorized `pnpm mcp:readme` and listed the file in the allowed surfaces, so it was applied and is reported here. The Storybook MCP contract also required a documented story component for `GridItem`; it is declared as `subcomponents: { gridItem: GridItem }` on the Grid meta, so `scripts/storybook-mcp-exceptions.json` is untouched.
- **F-9 — Parent-owned integration surfaces were written by the writer.** Plan G6 names the registry, artifact, catalog, package harnesses, barrel lines and changelogs as parent-owned; the parent's allowed edit surfaces delegated them to this run, so they are included. The receipt test reads `odd/tasks/layout-grid-395.md` (the owner's verbatim answers), which is still untracked: commit it with or before the registry slice.
- **F-10 — Plan-level choices.** Inline literal maps with no runtime import from Stack: implemented. `GridItem asChild` over a `Stack` for About: implemented and measured. The nine story names: implemented. The #392 guard that fails if effects declares a collapse property: implemented and shown able to fail. The new `grid-docgen.test.ts` instead of extending the Stack-era parser list: implemented in the second pass (221 lines, 7 tests). E2's failing-order proof is a permanent in-memory reorder inside the test instead of a one-off scratch run, which is stronger and leaves nothing on disk.
- **F-11 — The parser drops an undocumented `children`.** With an own `children` declared on `GridOwnProps`, the real parser (the `main.ts` options) emits a `children` row only when the declaration carries a doc comment: `buildFilter.js` of `react-docgen-typescript` drops a `children` prop with an empty description unless `skipChildrenPropWithoutDoc` is `false`, and `main.ts` leaves the default. So `grid-docgen.test.ts` guards a silent redeclaration with its AST assertion (the declared props must be exactly the planned ones) and a documented one with the parser assertion (exactly the own and the allowlisted rows). Both were shown by mutation (section 2, row 11: the undocumented variant fails the AST test only, the documented one fails both).
