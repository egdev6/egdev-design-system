## 4. Findings

None of these needed a code or spec change. F1 and F2 describe edits made inside the delegated surfaces; the others are observations.

- **F1 — Two pinned registry counts moved.** The Indicator conventions test in `scripts/prop-naming.test.mjs` pins the registry size and its pre-Indicator subset (`192` and `189`); a new convention moves both (`193` and `190`), as `titleVariant` did. Plan sections 2 and 5.1 name three edit places in that file and not these two; the file is inside the delegated surfaces and no stop line applies.
- **F2 — The receipt landed with the code, before the artifact.** The owner's answer approved D5 together with the plan, so the entry was written as `approved` with its receipt in the same pass instead of `proposed` in slice 1 and flipped in slice 3 (plan section 10); the artifact was therefore generated once, with the convention already `approved`. Two points of authority are worth stating plainly: `odd/tasks/round-5-consumer-requests.md` L13 does not list the receipt (D5) or the catalog note (D4) among what the answer covers, and the receipt rests on the parent's relay that it does, which `approval.md` and the receipt's `interpretation` record. The commit grouping below keeps `props:check` and `test:props` green in every commit.
- **F3 — The plan's heading arithmetic omitted the card border.** Plan section 3 computes 19.2 + 25.04 + 9.6 = 53.84px for the heading's top; the measured offset from the card's border-box top is 54.812px, the 1px border and 1/64px snapping accounting for the difference. The claim it served, band and pill agree, holds exactly (0.000px).
- **F4 — Contrast is inside the arithmetic bracket.** Measured 6.90:1 (worst pixel), 6.96:1 to 7.00:1 (median) and 7.08:1 (best), against the spec's about 7.4:1 and about 6.6:1; at least 4.5:1.
- **F5 — An invalid runtime `size` leaves the band without an inset.** The spec promises a fallback only for `statusPresentation`. With an untyped `size` such as `'xs'`, the two compounds (`md` and `sm`) match nothing, so the band carries no `mx-*` class and sits flush with the card's edges, while the heading keeps its base `px-6`; a one-off render confirmed the class list.
