## 5. Findings

1. **F1 — spec section 4, over-wide label (resolved by amendment).** The sentence "a label wider than the card's content box overflows rather than being clipped" did not hold under the shipped CSS. Observed in `StatusInNarrowCard` (content box 189.99 px, card padding 19.2 px, card padding-box edge 245.39 px) by replacing the Badge label in the DOM:

   | Label | Badge width | Overflow past the content box | Clipped at the card edge | Visible | Card `scrollWidth` over `clientWidth` |
   | --- | --- | --- | --- | --- | --- |
   | `testing` | 68.98 px | 0 | 0 | 100% | no |
   | `testing in staging before launch` | 187.98 px | 0 | 0 | 100% | no |
   | `testing in staging before the launch review` | 241.98 px | 51.98 px | 32.78 px | 86.5% | yes |
   | `in extended testing across several environments before the launch review` | 395.98 px | 205.98 px | 186.78 px | 52.8% | yes |

   The wrapper stays at the content width (190.02 px), the nowrap Badge overflows it and the row, and `.eg-project-card { overflow: hidden }` (legacy, `@layer components`) clips whatever passes the padding edge: only the padding step (19.2 px here) beyond the content box stays visible. In the upper-zone branch the label grows the content-hugging upper zone (F2) and the card clips it the same way (33.78 px clipped, 86% visible). The card adds no clipping utility, so PC-S9 as written held and the implementation matched the plan. The first pass stopped here, as instructed, and the parent put the choice to the owner. **Resolution:** the owner chose A, "A: corregir la frase de la ficha (Recomendado)" (ODD L8). The §4 sentence was amended and nothing else in the spec changed ([`approval.md`](approval.md) Amendment 1; spec hash `0d346d35…` to `21ae2a49…`); the implementation was kept as built.

   **Not amended by that answer, reported for the owner:** the §4 behavior-table row for a narrow host says "The card never truncates, clamps, clips or scales the Badge", and PC-S9 says "the card adds no truncation, clamp or clipping utility". PC-S9 is true as written (no utility of the new recipes clips). The table row is literally in tension with the legacy `overflow: hidden` for a label wider than the padding edge: the legacy frame rule, not a recipe of this change, does the clipping. Left as approved.
2. **F2 — the upper zone hugs its content under the legacy cascade (pre-existing, not introduced here).** The existing `BackdropAndMark` story, which has no status, already shows an upper zone 108 px wide in a 1207.6 px content box, because the card's `align-items: flex-start` applies to the zone (`align-self: auto`).
