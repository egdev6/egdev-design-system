## 1. Purpose and scope

- **Need / non-goals:** Each detail page of the web's four collections (editorial, events, projects, notes) opens with its title block and its metadata: the kind, the publication or event date, the source or location, tags, and external links such as the canonical URL, GitHub, a demo or the online event URL. SectionHeader covers title, eyebrow and lede only (`packages/ui/src/molecules/section-header/types.ts`, `SectionHeaderProps`), and nothing else in `@egdev/ui` places the metadata. The website pages are not built (issue #572, "Current mitigation: None yet"). DetailHeader is one reusable unit that composes the existing SectionHeader with a label/value list, a tag list and an external-link list. Content arrives through props; the only built-in text is two localizable list names and the new-tab notice. Intended mapping: kind → `eyebrow`; date, source, location and any other fact → `metadata` (dates with `dateTime`); tags → `tags`; canonical, GitHub, demo and event URLs → `links`.

  **Non-goals:** breadcrumb (#570), page body (#569), pagination (#571), cover or hero media, buttons or other actions (PageHeader's responsibility), author avatars, routing, analytics, date formatting, reading-time computation, data fetching and filtering; linkable tags (additive later, OQ-3); rich or interactive metadata values (plain text only; destinations belong in `links`, OQ-7); same-tab or in-product links (the collection is external by definition, OQ-6); SectionHeader's `variant`, `accent`, `accentBreak`, `tone` and `titleId` (not exposed in v0.1; adding them later is additive). SectionHeader, Chip, Link and ArticleFeature are not modified, and the frozen `docs/components/article-feature/v0.1/` folder stays untouched.
- **Cataloging decision / alternatives:** Approved (L3): new component "#572 DetailHeader"; the cataloging draft reads "compose a generic molecule; probably new". Kind: new. Rejected, in order: *reuse*, because SectionHeader has no metadata, tag or link row, PageHeader is a compact product heading with plain-string title, eyebrow and lede plus Button/IconButton actions and no metadata (`molecules/page-header/types.ts`), and ArticleFeature is a whole-card link; *variant* of SectionHeader, because facts, tags and links change its responsibility (a passive editorial introduction with no children); *compose in the app*, because four collections in two languages would repeat the same list, validation and localization logic, and the web consumer amendment (`docs/CATALOGACION.md`, §1) admits a reusable web piece without domain data into `@egdev/ui`; *extract*, because ArticleFeature's context row is internal, inline, inside one whole-card anchor and not a label/value list, and its v0.1 folder must not change. Nothing existing covers the need, so new is justified.
- **Evidence / level and package:** Molecule in `@egdev/ui`, proposed `packages/ui/src/molecules/detail-header/`; Radix base: none. Responsibility: coordinated concepts (heading block, facts, tags, links) working as one reusable unit, with no section, navigation or domain responsibility, which the decision signals classify as a molecule (`docs/CATALOGACION.md:43`). Inspection establishes exports and current markup, not visual conformity.

## 2. Anatomy and composition

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| Root | Groups the parts in reading order; no role, name or paint. | `div` | The four parts below only. |
| Heading block | Eyebrow, page title, lede. | The existing `SectionHeader` (renders `header`, a native `h1`–`h6` through Heading, a Text eyebrow and a Text lede). | `title`, `eyebrow`, `lede`. |
| Metadata list | Label/value facts. | `dl` > `div` > `dt` + `dd`; `time` inside `dd` when `dateTime` is given. | One entry per valid item; plain text. |
| Tags list | Short classification labels. | `ul` (explicit `role="list"`, named) > `li` > the existing `Chip mode="static"`. | Plain strings. |
| Links list | External destinations. | `ul` (explicit `role="list"`, named) > `li` > the existing `Link` with `external`. | A visible label and an absolute `https:` URL. |

- **Radix / composition:** no Radix primitive of its own and no `asChild`. It composes SectionHeader, Chip and Link through their public modules; Radix appears only transitively through Link (Slot, VisuallyHidden). No new dependency. Layout is static utilities declared as CVA in `types.ts`, as SectionHeader does; `Stack` and `Cluster` are not used, because their `asChild` gap-key API adds nothing here. A part with no valid content is omitted, never rendered empty (no empty `dl` or `ul`).
- **Public markers:** `eg-detail-header` is the stable public root. `eg-detail-header__meta`, `eg-detail-header__tags` and `eg-detail-header__links` are retained internal markers on the three lists, for debugging and themes, with no part-selector API and no consumer `className`. SectionHeader keeps its own `eg-section-head`. No `eg-detail-*` rule exists in `packages/ui/src/styles` and none may be added.
- **Reading order:** DOM order equals visual order: eyebrow, title, lede, facts, tags, links.

## 3. Public API

```ts
type DetailHeaderMetadataItem = { label: string; value: string; dateTime?: string };
type DetailHeaderLink = { label: string; href: string };
type DetailHeaderMessages = { tags: string; links: string };
```

| Prop / event | Type | Required | Default or rule | Description |
| --- | --- | --- | --- | --- |
| `title` | `SectionHeaderText` (string or ordered language-tagged runs, per the [SectionHeader multilingual amendment](../../section-header/v0.2/multilingual-amendment.md)) | yes | none | Page title, rendered by SectionHeader. No readable text renders nothing (block 4). |
| `eyebrow` | `SectionHeaderText` | no | omitted | One short context line before the title, typically the kind (post, article, news). |
| `lede` | `SectionHeaderText` | no | omitted | Introductory paragraph after the title. |
| `level` | `SectionHeaderLevel` (1–6) | no | `1` | Native heading rank only, never a typography selector. A runtime value outside 1–6 resolves to 1. |
| `metadata` | `DetailHeaderMetadataItem[]` | no | omitted | Ordered facts. `label` is the visible term, `value` the visible plain text, optional `dateTime` a valid HTML date or time string that wraps the value in `time`. |
| `tags` | `string[]` | no | omitted | Ordered short labels, rendered as non-interactive pills. |
| `links` | `DetailHeaderLink[]` | no | omitted | Ordered external destinations. Each opens in a new tab; `label` is the visible, descriptive link text. |
| `newTabText` | `string` | no | `(opens in a new tab)` | Localized notice appended to every link's accessible name. |
| `messages` | `Partial<DetailHeaderMessages>` | no | `tags`: `Tags`; `links`: `Links` | Localized accessible names of the two lists. |

  - **Lookup** (terms: metadata, meta, details, facts, attributes, tags, labels, keywords, links, urls, destinations, external, sources, name, label, messages, id). Closest entries, rejected: `collection-items` (`items`, `:3953`), whose meaning fits but which names one primary collection and cannot tell three apart; `option-metadata` (`meta`, `:6536`), selectable-option detail that excludes badges and long content; `content-detail` (`detail`, `:8304`), one fact beside a context label, not a collection; `accessible-name` (`label`, `:1626`), which cannot carry two list names without scoped exceptions such as SectionNav's `disclosureLabel`, whereas `messages` needs none; `heading-id` (`titleId`, `:6509`), not exposed in v0.1.
  - **New proposals** (status `proposed`, none registered yet; the owner approved all three as a convention decision with OQ-5, recorded separately from this spec, and each registry entry stays `proposed` with `approval: null` until a receipt binds its exact content at implementation):

    | --- | --- | --- | --- | --- |
    | `content-metadata` / `metadata` | Ordered label/value facts about a content unit, rendered as a description list. | A header or card presents factual attributes such as date, place or source. | Option detail (`meta`), one context fact (`detail`), selectable options, rich or interactive values. | `DetailHeaderMetadataItem[]` |

Usage `source: {path, symbol, revision}` can only be recorded after `types.ts` exists: a plan item, never invented here.

## 4. Behavior

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| `title` has readable text | The root renders SectionHeader (eyebrow if any, heading at `level`, lede if any), then the parts that have valid content. | None |
| `title` is blank or has only decorative runs | Nothing renders: no root, facts, tags or links. Development warning, exact text: `DetailHeader requires a non-blank title; nothing was rendered.` | None |
| `eyebrow` or `lede` is blank | Omitted, as SectionHeader omits it. | None |
| `metadata` has valid entries | One `div` per entry, in array order, with `dt` = `label` and `dd` = `value`; a non-blank `dateTime` wraps the value in `time` with that `datetime`. The component neither formats nor validates `dateTime`. | None |
| A metadata entry has a blank `label` or `value` | Skipped; warning `DetailHeader: skipping an invalid metadata entry.` The others render. | None |
| `tags` has valid entries | One `li` per tag containing a static Chip, in array order; duplicates both render. | None |
| A tag is blank | Skipped; warning `DetailHeader: skipping a blank tag.` | None |
| `links` has valid entries | One `li` per entry containing the existing Link with `external`: new tab, `noopener noreferrer`, the hidden notice and the default decorative arrow. | None; navigation is native |
| A link has a blank `label`, or an `href` that is not an absolute `https:` URL with a host, without credentials or raw control characters | Skipped; warning `DetailHeader: skipping an invalid link entry.` No relative, `http:` or script URL reaches the DOM; surrounding whitespace in a valid `href` is trimmed, as SocialLinks does. | None |
| `metadata`, `tags` or `links` is absent, empty or has no valid entry | That list is not rendered. | None |
| `messages.tags`, `messages.links` or `newTabText` is blank | The default is used; warning `DetailHeader: <prop> must not be blank; using its default.` | None |
| `level` is outside 1–6 at runtime | Resolves to 1; no invalid heading element. | None |
| Props change between renders | Output follows the current props; nothing is stored. | None |

- **States / representation:** no own states, `data-state` or state classes; the component is passive. Warnings are development-only (silent when `NODE_ENV` is `production`) and use the SocialLinks pattern.
- **Limits / consumer responsibilities:** the host formats dates and text in the page language; built-in defaults are English, so a localized page passes `messages` and `newTabText`. The host bounds how many entries it supplies. Long values wrap and are never truncated or clipped. The `dt` uppercase is presentation only (CSS), so the DOM text equals the supplied label. The component does not check that a URL is reachable or that `dateTime` is valid, and it does not deduplicate. Exactly one `h1` per page is the host's responsibility.

## 5. Accessibility

- **Accessible name / roles / relationships:**
  - **Root:** a plain `div` with no role and no name; the heading names the content and the host's `main` or `article` owns the region name. `role`, `aria-label` and `aria-labelledby` are not forwarded.
  - **Heading:** a native `h{level}` through SectionHeader; its name is the title text, including multilingual runs with their `lang` spans.
  - **Placement:** render it inside `main` or `article` (for example WebTemplate's `main`). Per HTML-AAM a `header` is a `banner` only when not scoped to sectioning content or `main`, so outside that scope SectionHeader's inner `header` could be announced as a second banner. Not evaluated in a real browser.
  - **Facts:** a native `dl`; each `dt` names its `dd`. The `time` element adds a machine-readable date; assistive technology speaks the visible text.
  - **Lists:** each `ul` carries an explicit `role="list"` (the usual remedy for WebKit dropping list semantics under `list-style: none`; precedent `molecules/social-links/useSocialLinks.ts:132`, supplied through the hook's props object) and an `aria-label` from `messages`, defaults `Tags` and `Links`. Chips are plain text.
  - **Links:** native anchors through Link. The accessible name is the visible label, one space and the hidden notice, for example `Repository (opens in a new tab)` (pattern pinned in `atoms/link/Link.test.tsx:77`); the arrow is decorative. The notice is localizable through `newTabText`.
  - No ids, `useId` or `aria-describedby` are needed.
- **Keyboard / focus:** native only. Tab visits each Link once, in DOM order, and nothing else is focusable (heading, facts and chips are not). Enter activates a link. There are no shortcuts, roving focus, focus movement or restoration. The focus ring is Link's own recipe.
- **Announcements / other conditions:** no live region and no announcement; the header is passive. Non-colour cues: links are underlined at rest ([Link v0.4](../../link/v0.4/underline-hover-amendment.md)) and carry a text notice; terms, values and tags are text. Contrast, computed from the hex values in `packages/tokens/src/theme.css` and not measured in a renderer: `text-fg-default` is 18.26:1 and `text-fg-muted` 7.17:1 on `surface-0` (13.55:1 and 5.32:1 on `surface-3`). Link text is neon `--color-link-default` = `--color-fg-brand-raised` = `#FF0036`, which the tokens document as 4.61:1 only on `surface-0` and below 4.5:1 on `surface-1` to `surface-3` (`theme.css:78,110,185`). The web's reading sections use SectionShell `--grafito`: `surface-0` at 50% over the particle layer, dimmed to 0.6 in the `read` profile (`docs/DECISIONES.md:92-93`; `docs/MATERIAL.md:77`). If detail pages follow that register, which is not decided for pages that are not built, the host is translucent, so real contrast depends on the backdrop and is host-owned. DetailHeader paints no surface and never places text on a raised one. Not evaluated: real screen-reader output for the `dl` with `div` wrappers and the explicit list roles, contrast on the actual host, and link target size and spacing (WCAG 2.5.8), which Link's own contract governs.
