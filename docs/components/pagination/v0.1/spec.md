## 1. Purpose and scope

- **Need / non-goals:** Listings with many entries (editorial, events, projects, notes) split into pages with **crawlable** links: previous and next, page numbers inside a bounded window with ellipses, and the current page marked. Filters keep working across pages because the consumer encodes route and filter state into each page URL. First consumer: egdev-website (egdev.es) reading sections, which sit on the grafito register (`docs/DECISIONES.md`, "Pulso en Grafito"); consumer issue egdev6/egdev-website#49, request #571. Current mitigation: none (the pages are not built).

  Non-goals: slicing data, page size, fetching or filtering (consumer); routing beyond the `onNavigate` notification; "load more" or infinite scroll; a page-size selector or a "go to page" input; "Showing 11–20 of 134" text; first/last jump controls beyond the numbers 1 and `pageCount`; `siblingCount` or `boundaryCount` props (OQ-1); a `variant`, `size` or `tone` axis; SEO tags in the document head; client state, animation or live announcements; the Show register (reading sections only); RTL appearance (not evaluated, block 5).
- **Cataloging decision / alternatives:** **new** molecule, owner-approved (L3). The reuse → variant → compose → extract order was walked again on inspected public code; each earlier step fails:

## 2. Anatomy and composition

| Part | Responsibility | Native element / Radix primitive | Allowed content |
| --- | --- | --- | --- |
| Root `eg-pagination` | Navigation landmark named by `label` | `nav`; no Radix | exactly one list |
| List | Ordered controls | `ul` with `role="list"` (precedent: `packages/ui/src/molecules/social-links/useSocialLinks.ts:132`, which keeps list semantics under the list-style reset; the plan checks the role against the lint rules) | `li` items only |
| Previous | Link to page `value − 1` | `li` > `a[href][rel="prev"]` | decorative `Icon` `arrow-left`, then the text `messages.previous` |
| Page | Link to one page of the window | `li` > `a[href]` | the page number as plain digits (`String(page)`), nothing else |
| Current page | The page `value`: the same Page link with `aria-current="page"` | `a[href][aria-current="page"]` | as Page |
| Ellipsis | Marks pages that are not shown | `li[aria-hidden="true"]` > `span` | the single glyph `…` (U+2026) |
| Unavailable Previous/Next | Keeps the row stable at a boundary | `li[aria-hidden="true"]` > `span[data-disabled]` | the same icon and text as the link it stands for, no `href` |
| Next | Link to page `value + 1` | `li` > `a[href][rel="next"]` | the text `messages.next`, then decorative `Icon` `arrow-right` |

- **Radix / composition:** none. Reused: the `Icon` atom (`packages/ui/src/atoms/icon`), decorative because it gets no `label`. No Surface, Link, Button or Chip import, no `asChild`, no ref, no router coupling. Consumers navigate through plain anchors; a router integrates through `onNavigate`.
- **Public markers:** `eg-pagination` is the stable public root marker. Parts carry no `eg-pagination__*` markers and expose no part-selector API. Native `aria-current` is the current-page state, styled through `aria-[current=page]:` variants; `data-disabled` marks the unavailable placeholders and is styled through a data variant; states are never mirrored into classes. Nothing legacy exists to preserve.

## 4. Behavior

The window is **constant-width**: every `pageCount` above 7 renders exactly 7 page-or-ellipsis slots, so the row does not jump while the user pages through. With `n = pageCount` and `p = value` after normalization:

- `n ≤ 7`: pages `1..n`, no ellipsis.
- `n > 7` and `p ≤ 4`: `1 2 3 4 5 … n`.
- `n > 7` and `p ≥ n − 3`: `1 … (n−4) (n−3) (n−2) (n−1) n`.
- otherwise (`5 ≤ p ≤ n − 4`): `1 … (p−1) p (p+1) … n`.

An ellipsis therefore always stands for at least two hidden pages.

| Initial state / action | Expected result | Emitted event |
| --- | --- | --- |
| `label="Editorial pages"`, `value=6`, `pageCount=12` | One `nav` named "Editorial pages" with `ul` items in DOM order: Previous (→ 5), `1`, ellipsis, `5`, `6` (current), `7`, ellipsis, `12`, Next (→ 7) | none |
| `value` 1 to 4 with `pageCount=12` | `1 2 3 4 5 … 12` with `value` current; at 1, Previous is an unavailable placeholder | none |
| `value` 9 to 12 with `pageCount=12` | `1 … 8 9 10 11 12` with `value` current; at 12, Next is an unavailable placeholder | none |
| `pageCount` 2 to 7 | All pages, no ellipsis; Previous and Next as above | none |
| `pageCount` 0, 1, 1.9 or negative | Nothing is rendered and nothing is warned: there is nothing to paginate | none |
| `value` fractional (3.9) or out of range (0, 99) | Floored and clamped to `1..pageCount` (3; 1; `pageCount`); never throws | none |
| `value` or `pageCount` NaN, ±Infinity or not a number (untyped) | Development warning `Pagination requires a finite numeric value. Nothing was rendered.` or `Pagination requires a finite numeric pageCount. Nothing was rendered.`; no output; a later valid rerender renders | none |
| `label` empty, whitespace-only or not a string | Development warning `Pagination requires a non-empty label. Nothing was rendered.`; no output | none |
| `getHref` not a function, or blank or not a string for a rendered control | Development warning `Pagination requires a getHref function. Nothing was rendered.` or `Pagination requires getHref to return a non-empty string for every rendered page. Nothing was rendered.`; no output | none |
| User activates a page, Previous or Next link by click or Enter | The native navigation proceeds unless the consumer called `event.preventDefault()` | `onNavigate(page, event)` once, before the default action |
| Ctrl, Meta or Shift click, or middle click | The component does not intercept them: modified clicks still reach `onNavigate` (the consumer ignores them) and a middle click raises `auxclick`, not `click`, so it is not reported | `onNavigate` on modified `click` only |
| Tab and Enter | Tab visits Previous, the page links and Next in DOM order; Enter activates the focused link. Placeholders and ellipses are never tab stops | as above |
| Rerender with new props | Names, links and the current marker update immediately; no focus move, no announcement, no transition | none |
| `messages` partial, blank or throwing | Each entry falls back independently to English; a `page` formatter that throws or returns blank falls back to `Page ${page}` for that link | none |

- **States / representation:** The current page uses native `aria-current="page"`; the unavailable placeholders use `data-disabled`. No own `data-state`. Each invalid input emits its own warning behind the development-only guard used elsewhere (`typeof process === 'undefined' || process.env.NODE_ENV !== 'production'`, for example `packages/ui/src/atoms/step-meter/useStepMeter.ts:59`). The warning strings carry the component name, final per the name approved in L3. The rendering has no effect, `useId` or browser API, so server and client markup match.
- **Limits / consumer responsibilities:** The consumer slices data, computes `pageCount`, keeps `value` equal to the route, validates an out-of-range page parameter (a 404 or redirect; the component only clamps defensively) and builds `getHref`, including active filters. `getHref` must be pure: it may run more than once per render. After a client-side navigation the consumer owns focus and any announcement. Several instances on one page need distinct `label` values. An empty listing needs an empty state (#573), not Pagination. `<link rel="prev/next">` in the document head, canonical URLs and indexing policy are the consumer's. Not a filter, a tab set or a stepper.

## 5. Accessibility

- **Accessible name / roles / relationships:** `nav` landmark named by `label`; `ul[role="list"]` of `li`; every control is a native `a[href]`. Numbered links are named `messages.page(n)` (default `Page 3`), which contains the visible digits (WCAG 2.5.3 Label in Name); the current page is the same link with `aria-current="page"`, and assistive technology announces "current page" in its own language, so no extra text is added. Previous and Next are named by their visible text (`messages.previous`, `messages.next`); their arrows are decorative. Ellipses and unavailable placeholders are `aria-hidden` on the `li`, so they leave the accessibility tree and the list count; the gap is evident from the page names. Required consumer input: `label`.
- **Keyboard / focus:** Native only, no Radix and no custom key handling: Tab order equals DOM order equals visual order in left-to-right text (Previous, pages, Next); Enter activates a focused link; there is no roving tabindex. The focus ring is `--shadow-focus` on `:focus-visible`, and it wins over the current page's edge shadow. Nothing in the component moves focus after a rerender or navigation.
- **Announcements / other conditions:**
  - Announcements: none (no live region). A page change is a route change; the consumer announces it if needed. Touch target: visible controls are at least 32px and at least 44.8px on coarse pointers (block 6).
  - **Color independence:** the current page differs from the others by its brand-tinted fill and its neon border (a shape cue), and programmatically by `aria-current`; the number colour is not the only cue. Estimated from the documented token values with the sRGB formula (hand-computed, not browser-measured): the neon border against `surface-0` 4.61:1 and against `surface-1` 4.30:1 (token comments, `packages/tokens/src/theme.css:78`), and about 3.5:1 against the current fill, so the indicator keeps 3:1 against both neighbours; white text on the current fill about 14:1; rest text `fg-secondary` 13.1:1 on the canvas. Contrast is specified on `surface-0` and `surface-1` first. Over the translucent grafito host (`surface-0` at 50% above the particle layer, host-owned) it is Not evaluated.
  - **Forced colors (proposed):** shadows and backgrounds are dropped, so the focus ring and the current page use a system-colour outline with system keywords only and no new token, following Carousel's current-slide recipe (`packages/ui/src/molecules/carousel/types.ts:185`). Every link keeps a transparent border; forced-colors modes replace border colours, so that border is painted (general knowledge, to be confirmed by PG-14), and the current page is told apart by the added outline, never by hue. Chromium emulation is the planned evidence; Firefox and real Windows High Contrast are Not evaluated unless separately checked.
  - **Disabled and reduced motion:** the unavailable placeholders use the contract's dimming (opacity .45) and are hidden from assistive technology; inactive components are exempt from text-contrast requirements. Transitions cover colour and background only and are removed under `prefers-reduced-motion`; no transform or press scale exists.
  - **Not evaluated:** screen-reader output (including VoiceOver's list announcement under the list-style reset and how `aria-current` on a link is spoken), RTL appearance (the arrows are physical glyphs and rotate with `rtl:rotate-180`, unverified), zoom and reflow in real browsers, contrast over translucent hosts, protan and deutan simulations.

Typography: `font-display text-meta` with `tabular-nums` on the digits (the shipped Carousel counter recipe, `carouselCounterVariants` at `packages/ui/src/molecules/carousel/types.ts:145`) and `uppercase` on the Previous/Next text (`--text-meta` is 11.2px/1.3 under the ×0.8 scale of #218; the CSS casing leaves the DOM text unchanged).   - **Material recipe R1 (approved, OQ-6):** the current page reuses the selected treatment that Tabs `outline` already ships (`packages/ui/src/molecules/tabs/types.ts:229-233`) through `aria-[current=page]:` variants: `border-state-selected`, `[background:var(--gradient-chip-active),var(--color-surface-1)]` and `shadow-[var(--shadow-edge-strong)]`, with `text-fg-default`. Rationale: it is the system's selected-pill family (Tabs `outline`, Chip `data-state=on`), it keeps the 3:1 indicator of block 5, and it adds no surface, well, overlay or glow. Rejected: a bare tonal fill, which is how NavList marks its current link through `surfaceVariants` at `surface-2`; even `surface-3` is only about 1.35:1 against the canvas (hand-computed), too faint to carry the state alone. Focus: `focus-visible:outline-none focus-visible:shadow-focus`, and `aria-[current=page]:focus-visible:shadow-focus` so the ring beats R1's shadow (`--shadow-focus` wins over Material shadows, `docs/MATERIAL.md`).
  - **Geometry (approved, OQ-6; arithmetic from tokens, not a browser measurement):** links `box-border inline-flex min-h-10 min-w-10 items-center justify-center gap-2 rounded-md px-2` (32px minimum under the ×0.8 spacing scale, `--space-10`) with `pointer-coarse:min-h-14 pointer-coarse:min-w-14` (44.8px, `--space-14`; precedent: Slider, SearchTrigger and Chip). The list is `m-0 p-0 list-none flex flex-wrap items-center justify-center gap-1`, so a narrow host wraps instead of overflowing and the row is centred under its listing (OQ-6). The arrows are `Icon` at `size="sm"` (12.8px). No hover or press transform.
  - **Motion and forced colors:** `transition-colors duration-(--duration-fast) ease-(--ease-out) motion-reduce:transition-none`; forced-colors outline utilities with the system keyword `Highlight` for focus and the current page (block 5). Arbitrary utilities in total: the chip-active background composition and the edge-shadow reference (both identical to Tabs `outline`) and the two system-colour ones; no hardcoded colour, shadow, gradient, spacing or font.
- **Dynamic geometry:** Not applicable. No custom property, inline style or interpolated class string; the number of links changes DOM nodes, not CSS. The Gauge, PreviewFrame and ColorSwatchGroup exceptions are neither used nor extended.
- **Class composition / consumer layout:** Root only: `className` merges last through `cn()` for outer placement (margin, self-alignment, flex and grid item placement: the base list), with no width, size, paint or state override. The list, items and links expose no `className`. No `@classNameAllows` tag is proposed. `twMerge` resolves recognized utility conflicts only; there is no last-class-wins promise.
